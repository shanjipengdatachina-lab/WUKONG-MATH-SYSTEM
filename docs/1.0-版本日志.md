## 0. 一句话

把**小学到高中（外加竞赛）的数学知识**做成一张**可缩放、可下钻的图谱**，外面套一个**IDE 化的外壳**：左边是栏目，中间是内容，需要演算时随时拉起**白板**，卡住时随手进**论坛**。

## 2. 功能清单（能做什么）

### 2.1 外壳（IDE 式）

- **固定左栏**：默认 56px，鼠标悬停展开为 212px 的覆盖层，不挤压正文。
- **栏目分组**：主功能区 8 项 —— 首页 / 章节 / 图谱 / **时间轴** / 白板 / 真题 / 方法 / 论坛；底部功能区 4 项 —— 全屏 / 搜索 / 账号 / 设置。时间轴挨着图谱放：两个都是"把知识铺开看"的全景视图，从图谱切过来不用越过其它栏目。
- **折叠记忆**：左右栏开合状态写入 `wkmath.shell.left`、`wkmath.shell.right`，刷新后保持。
- **收起之后一定回得来**：两栏收起时**都留 56px 的窄条**，条里留着各自的「展开」按钮（左栏目录头那颗、右栏「本页」行那颗）。这一条是硬要求 —— 右栏原来收起时整条宽度收成 0，而那颗按钮自己就长在条里，收起来就再也点不回来（用户问过"为什么右边栏没有了"）。
- **鼠标点完即收**：用鼠标点左栏条目后主动失焦，侧栏恢复原来的折叠状态（键盘 Tab 导航不受影响）。
- **快捷键**：`⌘/Ctrl + B` 左栏开合；`⌘/Ctrl + ⌥/Alt + B` 右栏开合；`⌘/Ctrl + K` 搜索。**键都在，但界面上不再写出来** —— 搜索那行的 ⌘K 角标、全屏 title 里的 Esc、工具条气泡里的按键，一律去掉（用户："去掉界面上的快捷键提示"）。
- **账号区**：未登录显示"登录"，登录后显示头像 + 姓名 + 年级，并跳向个人中心。

### 2.2 全站统一件

- **全屏**：42 个带侧栏的页面**全部**在搜索按钮**上方**放了同一个全屏按钮（左栏左下角）。
- **全屏不漏**：进入全屏后点击其它栏目**不会**退出全屏 —— 站内跳转改为加载进"全屏覆盖区"（iframe 覆盖层），顶层文档不卸载，`pushState` 更新地址，返回键回到上一层。
- **当前页入口不重载**：点自己所在的栏目不再整页刷新（刷新会掉全屏）。
- **品牌统一**：站名"悟空数学"、标识"悟"，41 个侧栏页 + 39 个页脚页一致。

### 2.3 章节阅读器（`reader.html`）

- 三栏：左栏册/章/节树、中栏正文、右栏页面大纲。
- **右栏是"按宽度分档"的，但 ≥1024 一律有右栏**：≥1280px 右栏 320px；1024~1279px 右栏窄一档 **264px**（正文仍留 472px，减去内边距约 392px 成句）；<1024px 三块摞起来（右栏内容落到正文下面），这时候两颗收起按钮都藏掉 —— 窄屏下所以看不到「隐藏右栏」那颗按钮，是**故意**的。**不能说"窄屏就看不到右栏"**：1024~1279 曾经是两栏（右栏内容挪到正文下面），于是那一档的窗口根本没有右栏，而正文里还写着"点击右栏「本页目录」"。现在只在 <1024 才摞。
- **点章节后左栏章节树默认展开**，普通页则默认收起（`data-left-default="open"`）。
- **学段与正文必须一致**：左栏收起只剩 56px 时，学段那一排**只留真选中的那一个**（四个 chip 挤不下，会被裁成"看着选了小学"）；切学段时若索引里缺章，跳到下一个有内容的章，整段都缺就明写「还没上内容」，**不留上一篇旧文**。
- **不显示外部网址**：目录与图谱数据里的 `source` 字段保留（生成器必填、校验在跑），但正文与图谱面板都不再渲染来源链接 —— 内容后续由后台上传。
- 中栏换页不刷新整页，右栏大纲随页联动。

### 2.4 知识图谱（`graph.html`）

- **满屏骨架**：去掉页头，画布独占整屏（除侧栏外全是图谱），和"白板"一致。
- **底部工具条**：与白板图标、样式、尺寸**同源**（由白板样式生成 51 条共享规则，其中 14 条逐字节比对一致）。
- **册筛选**：总览 / 七上 / 七下 / 八上 / 八下 / 九上 / 九下，选择后记住（`wkmath.graph.scope`）。
- **层级**：到章 / 到节 / 全部 三档。
- **搜索定位**：悬浮面板里搜知识点，命中即定位到节点。
- **外部点名**：`graph.html?q=知识点名` 直接落到那个条目 —— 白板的「回到知识点」、以及任何带 `?q=` 的链接都走这条通道；命中会自动放开册筛选、展开路径并浮出信息面板，没命中就把词留在搜索框里说明一声。
- **缩放**：放大 / 缩小 / 适应窗口 / 一键复位（读数显示当前百分比）。
- **说明**：工具条内收纳全部介绍、图例、筛选口径与范围提示，不占用画布空间。
- **悬浮节点面板**：点知识点后，信息以**可拖拽浮层**贴在图上（与白板题库面板同一套交互），拖动手柄可任意摆放，自动限制在可视区内。
- **年级默认**：已登录 → 默认聚焦本人年级；未登录 → 默认"总览 + 全部册章"。
- **键盘**：`⇧1` 适应窗口、`⇧2 / ⇧3 / ⇧4` 切层级、`0` 复位缩放、`Esc` 关闭浮层/浮窗。

### 2.5 白板（`whiteboard.html`）

- Canvas 2D 手写：Pointer Events + 压感 + `getCoalescedEvents()` + 二次曲线平滑，`devicePixelRatio` 适配。
- **无限画布**：锚点缩放（0.15×–8×）、适应内容、平移。
- **PS 式工具组**：同功能合并为一组，点击弹出浮层选具体工具 —— 画笔组（画笔 / 荧光笔 / 橡皮）、图形组（直线 / 箭头 / 矩形 / 椭圆）。
- **专业激活态**：选中工具用实底浅色块 + 主色描边，不用圆环。
- **自绘提示**：按钮提示统一走 `[data-wb-tip]` 的 CSS 气泡，不出现系统 `title` 气泡。
- **题面底纹**：从题库选题、或从其它页面带题进来，题面/来源/补充信息**直接印在板上**（浅色衬底、无边框，宽度按内容自适应 —— 短题不顶满一条）。平时不画底，鼠标压上来才浮现，板面整个留给演算。
- **题面可挪**：抓题面**左侧那条无字把手**（悬停显出两道短横、光标变可抓）拖动；题面**正文上照常落笔**，方便在题目上圈已知条件。拖动不落笔、不带动板面、不进撤销栈。
- **回到知识点**：工具条上「回到知识点」按钮（在题库与设置之间）。它把当前题面的来源当作点名 —— 「七上 · 有理数」只取章名，「考点 1 整式的概念」去掉考点序号 —— 拼成 `graph.html?q=…` 回到图谱定位；板上没有题面时退回图谱首页。按钮提示会跟着来源变（如「回到知识点 · 有理数」）。
- **题库悬浮面板**：可拖拽、可开合，与图谱信息面板同一套。
- **底部工具条上的「上传我的题」**：独立功能（拍照 / 传图识别在 Plan 3），点开选一道自己的题上传。这一版的按钮点了会给一句实话 + 一条现在就能走的路，不做点了没反应的假按钮。
- **右侧竖工具条**：对"**这道题**"做的事全收在这一条上（竖着排、图标竖着放），三个按钮 —— **分析（里面带答案两个 tab）/ 转译 / 保存**。底部那条是画板自己的工具，这条是"对这道题做的事"；板上有题才亮、没题时三个都灰掉，**这样题目周围干干净净**。
- **「分析」= 一个面板、两个 tab**：点一下浮出**一个**框，第一页是"分析"（把"该往哪儿看"按 1、2、3… 列出来，有几级写几级、上限 8 步，只在 tab 上写着「4 步」），第二页是"答案"（结果加重 + 分步 + AI 注释，一个开关切「显示注释 / 收起注释」）。**只读**：一个字都不用填，"目的就是看"。**分析页里不出现答案**（这是底线 —— 给了答案，前面几步就没人走了）。面板长内容自己滚，不会顶出画布。
- **分析是针对"当前这道题"做的**：面板顶上有一行「正对：<册·章>　<题面>」，切题时先变；台阶本身也按这道题生成 —— 从题面里**复述**两件事填进去：题面上写着的数（「先圈出来：7、3」）和题面上出现的记号与运算（「加法、减法」）。**只复述、不推断**：圈出来的就是题面上印着的字，所以不可能算错；抠不出东西的题（一个数都没有）自动退回通用台阶。**这就是"切题时分析跟着换"**：不接真服务的前提下，能让分析随题变化的只有题面自己的东西。
- **题面自己也有两颗控件**（鼠标压到题面上才出现，落在题面框**之内的右上角**）：**✕ 收起题面 / ⠿ 拖动**，跟分析面板标题栏上那一套同样的形状与动作 —— 指纹是按上去真能搬题面的（跟按在题面标题行上同一条路），不是只做了个样子。**必须在框内**：浮到框外时指针从题面挪过去要先跨过一段空档，一跨出去题面就判定"离开了"、控件当场消失，于是永远点不到。
- **面板与转译窗口各是各的位置**：都是"工具窗口"（位置是画布里的屏幕像素），**标题栏就能拖**，跟题目完全无关 —— 题目拖到哪儿它们都待在原地；刷新回来还在你放的地方。
- **「保存」= 一个按钮两个动作**：存进「我的题」（题面 + 你写的笔迹 + 分析/答案/转译出来的文字，落在本机，以后能重新打开接着做）/ 导出成图片（题目 + 你写的 + 生成的文字，一张 PNG 下下来）。
- **导出图片的分辨率**：导出前把板面临时按「内容正好铺满画布 + 像素密度顶到 5 倍」重画一次，抠完再还原（同步完成，屏幕上看不到闪）。不这么做的话，抠的就是屏幕上那一帧 —— 用户缩到 69%，内容就只有 0.69 倍的像素，导出来必然糊。实测同一块内容：像素从 1380 宽涨到 3440 宽。
- **浮层的尺寸规矩**（一处声明，四处对齐，别再各写各的）：容器圆角 16px（`--math-radius-lg`，跟底部工具条、题库面板同档）· 里面的按钮与条目 8px（`--math-radius-md`）· 标题 13px（跟题库面板标题同档，**压住正文**）· 正文 12.5px · 注释 12px · 计数与微标 11px。
- **工具条槽位**：底部 15 个（2 个工具组 + 12 个普通按钮 + 1 个缩放读数）· 右侧竖条 3 个，浮层 146×117px。末尾那几格是**视图组**：缩小 · 读数（点一下回到 100%）· 放大 · 适应内容（`maximize-2`，与图谱页的「适应窗口」同一个图标）—— 「适应内容」原来藏在「画笔设置」浮层里，找一个适应内容得先打开设置，已按用户要求挪到工具条上。

### 2.6 跨页"去白板"桥（`assets/js/board-link.js`）

- 在 10 类"可演算条目"旁注入统一的"去白板"小按钮：考点速练题目、练习结果题目、考点总览条目、错题本题目、错题详情题干、方法速学方法、易错速析易错点、公式速查公式、知识点卡片标题、笔记条目。
- 通过 `whiteboard.html?t=题面&g=来源&x=补充` 传参，白板端解析后自动落座。
- 章节页目录树、章首页的密集列表**不挂**按钮，保持列表干净。

### 2.7 练习与真题闭环

### 2.11 时间轴（`timeline.html`）

> **正在按用户 2026-09-29 的 18 条意见重做**（清单与进度见 §8）。下面写的是**当前代码的样子**，
> 过期的描述会被改掉，不留"文档写的和代码不一样"。

一屏**一根完整的数轴**，画在 canvas 上（不是 DOM）：可以拖、可以一直放大，工具条 / 网格 /
浮层 / 气泡提示整套照**白板**那一套（用户原话："图标样式和大小都参考我们的白板功能"）。

**① 刻度从图谱来，六级文字随缩放细分**

轴上的格子不是设计稿里编的那几组数，而是 `window.MATH_TREE` 摊平出来的。
**文字出现的六级与顺序是用户 2026-09-29 定的：分段 → 年级 → 册 → 章 → 节 → 知识点**：

| 级 | 是什么 | 现在的量 |
| --- | --- | --- |
| 0 分段 | 小学 / 初中 / 高中 / 竞赛 | 4 |
| 1 年级 | 图谱里**没有**这一层，从册名推：一年级上册 → 一年级；必修第一册 → 高一 | 11 |
| 2 册 · 板块 | `book`；竞赛没有册，一条 `track`（代数 / 几何 / 数论 / 组合）落在这一级 | 23 |
| 3 章 | `chapter`（竞赛那四支的章底下没有节，章自己就是最细一格） | 185 |
| 4 节 | `section` 底下没有细分知识点时，节自己就是一格 | 520 |
| 5 知识点 | `point`（例：绝对值）—— 轴上一格一个 | 280 |

摊平后 **769 格**（`4 分段 / 11 年级 / 23 册 / 185 章 / 520 节 / 280 知识点` —— 这几个数原来刷在左上角读数里，
2026-09-30 按用户要求收掉了，见 ⑤）。放大时一级一级自然长出来（缩小时反过来一级一级收掉），
规则是"这一段在屏幕上够不够宽"：先丢知识点（< 5px）、再丢节（< 12px）、再丢章（< 20px），
最后只剩学段与册 —— 这就是"永远是一条完整的数轴，缩小时只显示重要的部分"。
再放大到一格 ≥ 56px 时，格内还会出现 5 个小刻度（将来"知识点内部的部分"就落在这些位置上）。
（上面说的是**标记**；**名字**另有一层规则 —— 同一时刻只写一级，见 ②-2。）

**② 轴上的标记：学段用大点，册 / 章 / 节用刻度线，知识点用小点**

用户口径（原话："数轴是一条线。几个阶段，然后有一些大的点来显示。你可以给它一些刻度，
用粗一点的线，或者高一点的线，这都没有问题"）：

**轴本身是一条点线**（2026-09-30 照参考图改的）：不再是"一根实线 + 一堆刻度线"，
而是一串小圆点串成的轴，节点像珠子一样穿在上面（`drawAxis` 里 `setLineDash` + 圆头线帽）。
两端的短竖线保留 —— 那是轴的端点。

| 级 | 标记（2026-09-30 照参考图改） | 说明 |
| --- | --- | --- |
| 分段 | **穿在轴上的空心圆**（r≈6.4px，白底 + 灰描边） | **不写名字**（2026-09-30 撤掉，见 ⑲）：学段靠那颗圆认 |
| 年级 | 刻度线 32px（粗 1.6px） | 越粗的级线越长也越粗 |
| 册 · 板块 | 刻度线 26px（粗 1.6px） | |

| 节 | 刻度线 12px | |
| 知识点 | 轴下那排**小点**（y = 轴下 9px）当刻度 | "点就是知识点" —— 不再另画线 |

**②-2 名字只写一级，其余钉在屏幕左边（用户 2026-09-29 的更正）**

用户原话：**"底部的名字不可能各个层级都出现啊……只出现当前的；他上一级别的就在左边
一层层对应出现。"** —— 六级名字不再同时铺在轴上，规则是：

| 哪一级 | 名字写在哪 |
| --- | --- |
| **当前这一级** | 轴上**逐段**写（屏幕上画得出来的**最细**那一级：由细到粗找第一级"过半的段名字都写得下"的） |
| **更粗的几级**（分段 / 年级 / 册 / 章 / 节 …） | 轴上**一个名字都不写**，每级只在屏幕左边钉一条："视野左缘那一段"的名字，一级一行往下排成面包屑 |
| **更细的几级** | 一个名字都不写（标记照旧按宽度画） |

判据沿用同一条（"段装得下半个名字"），**挑级别和写名字必须是同一条** ——
不然会出现"挑中了这一级、可它的名字一个都写不出来"，轴上就空一片（踩过一次）。
视野左缘跑到轴外（适配那一刻）时先夹回轴的范围再问，不然左边那一列会整列空掉（也踩过一次）。
六级**标记**不受这条影响：分段大点 / 册·章·节刻度线 / 知识点小点照旧都画。

标签的行位是（屏幕像素，越粗的级越靠下）：分段 **158·178**（名字 + 区间两行）/
年级 132 · 146 / 册 108 · 122 / 章 82 · 96 / 节 54 · 68 / 知识点 18 · 32 · 46；
一段名字不够宽就不画 —— 缩小时先丢知识点、再丢节、再丢章，剩下上面几级；放大时一层层长出来。

**名字装不下时用"…"截断**（2026-09-30 照参考图改）：原来那一档是"整条不写"，轴上一空一片；
现在参考图里那种 `有理数…`、`一元二…` 的写法 —— 但只在**连半个名字都放不下**时才截，
装得下半个的就写全（多出来的字靠"挪行"避让）：中文册名如"一年级上册"挤一挤还看得清，
不该被截成"一年…"。

**踩过的坑（值得记一条）**：画布清屏**必须按像素密度清**。原来退回单位变换再
`fillRect(0,0,w,h)`，只擦掉了左上角 1/dpr² —— Retina（dpr=2）上剩下四分之三留着上一帧，
一放大一拖动就把旧文字糊成一片（用户截图给的正是这个）。白板的 `redraw()` 是先
`setTransform(dpr,…)` 再铺底，这里对齐它。**无头浏览器 dpr=1，怎么截图都是好的**：
这一条已经在 `verify_timeline.rb` 里钉住了。

**③ 彩色条：高矮 = 难度、颜色 = 掌握情况、顶端是圆的、默认不显示**

> 这一条被用户更正过一次，两版都记在这里，免得再绕回去：
> **第一版（错）**：高度 = 掌握度，没学过的不画（掌握度 0 就没有条子）。
> **第二版（对，现役）**：**学没学都有高度**，高矮 = **综合判定的难度**（`diff` 1.0–5.0）；
> 颜色 = 掌握情况；没学过的就是"未开始"那档灰，不是没有条子。

每个知识点从轴上长一根条，**顶端走二次曲线收圆**（用户原话："数值出来这个色条的时候，
它应该是一个圆形的，比较舒服"）。难度最低的一档也留 0.34 的高度 —— 难度 1 要是画成零高，
"简单"就变成了"没有"，跟"这根条子不存在"分不开。

**默认不显示**（用户原话："如果太小的时候……默认时不显示这些彩色的。它只有刻度，
只有这些文字的点。放大的时候就可以展示一下。还有这个有按钮控制显示，它才显示"）：
这一层跟底部那颗「掌握度」按钮绑在一起 —— 关着的时候轴上不跳颜色（点也是中性灰），
按一下才长出彩色条 + 状态色。高度档（低 / 中 / 高）在「网格与高度」那个浮层里。

两处尺寸的取法**故意不一样**：宽度按**世界单位**（跟着轴缩放：缩小时是一条密梳齿，
放大后每根都分开），高度按**屏幕像素**（96 / 150 / 224 三档，默认"中"）。
高度若是也按世界单位，放大十倍一根条就有两千多像素高，屏幕上只剩条子的一个下角。
换高度档只重摆竖向、不动缩放（用户正放大看着某处，不该被弹回 100%）。

**④ 底部还加了「学习计划设定」按钮**（用户第 16 条："你先加上一个按钮就行，你记录一下"）：

**⑫ 掌握度是五因子加权出来的；知识点内部再细分就是它的卡片**

速度 10% / 错题消除 10%（`assets/js/timeline-data.js` 的 `FACTORS`）。

两件事因此是**算得出来、对得上账**的，不是各写各的：

- 卡片的正确率围着这个知识点的"正确率因子"起伏，卡片的状态由正确率分档 ——
  所以一群卡片看过去，跟知识点自己的颜色是对得上的。

参考图底部还写着三条规则：**宽度 = 卡片权重、高度 = 难度、颜色 = 状态**。三条都已经照做：

**最细那一档：把一格展开成它名下的卡片**（一格宽到 56 屏幕像素就拆卡，4200% 左右）。
这一档画的不是整格那一根柱子，而是这个知识点名下的那几张卡 —— 把这 1 格宽度按卡片权重
分给它们并排画进去，每张卡的高走卡片自己的难度、颜色走卡片自己的状态；
卡再宽一点（≥34px）就写上正确率，再宽（≥52px）把卡片名也写上。
掌握度那一层关着的时候，卡片只画中性灰的结构（颜色同样归「掌握度」那颗按钮管）。

| --- | --- | --- | --- |

两处摆法都问过用户并照答做：**横着**贴着工具条上方铺一条（不是竖轴）；**只在放大之后出现**。

**第二轮**（"太丑了……做得细一点。底下的白色框就不要了"）
—— 原来的白卡片（描边 + 投影 + 玻璃底）撕掉了，只剩**一条 12px 的细杆 + 右边一行读数**；
杆里那四个"小学 / 初中 / 高中 / 竞赛"的白底小字也去掉了（见 ⑲）。

**第三轮**（"放在图例的上方" / "他挡住了，中间没有呼吸感" / "那个颜色不对啊，他只搞了一半儿"）：

- **排到图例条上方**：同一 flex 列里的顺序改成"网格弹层 → **缩略条** → 图例条"，
  图例不开时它自然就是最上面那一样。整列 `bottom` 74 → **78** ——
  实测上一版缩略条的底边正好压在工具条顶边上（`749` 撞 `749`），现在留出 14px。
- **学段色铺满整条**：第一版只铺了下面那 1/3、上面一截是灰的，用户看完成品说"只搞了一半儿"。
  现在底子整条就是那四条学段色（`g.fillRect(seg.start * cw, 0, …, h)`）。
  "缩略的轴"那排小竖线改成压在**顶上那 28%** 的一条细线，而且**只在掌握度开着时画** ——
  关着就不画，不然又是一条"一半有色一半没色"的杆子。
- **底色罩子 66% → 42%**，窗口本身改由**那道描边**认（`--math-foreground` 80%）：
  放得很大时窗口只占几个百分点，66% 会把剩下 90% 洗成近白 —— 那正是"颜色不对"的来源。

**第四轮**（"这个宽度太宽了，会显得很笨，细一点就行" / "滑块的那个颜色现在也比较丑，你那个底色
就直接弄成灰色，或者是黑色，然后那个滑块的那个颜色就搞成那个系统色" / "鼠标滑到下方那些功能按钮的
时候，按钮的名字被时间轴挡住了"）—— 这一轮把缩略条**定成一条标准滚动条**：

- **宽度 640px → 420px**（`width: min(420px, 100%)`）：跟底部那条工具条差不多宽（实测工具条 411px），
  一条细杆配一条工具条，长度也齐，"不显得笨"。
- **底色换成中性灰**（`.tk-mini__track { background: var(--math-line-strong) }` ——
  亮色下是一道浅灰、暗色那一包就是黑）；
- **滑块换成系统色**（`.tk-mini__win { background: var(--math-primary) }`）：跟着七个高亮色走，
  选红就是红的、选绿就是绿的。**那层白纱和描边一起去掉** —— 外面已经是灰的，一块实心色块
  就是最直白的"我在哪一段"，不必再拿白纱去洗别处。
- **学段色退成杆底一条 2px 的刻度尺**（`g.fillRect(seg.start * cw, h - ruler, …, ruler)`）：
  第三轮那版"四段色铺满整条"太花，这一轮底色要灰 —— 两条要求并存的办法就是让它变成刻度尺，
  "学段认色不认字"（⑲）这条口径还在。掌握度那排小竖线**整条撤掉**：杆子现在只讲"范围"一件事。
- **工具条那层从 5 抬到 9**（`.tk-dock`）：气泡提示是按钮自己的 `::after`，
  而 z-index 在"有 z-index + position 的祖先"里是**分层用的**（`.tk-dock` 就是这样一个祖先）——
  所以气泡里写的 `z-index: 9` 只能在工具条内部排序，整条工具条连气泡一起压在 `.tk-above`（6）下面，
  鼠标划上去就被缩略条盖住（用户报的正是这个）。抬到 9（高于缩略条 / 图例条 6、浮动卡片 7）即好。

**第五轮**（"拖动滑块的时候时间轴抖动这是不对的" / "缩略图的提示文字应该在缩略图的上方，不应在右边"）
—— 这一轮修的是**手感**，两句话各对一个根因：

- **读数搬到杆子上面去**（DOM 里读数是 `.tk-mini` 的第一个子节点，靠 `flex-direction: column` 落在杆子上方）。
  这不只是好看：读数原来跟杆子挤在同一行、又是 `flex: 1` 抢宽度，而**读数的宽度是变的**
  （"视野 1–43" 比 "视野 363–681" 短一截）—— 读数一变宽杆子就变窄，`miniAt()` 量到的百分比
  就跟着漂，时间轴于是来回抖。分行之后杆子的宽度由 `.tk-mini` 定死（420px），与读数无关。
- **滑块的宽度改成"一屏能装下多少格"**（`view.w / view.scale / N`，只跟缩放有关）：
  原来拿 `visibleIndexRange()` 算 —— 那是"屏幕上那几格"，拖到两头时视野有一半落在轴外，
  区间被夹短，滑块就忽宽忽窄。现在**拖动只挪位置、不动宽度**，位置另夹在轨道内不越界。
- 第三道保险：**整段拖动只量一次杆子**。`miniDown` 把 `getBoundingClientRect()` 的结果
  存进 `miniDrag.box`，后面每次 `miniMove` 都用这一份 —— 映射彻底冻住，
  中途哪怕有别的布局变化也不会错位。

- **一条细杆**（`.tk-mini__track`，12px、`border-radius: pill`、底色中性灰）：
  杆底 2px 是 **四个学段各一支色**（`--math-stage-primary / junior / senior / olympiad`，
  四支都引用现成的令牌，所以中色 / 暗色两包不必各写一遍）的刻度尺。
- **亮着的那一段 = 屏幕上正显示的范围**，由 `.tk-mini__win` 那块**系统色实心块**表示；
  外面就是灰杆本身，不压任何罩子。
- **读数在杆子上面、居中一行**：`视野 363–681 / 共 769`（杆子细了，一行短句挨得住）。
- **什么时候出现**：`miniZoomed()` 就是 `view.scale > view.fit * 1.02` —— 屏幕上装不下整条轴时才浮出来；
  点"适配"或缩到能看全，它自己收起（`syncMini()` 每帧算一次，`redraw()` 末尾调用）。
- **点 / 拖 / 键盘**：`role="slider"`。点一下或拖一下 = **只左右平移**视野（缩放不动，缩略条也能当路标用，
  `miniJump` 把那一格挪到屏幕中央）；聚焦后左右方向键各挪 1/4 屏；aria 读数跟着报当前范围。
- **只在需要时重画底子**：那条刻度尺不必每帧重画 —— `miniStamp()` 是"指纹"
  （宽度 + 主题底色 + **四支学段色**），指纹没变就只挪滑块。
  学段色要算进指纹：换主题 / 换高亮色时 `C.stage` 会重解，不带上的话色带还是上一套的色。

实测（无头 Chrome）：适配档隐藏 → 切到初中段浮出（窗口 left 46.68% / width 42.26%）→ 放大 3×
宽度收到 14.43% → 点 25% 处挪过去 → 拖到 80% → 左方向键回退 → 适配后自动收起；
第三轮复测：1837% 下整条是"蓝 → 绿 → 金 → 紫"的四段色带（上下两排取样的颜色都与学段对得上），
窗口是一枚描了边的胶囊，读数"视野 359–412 / 共 769"；图例开着时三样的纵向落点是
缩略条 674–690、图例条 698–735、工具条 749 —— 样与样之间都留着缝。

第四轮复测（成品的定稿数）：杆子 `295 × 12`（整条 420，比上一版 515+640 短了一截）；

## 3. 原理（为什么这么做）

### 3.1 零构建，是硬约束不是偷懒

不用 npm、不用打包器、不用框架。理由：一是任何一台电脑双击就能打开，交付零门槛；二是知识结构本身在变，工具的稳定性比开发的便利更重要。
**代价与对策**：没有模块系统，就用"全局脚本 + 顺序依赖"的方式组织，所有页面脚本加载顺序固定（`shell.js → ide-shell.js → board-link.js → pages.js → math-tree.js → mindmap.js`），越靠后的越依赖前面的。

### 3.2 IDE 化外壳，而不是网站导航

左栏是可折叠的"工具栏"，不是导航栏。它要求：
- 折叠时不占正文宽度（覆盖式展开）；
- 状态可记忆（谁都不希望每次刷新都重新点一遍）；
- 快捷键对齐开发者肌肉记忆（`⌘B`）。

### 3.3 同源样式：白板是"母版"，图谱是"派生"

白板的工具栏是这条产品线的视觉基准。图谱的工具条/浮层/悬浮面板**不重新设计**，而是由工具脚本从 `whiteboard.html` 抽取样式、把 `wb-` 前缀改名为 `mm-` 后生成，写进 `graph.html` 的 `/* MM-SHARED-BEGIN */ … /* MM-SHARED-END */` 区段。

好处：白板改了样式，图谱重新生成即可同步；两边尺寸不会"各自漂移"。

### 3.4 声明式注入，而不是手工复制粘贴

`board-link.js` 用一张"规则表"（目标选择器 → 取值函数）把按钮注入到所有页面对应的条目上，并用 `data-board-done` 保证幂等，配合 `MutationObserver` 兜住后续动态渲染的内容。
**收益**：新增一类入口只改规则表，不改 42 个页面。

### 3.5 浏览器全屏的"覆盖区"解法

浏览器全屏在文档卸载时必然退出，这是规范层面的行为，改不掉。所以解法不是"阻止退出"，而是**不卸载**：全屏中点击站内栏目时，把目标页加载进一个铺满的 iframe，顶层文档始终不动，全屏自然保持。

### 3.6 本地优先的数据模型

1.0 没有后端。论坛、会话、画布、面板开合、图谱筛选范围全部落在 localStorage：

| Key | 存什么 |
| --- | --- |
| `wkmath.shell.left` / `wkmath.shell.right` | 左/右栏开合状态 |
| `wkmath.user` | 登录会话（姓名、年级） |
| `wkmath.whiteboard.v1` | 白板内容 |
| `wkmath.forum.v1` | 论坛帖子与回复 |
| `wkmath.graph.scope` | 图谱当前册筛选 |

好处：无网可用、刷新不丢、便于演示。代价：换设备不同步 —— 这是 1.1 之后要接后端的地方。

### 3.7 一个必须记住的坑：CSS Grid 隐式列

单列骨架下，如果子元素仍然带 `grid-column: 2`，浏览器会**凭空生成第 2 列**，把画布压成 1px（历史上"全屏白屏"就是这个原因）。
**对策（写成红线）**：`.wb-stage{grid-column:1}`、`.mm-stage{grid-column:1}` 必须显式声明，并且用断言守住。

## 4. 规范（写代码要守的）

### 4.1 目录规范

```
WKMATH/
├── *.html                 页面（扁平放置，不做子目录，便于相对路径与双击打开）
├── assets/css/            base.css 基础样式 / tokens.css 设计令牌 / shell.css 页面骨架 / ide.css 外壳
├── assets/js/             脚本（全局挂载，按固定顺序加载）
├── tools/                 一次性改造脚本（migrate-*/remove-*/add_* 与构建器）
├── tools/checks/          自检体系（断言包 + 静态体检 + run_all.rb）
├── docs/                  文档（本文件所在处）
├── serve.rb               本地预览服务
├── .gitignore             排除自检产物 / 分享包 / 系统杂项
├── tools/first-push.sh    首次入库的一键脚本（git init → commit → push）
└── 人教版初中数学知识结构.md/.xmind   教学内容源
```

### 4.2 命名规范

| 对象 | 规则 | 例 |
| --- | --- | --- |
| 外壳类名 | `ide-` 前缀 + BEM | `.ide-rail__item--active` |
| 白板类名 | `wb-` 前缀 | `.wb-dock__btn--group` |
| 图谱类名 | `mm-` 前缀 | `.mm-dock__btn` |
| 论坛类名 | `forum-` / 语义块名 | `.forum-nav` |
| 脚本挂载点 | 挂在 `window` 上的能力对象 | `window.WK_SHELL`、`window.__MM__`、`window.MathSite` |
| DOM 钩子 | `data-` 属性 | `data-nav-key`、`data-board-done`、`data-wb-tip`、`data-mm-tip` |

### 4.3 路径规范

- 一律**相对路径**，不写死绝对路径；脚本里要项目根时用 `File.expand_path('../..', __dir__)`，并允许 `ENV['WKMATH_ROOT']` 覆盖。
- 中文路径、中文参数必须显式编码/解码（`encodeURIComponent` / `decodeURIComponent`）。
- 脚本读文件统一 `File.read(path, encoding: 'UTF-8')`；涉及路径拼接的常量加 `.dup.force_encoding('UTF-8')`，否则某些终端 locale 下会报 `incompatible character encodings`。

### 4.4 视觉规范

- 颜色、圆角、字体一律走 `assets/css/tokens.css` 的 `--math-*` 令牌，禁止散落十六进制色值。
- 图标用本地 `lucide.min.js`，写法 `<i data-lucide="名字"></i>` + `lucide.createIcons()`。
- 尺寸基准：工具条按钮 34px；浮层 146×117px；**悬浮浮窗宽度 320px（`--math-float-w`）**；主色 `--math-primary`，描边/分隔用 `--math-border`。
- **高亮色只改三个数**：`html[data-wk-accent="…"]` 只覆盖 `--math-primary` / `-strong` / `-foreground`；其余几档（`-soft` / `-tint` / `-200` / `-300` / `-400`）与焦点圈、信息态都由 `--math-primary` 与 `--math-background` 混出来（`color-mix`）。所以"换高亮色 / 换配色"都不用逐档重算 —— 加一个色只需要写三个数（亮底一套 + 暗底一套）。默认那档（松绿）不写属性，住在 `:root`。**每个色都必须有暗底那一套**：暗色下主色要换成亮色版，深色主色压黑底等于隐形。守线：`verify_display.rb` 第 6b 节（逐色 × 逐配色算对比度）。
- **暗色是纯粹的黑白**：`html[data-wk-theme="dark"]` 的中性面（底 / 面 / 卡 / 浮层 / 分隔 / 四级灰字 / 悬浮条）一律 **R=G=B**，底 `#000000`、字 `#ffffff`；允许有颜色的只有 `--math-primary` 那一族（品牌色：按钮 / 选中 / 焦点圈）与 `--math-state-*`（成功 / 警告 / 错误）。白板的「黑板」同一套规矩（板面纯黑、粉笔纯白，网格与悬停底是无彩的白）。**这一条推翻了先前"深蓝黑更护眼、不用纯黑"的判断** —— 那是用户看过真机之后否掉的，别再照着旧理由改回去。守线：`verify_display.rb` 第 8 节。

### 4.5 组件规范

- **工具条按钮**：三态（默认 / 悬停 / 激活）；激活用实底块，不用圆环；提示统一自绘，不用系统 `title`。
- **工具组**：组按钮显示当前工具图标 + 名称 + 展开三角（`--group` + `--caret`）；浮层是同级兄弟节点；同一时刻只允许一个浮层展开。
- **悬浮面板**：绝对定位；**宽度一律取 `--math-float-w`（一个数管全部浮窗，白板与图谱两页同源）**；拖拽手柄在标题栏（指纹挂在标题栏上）；`touch-action:none`；拖动范围钳制在可视区内；有关闭按钮。窄屏**只有一条**破例：名单类那一块（题库 / 图谱的信息卡）摊到整屏读长名单，阅读框任何时候都保持 320px。

### 4.6 交互规范

- 键盘可达：所有按钮可 Tab 到，`Esc` 关闭最上层的浮层/浮窗。
- 焦点管理：鼠标点击后主动失焦（避免侧栏"粘住"），键盘导航不打断。
- 状态反馈：改变筛选/层级后给出轻提示（toast），并写入 localStorage。
- **浮层事件隔离**：浮层（悬浮面板、工具条、浮出菜单）压在画布上，属于界面层。在浮层里按下或滚动，画布**不许**跟着平移或缩放。在 `.mm-canvas` / `.wb-canvas-wrap` 这类"画布宿主"上挂监听时，必须先用 `closest` 判断事件是不是来自浮层（`.mm-card / .mm-dock / .mm-flyout`）。图谱的浮层是画布的子元素，最容易犯这个错；白板的面板与 `<canvas>` 是兄弟节点，天然不会。

### 4.7 数据规范

- localStorage 一律 `wkmath.` 命名空间 + 版本后缀（如 `wkmath.forum.v1`）。
- 读取必须容错：字段缺失、JSON 损坏、版本不符都要能回落到默认数据，且不能抛错阻塞渲染。

### 4.8 画布规范：画世界坐标前必须自己设变换

- 白板的每一笔都存在**世界坐标**里，绘制时靠 `ctx.setTransform` 换算到设备像素。**凡是要画世界坐标的地方，都必须自己先调一次 `worldTransform()`**，不许依赖"上一步留下的变换"。
- 为什么：`redraw()` 结尾的 `ctx.restore()` 会把变换退回**设备像素空间**，所以任何在 `redraw()` 之外单独发起的绘制（拖动途中的增量墨迹 `drawTail`、按下时的第一笔 `drawStroke`）拿到的是错的那个变换。
- `setTransform` 是**替换**而不是叠加，所以重复设是幂等的：多设无害，少设出事。因此在 `drawStroke` 内部设一次，`redraw()` 的批量绘制再设一次，也是安全的。
- 这个错误的特征是**只在"画的时候"错、一松手就对了**（松手时 `redraw()` 重画把它纠正回来）。所以"落定后的数据对不对"永远测不出来它 —— 断言必须去测**绘制那一瞬间用的变换**。测试桩为此照真机模拟了变换栈（`setTransform` 替换、`save`/`restore` 压弹），并在每次 `stroke()` 时记录当时的变换。
- 真实教训：用户报"我在 A 点落笔，画笔却从别处画起、还多一条长线"，查了数据、渲染像素、画布尺寸比例、缩放视图，全都对；最后是**量出绘制瞬间的变换**才抓到它（真机实测绘制时用的是 `[2,2,0,0]`，正确应为 `[1.381,1.381,32,32]`）。

### 4.9 跨页点名规范：先把范围对齐，再谈定位

- 任何"带着一个知识点从别的页面进来"的入口（目前是 `graph.html?q=…`），定位前**必须先把目标放进当前范围**：不在当前**学段**就切学段，不在当前册 / 领域就放开筛选。学段跟册一样记在本机 —— "上次看的是小学，这次点名的却是初中的知识点"是最常见的一路。
- **视图状态只许是有限数**。`centerOn` 不许拿没布局过的节点（`x/y/w` 是 `undefined`）算位置；`applyView` 不许把非有限的 `transform` 写进 DOM。理由：`translate(NaN,NaN)` 会被浏览器整条丢掉，图瞬移回左上角，而且之后**每一次拖动、每一次缩放算出来还是 NaN** —— 用户看到的是"不能放大缩小也不能拖"，听上去像另一个毛病（见「已完成」里那条缺陷十六）。
- 断言里比位置时**先判 `isFinite` 再比不等**：`NaN !== NaN` 恒为真，只写"变了没有"等于没守。

## 5. 流程（怎么改）

### 5.1 五步法（每一次改动都走这套）

1. **备份** —— 先把要动的文件复制到临时目录，出问题能整体回退。
2. **脚本化改造** —— 批量修改写成 `tools/` 下的 Ruby 脚本，**必须幂等**（重复执行结果一致）。
3. **补断言** —— 为新行为写断言；能静态核对的（结构、样式值、必要 token）就静态核对，能跑纯逻辑的就用 osascript 跑真实引擎代码。
4. **全量自检** —— `ruby tools/checks/run_all.rb`，断言全绿、语法全过、断链 0 才算完成；任何一条红都必须先修。
5. **人工验收** —— 在浏览器里按真实路径走一遍（全屏、拖拽、跨页带题这些只有真机才能确认）。

### 5.2 自检体系

**一个命令跑全部：**

```bash
ruby tools/checks/run_all.rb          # 全部
ruby tools/checks/run_all.rb wb graph # 只跑名字含 wb / graph 的
```

它做四件事：拼装断言包（`_build/`）→ 跑 JS 断言 → 跑 JS 语法体检 → 跑静态体检，最后汇总断言总数与失败数，并以退出码表示结果（0 = 全绿）。

**"没跑完"两边都要单独算红灯。** 断言包那边早就是这么定的（没打出 `RESULT` 行 = 中途抛错，单独报"未跑完"）；静态体检这边 2026-09-29 才补上：体检脚本**中途抛错**时一行 ✗ 都不打，只数 ✗ 就会把"这条守线根本没执行"当成"没红灯"。现在的判据是**退出码非 0、且一条 ✗ 都没有 = 崩了**，单独算红灯并打印退出码。

**体检脚本报"有问题"也必须打 ✗ —— 这是同一件事的另一半。** 也是 2026-09-29 补的：`verify_rail.rb`（42 页的侧栏结构检查）原来把问题打印成**普通行**、并且从不非零退出，而 `run_all.rb` 是按输出里的 **✗** 数红灯的 —— 于是它报的问题从来进不了账：**这个脚本的检查一直没被真正执行过**。发现时里面静静躺着两条（一条是样式注释里的 `<a>` 造成的"标签不配平"误报，一条是 `白板功能规划.html` 按设计没有侧栏），而 run_all 一直报"体检无红灯"。现在：问题行一律带 ✗、有问题就 `exit 1`；误报按"**先剥注释再数标签**"修掉；那一页按 `SKIP_RAIL` 跳过（`verify_brand` 原本就是这么跳的，两边口径这才对齐）。反证 5 组，每组都确认三件事同时成立：**verify_rail 打 ✗ + 退出码 1 + run_all 报出体检红灯**。

**推论（写守线时的自查口径）：** 一条守线要真的算数，得同时满足三条 —— ①问题行带 ✗、②脚本跑完（或崩了能被 run_all 认出来）、③能被反证踩红。这三条缺一条，守线就只是"打印了一段字"。

```bash
bash tools/commit.sh "这次改了什么"
```

自检不过会直接中断，红线代码进不了仓库。

5. **打附注标签**：`git tag -a vX.Y -F <说明文件>`，说明里写清这个版本包含什么

## 6. 规则（红线，违反即打回）

1. **不引入构建链**。不许出现 npm / 打包器 / 框架运行时。
2. **不写死绝对路径**。脚本里用相对根 + `ENV` 覆盖。
3. **不给工具条按钮用系统 `title` 气泡**，一律自绘提示。
4. **单列骨架必须显式 `grid-column: 1`**，防止隐式列把画布压成 1px。
5. **改工具栏样式先改白板**，图谱的共享样式由生成器同步，不允许两边各自手改。图谱独有的差异（例如图谱的组按钮要显示「总览」「到章」这种文字状态，而白板只有图标）**只能写在 `/* MM-SHARED-END */` 之后** —— 写进共享区里，下次跑 `build_graph_css.rb` 就被冲掉了。
6. **每次改动必须跑 `run_all.rb`**，断言全绿 + 语法全过 + 断链 0 才算完成。（条数会随开发增长，所以规则里不写死数字，只认"全绿"这个状态。）
7. **迁移脚本必须幂等**，不允许"只能跑一次"的脚本进 `tools/`。
8. **断链必须为 0**，内部链接不允许指向不存在的页面。
9. **演示数据必须集中在数据源里**（`boards` / 规则表 / `math-tree`），不允许散落在页面里手写。
10. **中文内容与中文参数必须正确编码**，不允许出现乱码或二次编码。

  悬停或键盘焦点进来都暂停，系统设了"减少动态效果"就完全不自动播）。**内容和组件分成两个文件** ——
  `forum-banners.js` 只有数据（标题 / 副标题 / 图 / 图说 / 链接 / 按钮字，另有可选的上线下线时间），
  `banner-carousel.js` 是通用组件，接真后台时只换"从哪读数据"。图片是手绘的三张**无字 SVG** 底图，
  文字用 HTML 叠上去：换照片只改一个 `image` 字段，文字不用重做也不会糊
- 顺手修掉的缺陷（六）：**断链体检只扫 HTML，扫不到 JS 里写的链接**。轮播的图片与链接都在数据文件里，
  所以另立守线逐条检查"图片文件在不在、href 能不能落到真实页面"，并证明过它能红（把一条改指向不存在的
  `exams-2026.html`，体检当场报错）
- 顺手修掉的缺陷（五）：设置浮层多了一行后变高（真机 281px），它靠 `bottom:74px` 往上长，
  矮屏上会把顶上一截切掉、够不着上面那一行。补了兜底滚动（放不下就自己滚，绝不切）
- 白板笔尖与橡皮都改成**圆圈指哪打哪**：笔 / 荧光笔按笔宽画圈、橡皮按擦除半径画圈，系统十字光标藏起来（图形工具仍留十字，它有方向）。圆圈是画在画布上的，不是 CSS 光标，所以缩放时会跟着板一起缩。**光标归位收口到 `syncUI()` 一个函数** —— 原本只挂在 `setTool` 上，于是"刚打开页面、还没点过任何工具"这一刻没人把 `#wb-canvas{cursor:crosshair}` 压掉，十字照样挂着（真机复现：`localStorage` 无记录、工具取默认值，启动全程不经过 `setTool`）
- 橡皮改成**区域擦除**：圆圈盖到哪、哪一段才没，一笔会被圆圈咬断成两截（落笔到抬笔算一次撤销，其余笔迹一个点都不动）
- 顺手修掉的缺陷（四）：**图谱底部一排按钮悬停时提示气泡全是空的**。根因不在图谱页而在生成器 —— `tools/build_graph_css.rb` 只把选择器里的 `wb-` 改名成 `mm-`，**没改声明体里的 `attr(data-wb-tip)`**，于是 `content:attr(data-wb-tip)` 取不到值。改的是生成器（加 `BODY_TOKENS` + `rename_body()`）而不是改生成结果，重新生成即不会再犯；`verify_graph.rb` 补了三条守线：不许再出现旧属性名、规则必须读 `data-mm-tip`、每个底部按钮都得挂提示

- **知识数据从「初中一套」扩到四个学段**：小学（一~六年级，12 册 88 章）、初中（6 册 29 章）、
  高中（必修 + 选择性必修，5 册 22 章）、竞赛（四板块 30 章，只到章这一层）。四份 `.md` 源、一个解析器、
  一份 `math-tree.js`（169 章 / 1291 节点 / 90.6 KB）。**学段是册上的一栏（`stage`），不是新加的一层** ——
  加一层会动到折叠层级、面板统计、阅读器深度的全部假设；选学段用「学段合成根」，与"按课标领域看"同一套机制。
  **每册必须写目录来源、每章必须登记课标领域，缺一个生成器就停下**：漏一章不会崩、只会安静地少一块
- 图谱工具条**最前面**加「学段」按钮（小学 / 初中 / 高中 / 竞赛，默认初中）：先选哪一套教材，再看那一套内部
  按教材册次还是按课标主题看。分法栏的两格**字样与选项都跟着学段生成**（小学是"教材册次 / 四大领域"、
  高中是"教材册次 / 课标主题"、竞赛只有四大板块所以第二栏整条收起），册 / 领域两份名单也改成按学段现建 ——
  写死一份必然和另外三个学段对不上
- 阅读器（章节索引）**只列当前学段**，并与图谱**共用学段记忆键**（在图上选了高中，过来阅读器也是高中）。
  左栏那棵手写的六册 29 章因此删掉、改成按学段现建：手写的那棵必然与数据脱节，而且**章号跨册会撞**
  （小学每册都从"第一单元"重来、高中必修与选必各自排、竞赛不编号），所以章在学段内的键只在"章号唯一"时才用章号
- **数据诚实**：核不到的就说核不到。小学正处于教材换版（一~三用 2024 新版、四~六用现行旧版），
  每册的 `> 来源:` 指向**带版本号的课本站目录页**（如二年级下 2026 春版），"当前在用哪一版"本身可追问；
  **这条留给后台核稿用，不再端到学生面前**（2026-09-29 起正文里不再渲染来源网址）；竞赛的四个板块有权威依据（联赛加试四范围），
  但**章名是把大纲条目与公认教材目录归并出来的**，不是任何单一权威的原文 —— 数据文件与源文件里都写明了这一点
- 小学目录里最后 9 个洞补齐（二下、三下两册 + 7 个只核到单元名的单元）：核查结论是**二下 / 三下的新版
  都已出版并在用**（2026 春版），所以不该留空；补齐后小学从 12 册 88 章 273 节变成 **12 册 104 章 357 节**
  （含三上补上的「数学广角—搭配问题」）。只剩 **1 处待核，且是章级的**：三下「生活中的运动现象」——
  课本站只列到单元名与"剪纸"，轴对称 / 平移 / 旋转 可能在例题里，不猜，标出来
- 顺手修掉的缺陷（十）：**生成器不转义引号**。待核说明里写了半角双引号，`dump` 把它直接拼进 JS 字符串字面量，
  生成出来的 `math-tree.js` 语法报错，连 mm-check 与 reader-live-check 两个断言包都没跑完（`run_all` 报"未跑完"
  而不是"失败 0 条"—— 这条早就分开了，这次正好用上）。修法：字符串一律走 `JSON.generate`。
  这一条现在由语法体检守着，反证过：把转义去掉，`run_all` 退出码 1 并点名出错文件与出错词
- 顺手修掉的缺陷（十一）：**「待核」只数了册级**。补完册级之后，三下那处章级待核会被"12 册 · 104 章"
  这种账吞掉 —— 数据里有、界面上没有。图谱的说明与阅读器的目录头都改成**册级 + 章级一起数**，
  树上给那一章挂「待核」小标。反证过：去掉章级计数，阅读器断言与图谱静态守线同时红
- **阅读与显示**（用户提的"文字有点细，怕孩子看不清"+"要个亮中暗"）：字号三档在**声明处**乘一个
  `--math-fs`（866 处 px / rem / clamp 一次改完，引用处不重复乘），亮 / 中 / 暗做成**一整包**令牌
  （31 个颜色令牌逐一对齐，体检逐个比对，缺一个就点名），白板板面与整站配色**共用同一真值**
  （在板里切「黑板」＝整站切暗色）。顺带把正文默认字重提到 500，并把两级灰字加深 ——
  它们原来在纯白底上只有 2.6:1 与 1.7:1，低于 4.5:1 的可读标准，「看不清」的主因就在这儿；
  体检里**真算对比度**，退回原值就报错并给出比值
- 顺手修掉的缺陷（十二）：**`data-theme` 被运行环境抢走**。现象是"选了暗色还是亮的"，而本机存储、
  内存状态、白板画布全是暗的 —— 只有 `<html>` 上那个属性是 light。三个候选脚本全 grep 过都没写它，
  换一个标签上本来就没有该属性的页面也一样，最后打开一个**没有任何我们代码的裸文件页**，
  它的 `<html>` 上照样挂着 `data-theme="light"`：写它的是环境。修法是不碰这个通用属性名，
  我们的读写搬进自己的名字空间 `data-wk-*`，并加守线「不许用回通用 data-theme」
- 顺手修掉的缺陷（十三）：**悬浮工具条写死 `rgba(255,255,255,.86)`**，深色下成了画布上一大块白板
  （真机截图一眼可见）。收进 `--math-dock` 令牌；同时把"白底白字"守线从只认 `#fff`
  **扩到也认 `rgba(255,255,255,…)`** —— 原来的写法正是从这条缝里漏过去的
- 顺手修掉的缺陷（九）：`reader.html` 里那段手写目录被我第一次动手时**认错了收尾 `</div>`**（这一页有两个 `</aside>`），
  连正文与右栏一起删掉了。**断言全绿、退出码 0**，只有 `verify_bridges.rb` 在喊 —— 因为 `run_all.rb` 当时只把
  断言与语法算进退出码，Ruby 体检的红灯只是打印。已把体检红灯单独统计、单独报、也计入退出码，
  并当场验证（把一处样式改坏 → 退出码 1 且点名 `verify_graph.rb`）
- 顺手修掉的范围声明：全站页脚原来写死「人教版七至九年级 · 六册二十九章」，站点已覆盖四个学段，39 个页面逐页改成
  「小学到高中四套教材 · 竞赛章节框架」

分别由 `verify_bridges.rb` 与 `verify_graph.rb` 守线，被拆掉即报错。

## 9. 附录：怎样在本地跑起来

```bash
# 起服务（零依赖，只需系统自带 Ruby）
ruby serve.rb                    # → http://127.0.0.1:5173/
ruby serve.rb 8080               # 指定端口

# 跑全量自检
ruby tools/checks/run_all.rb     # 断言 + 语法 + 体检，退出码 0 即全绿

# 重新从白板生成图谱的共享样式
ruby tools/build_graph_css.rb

# 生成/校验教学内容数据
ruby tools/build-math-tree.rb
```
