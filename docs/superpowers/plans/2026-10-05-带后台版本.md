规格：`docs/superpowers/specs/2026-10-05-带后台版本-design.md`
日期：2026-10-05
框架：**Express + TypeScript**（用户 2026-10-05 定："公司常用的是 Express"）

## 交付边界

**本计划做：** M0–M7 —— 工具链与骨架 → 结构与正文贯通 → 账号与权限 → 学习数据 → 题库与登录闸 → 论坛同步 → 会员与支付 → 部署。

**本计划不做：** 白板云同步 · Redis · 学生端改框架（Vue/React）· SSR · AI 分析与自动批卷算法 · 多语言（规格 §2 / §6）。

**每个 M 结束的硬门槛：** `ruby tools/checks/run_all.rb` 全绿（**前端那 1452 条断言与 15 项体检一条都不许退**），外加该期新增的接口契约断言。哪一期让它变红，就先停下修，不往下走。

├── apps/

│   │   ├── prisma/schema.prisma
│   │   ├── src/
│   │   │   ├── main.ts            装配 express app
│   │   │   ├── config/            env（zod 校验；缺一个就起不来）
│   │   │   ├── db/                prisma client 单例
│   │   │   ├── middleware/        auth · rbac · validate · error · logger · upload
│   │   │   ├── lib/               jwt · password · oss · idempotency
│   │   │   ├── openapi.ts         扫 schema 生成 OpenAPI → /docs
│   │   │   └── modules/           一个域一个目录，四件套 router/service/schema/mapper
│   │   │       tree/ content/ exams/ practice/ forum/ me/ orders/ pay/ admin/
│   │   └── tests/
│   └── admin/                     Vue3 + Vite + TS + Element Plus
├── docker-compose.yml             api · admin · mysql（开发不上 MinIO，文件走本地目录）
└── .env.example

### 四条铁规（规格 §7.1）

| # | 规矩 | 怎么保证 |
| --- | --- | --- |
| 1 | **Swagger 从 zod 生成，不手写** | `@asteasolutions/zod-to-openapi` 扫 `modules/**/schema.ts` → `/docs`（Swagger UI）；加自检：源码里出现 `@openapi` / jsdoc 注释即报错 |
| 2 | **入参走 zod，出参走 mapper** | `validate({ body, query, params })` 中间件；service 只认 schema 推导出的类型；mapper 负责 Prisma → API DTO，原始对象不许直接吐给前端 |
| 3 | **权限走中间件** | `requireAuth` / `requireRole('ADMIN')`；自检：路由文件里出现 `req.user.role` 的比较即报错 |
| 4 | **统一响应与错误** | `{ code, data, message }`；错误一律 `throw new HttpError(status, code, msg)`，全局 error 中间件兜；日志带 `requestId` |

## M0 工具链与骨架

**目标：** `docker compose up` 一行起来，`/api/health` 通。

### Task 0.1 装工具链（本机现在一个都没有）

Files：无（系统层）

1. **Node LTS + npm** —— ✅ **已装（2026-10-05）**，见文末「执行记录」。装在 `~/.local/node`（用户级，不碰系统目录），PATH 写在 `~/.zshrc`。
2. **Homebrew**（走阿里云镜像）—— **需要你的密码**：Intel Mac 上它会写 `/usr/local`。这一步只能你自己跑，命令见文末「执行记录」。
3. **MySQL 8**：`brew install mysql` —— 本地开发够用，先不上容器。
4. **容器用 `colima`，不用 Docker Desktop** —— 探测结果：`download.docker.com` **不通**；`desktop.docker.com` 的 dmg 有 1.5GB 且要 GUI + 管理员。colima 是命令行的，`brew install colima docker docker-compose` 就完事。
5. **MinIO 撤掉** —— 官方已下架 macOS 构建（探测 `dl.min.io` → **410 Gone**）。开发期改用**本地目录**存储驱动，生产再上 OSS。
6. Redis：**不装**（规格 §2 #11）
7. Nginx 本机不装（本地用 Vite dev server + API 直连），只在部署机需要

**验收：** `node -v` / `npm -v` / `brew --version` / `mysql --version` 四条都有输出；`brew services start mysql` 之后能连上。（Docker 那条推迟到真要 compose 整栈时，不阻塞 M0。）

### Task 0.2 骨架与 Compose

Files：`docker-compose.yml`、`.env.example`、`apps/api/package.json`、`apps/api/src/main.ts`、`prisma/schema.prisma`

1. **先定一件事**：后台与 API 放**新仓库**，还是**本仓新目录**（`apps/`）。判据只有一条 —— 学生端要保持"零构建、静态可托管"，混进一个 npm 工程会让"这个仓要不要构建"永远说不清。**建议新仓库**，本仓只留文档与接口契约。
2. compose 三个服务：`mysql:8`（带 volume + 初始化脚本）、`api`、`admin`（**不上 minio**，文件走本地目录）
3. api：Express + TS（`tsx` 热更）；`GET /api/health` 返回 `{ ok, version, db: 'up' }`
4. Prisma：`prisma init --datasource-provider mysql` → 建一张 `HealthCheck` 表跑通 `prisma migrate dev`
5. `/docs` 能打开 Swagger UI（哪怕只有 health 一个接口）

**验收：** `docker compose up` 起来；`curl localhost:3000/api/health` 返回 `db: up`；`/docs` 打得开；`docker compose down` 干净退出。

### Task 1.1 Prisma schema（结构 + 内容）

Files：`apps/api/prisma/schema.prisma`

模型：`Stage` / `Book` / `Chapter` / `Section` / `Point` / `PointCard` / `Content`

要点：

**验收：** `prisma migrate dev` 出迁移；`prisma studio` 里 7 张表都在。

### Task 1.2 从现有数据导入（不能靠手录 520 节）

**输入已经冻好了**：`seed/`（见文末「演示数据冻结清单」）。**先跑一遍 `node tools/export-demo-data.mjs` 确认能复现，再拿它当导库的输入。**

Files：`tools/import-math-tree.*`、`seed/*.json`

1. `seed/math-tree.json` → 落 `Stage / Book / Chapter / Section / Point`
2. `seed/learning-dict.json` → 落字典：掌握度档位 / 五因子 / 卡片六类 / 错因七种 / 掌握标记 / 事件类型
3. `PointCard` 按现在那 6 类（概念 / 公式 / 例题 / 变式 / 错题 / 复习）生成默认权重
4. 正文：把 `reader.html` 里那**唯一一篇真写的**（1.2 有理数 · 数轴）抽出来落成第一条 `Content`；其余先留空
5. 演示学生：`seed/learning-default.json`（默认那份）+ `seed/learning-students.json`（三个学生）→ 落 `User`（演示账号）+ `LearningRecord` + `Exam` + `ExamPaper` + `Mistake`

**验收：** 库里的数量与 `seed/_counts.json` **逐项一致**（23 册 / 185 章 / 520 节 / 280 知识点 / 769 格记录 / 336 格有轨迹 / 15 场考试 / 812 道卷面 / 58 道题库 / 3 板 6 帖 / 3 学生）。不是"看起来对"，是脚本比数 + 抽查若干条名字。

### Task 1.3 `/api/tree` + `/api/sections/:id`

Files：`apps/api/src/modules/tree/*`、`modules/content/*`

1. `GET /api/tree` 返回**与现在 `window.MATH_TREE` 同形状**的 JSON（一次拉全树）+ `version`（内容哈希）
2. `GET /api/sections/:id` 返回正文
3. 两个都**公开**（免登录）+ `ETag` / `Cache-Control`

**验收：** `curl /api/tree | jq '.children|length'` = 4；连刷两次 `version` 不变；改一条数据后 `version` 变。

### Task 1.4 学生端三页改读接口

Files：`assets/js/api.js`（新）、`reader-live.js`、`mindmap.js`、`timeline-axis.js`、`timeline.js`、`timeline-3d.js`

1. 新增极小的 `assets/js/api.js`：`WK_API.tree()` —— **带只读缓存**（localStorage 存 `{ version, tree }`，版本命中就不请求）
2. `window.MATH_TREE` 改成异步取得：三页入口加"等树再渲染"；拉不到就用缓存，缓存也没有就出提示页（**不许白屏**）
3. **零构建**：仍然只是普通 `<script>`，一个打包产物都不许出现

**验收：** 关掉 API → 三页用缓存仍能打开、正文可读；清缓存 + 关 API → 出提示不白屏；打开 API → 与后台数据一致。

## 执行记录

### M0 · Task 0.1 装工具链（2026-10-05，进行中）

**先做了源探测**（这台机器之前 `github.com:443` 就时通时断，不探不敢装）：

| 源 | 结果 | 结论 |
| --- | --- | --- |
| `nodejs.org` / `registry.npmjs.org` | 200 | 通，但慢（6.0s / 2.6s） |
| `npmmirror.com`（阿里） | 0.5s | ✅ 走这个 |
| `brew.sh` / `mirrors.aliyun.com/homebrew` | 200 / 0.5s | ✅ 用阿里镜像 |
| `download.docker.com` | **000 不通** | Docker Desktop 装不了 |
| `desktop.docker.com/...Docker.dmg` | 200 但 1.5GB、15s 没下完 | 放弃，改用 colima |
| `dl.min.io`（MinIO mac 版） | **410 Gone** | MinIO 撤掉，改本地目录 |
| `github.com` | 时通时断 | git push 仍然失败（见下） |

**已完成：Node + npm（用户级）**

- 版本：**v24.21.0（Krypton，最新 LTS）**，`osx-x64-tar`（本机 Intel x86_64）
- 装法：从 npmmirror 下 tar.gz（52MB）→ **SHA256 校验通过**（`1462cb3b…8097`，与官方 `SHASUMS256.txt` 逐字一致）→ 解到 `~/.local/node`
- 为什么不用系统安装包 / pkg：**不要密码**（pkg 要管理员），而且**删掉那个目录就能完全还原**
- PATH：在 `~/.zshrc` 里加一行 `export PATH="$HOME/.local/node/bin:$PATH"`（幂等，重跑不会重复写）。**必须放最前面** —— 原来 `node` 解析到的是 TRAE 插件自带那个 v18（`~/.trae-cn/plugins/.../lark/1.0.5/bin/node`），npm 会直接报警"不支持 Node v18"。
- **实测**：新起一个交互式 zsh → `which node` = `~/.local/node/bin/node`、`node -v` = `v24.21.0`、`npm -v` = `11.19.0`、`which npm` = `~/.local/node/bin/npm` ✓

**Homebrew 这条路走不通了（已证实，别再试）**

原计划是 `brew install mysql`。实测**死路**：Homebrew 官方安装脚本第 166-172 行写死了

```bash
# On macOS, support Apple Silicon only
if [[ "${UNAME_MACHINE}" != "arm64" ]]
  abort "Homebrew on macOS is only supported on Apple Silicon processors!"
```

本机是 `x86_64`（Intel）+ macOS 12.7.6，跑下去必定 abort。**Homebrew 已经放弃 Intel Mac。** 连带 `colima` / `brew install mysql` 全断。

同一条链上还断了这些：MySQL 官方 tarball 只有 `macos14` 构建（本机 12.7.6 跑不了）；MacPorts 能装但从源码编译，而本机 **CLT 是坏的**（`xcrun` 缺文件）。

**用户 2026-10-05 定的方向：方案 A —— 本地开发用 SQLite，生产用 MySQL。**

- 不再需要本机装任何数据库服务（Prisma 对 SQLite 是内置支持，不用编译）
- Prisma schema 按 MySQL 写；本地开发另跑一份 SQLite schema，**差异清单**在 Task 1.1 里列
- 兜底：M1 结束时把**同一套迁移拿到真的 MySQL 上跑一遍**，防止"本地能跑线上崩"
