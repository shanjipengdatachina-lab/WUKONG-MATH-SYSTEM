规格：`docs/superpowers/specs/2026-10-05-带后台版本-design.md`

## 交付边界

**本计划做：** M0–M7 —— 工具链与骨架 → 结构与正文贯通 → 账号与权限 → 学习数据 → 题库与登录闸 → 论坛同步 → 会员与支付 → 部署。

**本计划不做：** 白板云同步 · Redis · 学生端改框架（Vue/React）· SSR · AI 分析与自动批卷算法 · 多语言（规格 §2 / §6）。

**每个 M 结束的硬门槛：** `ruby tools/checks/run_all.rb` 全绿（**前端那 1452 条断言与 15 项体检一条都不许退**），外加该期新增的接口契约断言。哪一期让它变红，就先停下修，不往下走。

## 全局约定（Express 版）

### 目录骨架

```
wukong-math/                       ← 与本仓并列（新仓库或本仓新目录，Task 0.2 定）
├── apps/
│   ├── api/                       Express + TypeScript
│   │   ├── prisma/schema.prisma
│   │   ├── src/
│   │   │   ├── main.ts            装配 express app
│   │   │   ├── config/            env（zod 校验；缺一个就起不来）
│   │   │   ├── db/                prisma client 单例
│   │   │   ├── middleware/        auth · rbac · validate · error · logger · upload
│   │   │   ├── lib/               jwt · password · oss · idempotency
│   │   │   ├── openapi.ts         扫 schema 生成 OpenAPI → /docs
│   │   │   └── modules/           一个域一个目录，四件套 router/service/schema/mapper
│   │   │       tree/ content/ exams/ practice/ forum/ me/ orders/ pay/ admin/
│   │   └── tests/
│   └── admin/                     Vue3 + Vite + TS + Element Plus
├── docker-compose.yml             api · admin · mysql（开发不上 MinIO，文件走本地目录）
└── .env.example
```

### 四条铁规（规格 §7.1）

| # | 规矩 | 怎么保证 |
| --- | --- | --- |
| 1 | **Swagger 从 zod 生成，不手写** | `@asteasolutions/zod-to-openapi` 扫 `modules/**/schema.ts` → `/docs`（Swagger UI）；加自检：源码里出现 `@openapi` / jsdoc 注释即报错 |
| 2 | **入参走 zod，出参走 mapper** | `validate({ body, query, params })` 中间件；service 只认 schema 推导出的类型；mapper 负责 Prisma → API DTO，原始对象不许直接吐给前端 |
| 3 | **权限走中间件** | `requireAuth` / `requireRole('ADMIN')`；自检：路由文件里出现 `req.user.role` 的比较即报错 |
| 4 | **统一响应与错误** | `{ code, data, message }`；错误一律 `throw new HttpError(status, code, msg)`，全局 error 中间件兜；日志带 `requestId` |

## M1 结构与正文贯通（**用户点名的第一条**）

**目标：** 后台能录「章节树 + 一节正文」，学生端 `reader / graph / timeline` 三页改读接口。

### Task 1.1 Prisma schema（结构 + 内容）

Files：`apps/api/prisma/schema.prisma`

**⚠️ 施工单这里原本写错了，已按真实数据改正。** 原计划是 `Stage / Book / Chapter / Section / Point / PointCard / Content` 七张固定表 —— 但真实数据（`seed/math-tree.json`）不是一条直线：

- 树里有 **10 种节点**：`root`(1) / `book`(23) / `chapter`(185) / `section`(520) / `point`(280) / `group`(84) / `method`(147) / `error`(100) / `exam`(47) / `track`(4)
- **竞赛那支根本没有"年级"层**：`track`（代数 / 几何 / 数论 / 组合）→ `chapter`，共 27 章
- **章下面挂着 `group`**（方法速学 / 易错速析 / 真题速练，`tone` = method/error/exam），`group` 再挂 `method` / `error` / `exam` —— 这 382 个节点在"五张固定表"里**没地方放**
- 深度不齐：小学是 学段→年级→册→章→节，竞赛是 竞赛→轨道→章

所以改成 **一棵自引用的 typed tree**：`Node`（`parentId` 自引用 + `kind`）+ `Content`（挂**任意**节点）+ `CardType`（六类字典）+ `Card`（权重在卡上）。

**两个关键取舍（都写进 schema 注释了）**

- **`kind` 用 String 不用 enum** —— SQLite 不支持 enum，用了就断掉"一份 schema 同时喂 MySQL 和 SQLite"。取值约束搬到 zod（正好是 §7.1 那条规矩）。
- **权重存在 `Card.weight` 上**，不是从 `CardType.defaultWeight` 算 —— 真实数据里**同类型卡片的权重也不一样**（1.0~1.5）。字典里那份只是新建卡片时的默认值。

**实测：** `npm run db:dev` 建出 5 张表（`node` / `content` / `card_type` / `card` / `health_check`），列名与设计一致。

**本地一定会遇到的一个坑（不是 bug）**：`prisma validate --schema prisma/schema.prisma` 在本机**必报错** —— `.env` 里 `DATABASE_URL` 是 `file:./dev.db`，而这份 schema 的 provider 是 mysql，Prisma 会校验"URL 必须以 `mysql://` 开头"。**本地别直接对 `schema.prisma` 跑 validate / migrate**，走 `npm run db:dev`；那份是给生产 / CI 用的（那边 DATABASE_URL 是 `mysql://`）。

### Task 1.3 `/api/tree` + 正文接口 ✅（2026-10-05 完成）

Files：`apps/api/src/modules/tree/*`、`apps/api/src/modules/content/*`

1. `GET /api/tree` → `{ version, tree }`。`tree` **与原来 `window.MATH_TREE` 同形状**（只多一个 `id`，正文要靠它取）；`version` 是整棵树的 sha1 前 12 位，同时当 `ETag` 用。
2. **`GET /api/nodes/:id/content`** —— 施工单原来写的是 `/api/sections/:id`，**改成这个**：正文挂在**任意节点**上，而现在唯一那条就挂在 `point` 上、不在 `section` 上，叫 sections 名不副实。
3. 两个都**公开**（免登录），带 `ETag` / `Cache-Control: public, max-age=300`；`/api/tree` 支持 `If-None-Match` → 304。

**验收（实测）**

- `GET /api/tree` → 200；`tree.children` = **27** —— 施工单原写 = 4 是**错的**：根的 27 个孩子是 23 册 + 4 条竞赛轨道，"4 个学段"是另一回事
- 与 `seed/math-tree.json` **结构化深比对 4487 个字段，0 差异**（只多了 `id`）
- 连刷两次 `version` 相同（`fea82f566fbc`）；带 `If-None-Match` → **304**
- `GET /api/nodes/483/content` → 200，4218 字符，**与 seed 逐字符一致**
- `GET /api/nodes/999999/content` → 404 `{"error":{"code":"NO_CONTENT",...}}`
- `/docs/` 200、`/api/health` 200

### Task 1.4 学生端三页改读接口

Files：`assets/js/api.js`（新）、`reader-live.js`、`mindmap.js`、`timeline-axis.js`、`timeline.js`、`timeline-3d.js`

1. 新增极小的 `assets/js/api.js`：`WK_API.tree()` —— **带只读缓存**（localStorage 存 `{ version, tree }`，版本命中就不请求）

**验收：** 关掉 API → 三页用缓存仍能打开、正文可读；清缓存 + 关 API → 出提示不白屏；打开 API → 与后台数据一致。

## 附：演示数据冻结清单（用户 2026-10-05）

> 原话：「**一定要保存好现在的演示数据，后面搭建后台服务器的时候，数据库要搞上现在的演示数据**。」

问题在于：这些演示数据现在**长在代码里** —— 结构在 `math-tree.js`，学习记录和考试在 `timeline-data.js`，题库在 `whiteboard-problems.js`，论坛在 `forum.js` 用 `localStorage` 当库。接后台就是要把它们改成读接口，**一改就可能丢**。

所以先冻一份机器可读的快照：`seed/`。生成命令 `node tools/export-demo-data.mjs`（一次性工具，可重复跑）。

| `seed/` 文件 | 是什么 | 条数 |
| --- | --- | --- |
| `math-tree.json` | 知识结构树（册 / 章 / 节 / 知识点） | 1391 节点：23 册 / 185 章 / 520 节 / 280 知识点 |
| `axis-items.json` | 摊平后的轴格子（时间轴 2D/3D 的直接输入） | 769 格 + 6 段 |
| `learning-default.json` | 默认演示学生（43.7%）：每格掌握度 + 逐格轨迹 + 考试（含卷面逐题、错因） | 769 格（**336 格有轨迹**）/ 15 场考试 / 812 道卷面 |
| `learning-students.json` | 三个演示学生（林一鸣 / 周雨桐 / 陈子航）各自那一份 | 3 学生 × 同上 |
| `learning-dict.json` | 字典：掌握度档位 / 五因子 / 卡片六类 / 错因七种 / 掌握标记 / 事件类型 / 日历 | — |
| `wb-problems.json` | 白板题库（一键送上白板演算） | 58 题 |
| `exam-scan.json` | 真题原卷：正反面页 + 每题红框坐标（一律百分比） | 1 场 / 14 个框 |
| `forum.json` | 论坛演示数据（板 / 帖 / 回复） | 3 板 / 6 帖 |
| `forum-banners.json` | 论坛首页轮播 | 3 条 |
| `_counts.json` | **对数基准** —— 导库后逐项比的就是它 | — |

**三条纪律：**

1. **`seed/` 只增不改** —— 它是"原来那份"的证据。后台要改数据就改库，别改这里。
2. **导库之后必须逐项对上 `seed/_counts.json`**，对不上就是丢了。
3. **导出必须可复现** —— 连跑两次要逐字符一致。

第三条第一版**做不到**，是后来抓出来的：论坛的演示数据是按"距现在多久"造的（帖子/回复的 `at` = `Date.now() − 偏移`），所以每次导出那些时间戳都往前漂（实测两次相差 **191 秒**，正好是两次跑之间隔的时间）。后果是 git 每次都显示 `forum.json` 被改，"只增不改"这条纪律根本没法执行。

**修法：导出时冻结"现在"** —— 沙箱里把 `Date` 换成一个 `now()` 固定为 `2026-10-05T12:00+08:00` 的子类。冻完实测：连跑两次**逐字符一致**；并且与已提交快照相比**只有 `forum.json`（18 处时间戳）和 `_counts.json` 变了，学习数据一个字没动** —— 这条也得验，否则"修好了 A 改坏了 B"。

### M4 · 题库与做题（2026-10-05）

**题库有两种东西，必须分开**：

- **可判分的题**（`choice` / `blank`）：`practice.html` 里那 4 道，带正确选项与解析
- **只有题面的题**（`board`）：白板题库 58 条 `{id, book, chapter, text}`，**没有答案**。
  硬把它当练习题，一提交只能全判错 —— 所以建了 `kind` 判别，不混

**抽题这一步差点埋雷**：填空题的空格本来就在 `.quiz-stem` **里面**
（`<input class="blank" data-answer="-3">`），整段当题干存下来 = **把答案一起发给浏览器**。
导出器现在会把 input 抠出来（空格换成 `＿＿` 占位）、答案收进 `blanks`，
并在写完当场断言"题干里不许再出现 `data-answer=` / `data-correct=`"。
（这个漏法第一次真发生了：浏览器里一翻 DOM 就看见答案。）

**接口**（全部 `requireAuth`）：`GET /practice/questions`、`POST /practice/sessions`、
`POST /practice/sessions/:id/submit`、`GET /practice/sessions`。

两条守住的事：**取题时不带答案**（判分在服务端）、**一个会话只能交一次**（重复提交会把错题本刷重）。

**实测（真浏览器，完整一轮）**

- 未登录进 `practice.html` → 只出一张「登录后开始练」的卡，`去登录` 指向 `login.html?next=practice.html`
- 登录后取到 4 道题；**DOM 里搜不到 `data-answer` / `data-correct`**
- 作答（第 1 题 B 对、第 2 题 A 错、第 3 题填空 `-3|3` 对、第 4 题 B 错）→ **50 分（对 2 / 4）**
- 逐题标出「正确 / 错误」并展开解析；错的 2 道**自动进错题本**（`source: 'practice'`）
- 重复提交 → 400 `ALREADY_SUBMITTED`

**`Mistake` 因此改了形状**：原来那几列（`examCode` / `cellIndex` / `cardNo` / `score` / `full`）
是**考试**独有的，练习错的题没有卷面。加了 `source` 判别列，考试那几列改成可空 ——

## 后台录数据（知识树增删改 + 写正文）· 2026-10-07

用户 2026-10-05 点名的那条 ——「章节 / 图谱 / 时间轴的数据都是从后台才录入的」——
到这一步才真正落地：在此之前树的接口是**只读**的，后台一章一节都改不了。

### 一件必须先在服务端解决的事：轴

"轴"（时间轴 / 3D 数轴那一根）不是把树拍平，而是有条件地挑节点：
`point` 全上；`section` 只在没有 `point` 子节点时上；`chapter` 只在没有 `section/point`
直接子节点时上；`group/method/error/exam/book/track` 一律不上。

这条规则原来活在**两个**地方：前端 `assets/js/timeline-axis.js` 和导库 `import.ts` 自己
复刻的那份 DFS。**后台一旦能改树，问题就来了** —— 学习记录是按"轴上第几格"排的，
树一改那个数字就指向隔壁格。

两条路选一条：

| 做法 | 代价 |
| --- | --- |
| 在节点上存 `axisIndex`，每次改树后重排全部学生记录 | 漏跑一次就永远对不上，而且没人会记得 |
| **读的时候现算** | 1.2 毫秒（1391 行一次 DFS），永远不会错 |

选了后者。于是：

- 新增 `apps/api/src/modules/tree/axis.service.ts` —— 轴规则**只剩这一处**
  （导库也改用它，删掉了自己那份 DFS）
- `LearningRecord.axisIndex` **删掉**：它变成了一个必然过期的缓存
- `/api/me/learning` 按当前轴摆成**一条稠密数组**（第 i 个元素就是轴上第 i 格），
  没学过或新加的格子补一个"未开始"占位 —— 不补的话数组会短一截，
  后面每一格都错位，而且错得很隐蔽

### 卷面题与错题的"锚点"换成节点

`ExamPaper` 原来只记"轴上第几格"，树一改就指到隔壁题上。现在记 `nodeId`，
读的时候映射回当前的第几格；`from/to`（这一场考了哪一段）也从卷面题现算 ——
实测 15 场考试的 `min(题下标)=from`、`max(题下标)=to-1` 全部吻合，可以安全反推。

`Mistake.nodeId` 从"外键 + 级联删除"改成**普通列 + 名字快照 `nodeName`**：
删一个知识点不该把学生的错题记录一起删掉（那是数据丢失），节点没了名字还在。

### 写接口（`/api/admin/nodes*`）

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `POST /admin/nodes` | tree.write | 新增；插到兄弟里的任意位置 |
| `PATCH /admin/nodes/:id` | tree.write | 改字段；按 kind 白名单清理 |
| `POST /admin/nodes/:id/move` | tree.write | 移动 / 排序；**不能挪到自己的后代下** |
| `DELETE /admin/nodes/:id` | tree.write | 有子节点要 `?withChildren=1`；根不许删 |
| `GET /admin/nodes/:id` | content.read | 详情 + kindFields + 子节点/后代/正文版本数 |
| `GET /admin/nodes/:id/content/versions` | content.read | 正文版本列表 |
| `PUT /admin/nodes/:id/content` | content.write | 写正文，**存成新的一版**（不覆盖历史） |

三个取舍写进了代码注释：

1. **改完树不用清任何缓存。** `/api/tree` 的 version 是现算的哈希、`/me/learning` 的轴
   是现算的顺序 —— "改一次、三处一起变"是结构的自然结果。实测：新建一个章之后，
   `/api/tree` 的 version 立刻从 `fea82f566fbc` 变成 `479ec4fa433d`。
2. **字段按 kind 白名单收。** 真实数据里每种节点的补充字段是固定的（册：stage+source；
   章：no+field+cn+unit+pending；节/知识点/方法/易错/真题：no；组：tone），
   不在白名单的置空 —— 比"拒绝保存"友好，但库里不会积下"节上挂了 stage"这种数据。
3. **删除要显式确认子节点。** 删一个册等于删掉它底下 185 个章。

### 后台界面

知识结构页从"只读"变成**左树右编辑器**：点一个节点，右边就能改字段、写正文（源码 / 预览）、
加子节点、上移下移、删除。字段按 kind 动态渲染 —— 不做"一张大表单全列出来、不相关的置灰"，
那会让人以为"节也能填学段"，而服务端会把那个值清掉。

正文用版本列表承载：**改一次存一版，不覆盖历史**（那 4218 字是全站最贵的资产，改坏了要能回退）。

### 这一轮抓出来的三个真 bug

1. **后台改完界面不变。** `/api/tree` 带着 `Cache-Control: public, max-age=300`，
   浏览器 5 分钟内**直接拿缓存、压根不问服务端**（实测：库里名字已经改了、
   `/api/tree` 的 version 也变了，界面纹丝不动）。修法：后台所有请求 `cache: 'no-store'`；
   `/api/tree` 与节点正文的缓存头改成 `no-cache`（仍然走 ETag 协商，带宽没多花）。
2. **没动过的字段被写坏。** 编辑器原来把整张表单都提交，于是"本来没有 `unit` 这一项"的章
   被写成 `unit: false` —— 而前端里有 `'unit' in node` 这类判断，"没有这一项"和
   "这一项是 false"行为不一样。修法：**只提交真正改过的字段**（与载入时的原值做 diff）。
3. **`api.js` 取个人数据没送 cookie。** 本地开发学生在 5173、接口在 3000，
   这是跨源请求，而 `fetch` 的默认是 `same-origin` → `/me/learning` 直接 401 →
   被"退回演示那一份"那条降级兜住。症状极隐蔽：**页面照常显示林一鸣的数据**
   （演示那份跟他的长得一模一样），于是"登录后看自己的"其实一直没生效。
   修法：`getJson` 带上 `credentials: 'include'`；同时把"我是谁"的判据从
   本机那个显示用的镜像改成**问服务端**（`WK_AUTH.ready()`）。
   顺手把时间轴上那句写死的「本机演示数据 · 按账号在本机算的」改成照实说
   （现在是「服务器数据 · 就是你自己的」）。

### 实测

接口侧 33 项断言全过（`/tmp` 里那份一次性脚本，跑完已删）：权限（学生 403 / 无 cookie 401）、
新建、字段白名单清理、树版本立刻变、改名、移动、防环（挪到自己后代下 → 400 CYCLE）、
删根被拒、有子节点要先确认、删整支计数正确、正文多版本（v1 的 4218 字没被覆盖）、
公开接口立刻读到新版。

界面侧真浏览器验完：点节点 → 改名字 → 保存 → 树的 version 变了且新名字出现；
写正文 → 已存成 v2 且 v1 仍在列表里；加子节点 → 子节点数 7→8、version 变了。

学生端回归：时间轴 2D/3D 与个人中心在登录后确认走的是 `/me/learning`
（`mine: true`、769 格、15 场考试），`run_all.rb` 仍是 1452 条断言 / 0 失败 / 无红灯。

### 顺带记一条经验

这一轮三个 bug 里有**两个是被"优雅降级"掩盖的**（改完界面不变看起来像加载慢；
取了演示数据看起来像"演示数据本来就长这样"）。降级路径一定要留日志、
而且降级后的样子不能跟正常结果"长得一模一样" —— 否则它会一直骗到有人真去核对为止。

## M6 前半：套餐与服务项目（后台配 · 前台显示）· 2026-10-07

用户 2026-10-05 的口径："我们的系统收费可以在后台设置套餐和服务项目，然后在前台显示出来；
默认出免费版本，收费版本一个半年期，一年期，三年期。"

于是会员页**一个价格、一个权益名都不写死**。

### 四张表

| 表 | 装什么 |
| --- | --- |
| `Plan` | 套餐：代号 / 名称 / 价格 / 原价 / 时长（天）/ 卖点 / 推荐 / 上架 / 排序 |
| `ServiceItem` | 权益对比表的**行**（知识结构与正文、三维图谱、题库…共 9 项） |
| `PlanService` | 一个格子：这个套餐含不含这项权益、显示什么值（`included` + `value`） |
| `Subscription` | 谁买了什么、什么时候到期（`startAt` / `endAt` / `status`） |

### 三条定死的规矩

1. **金额以「分」存整数**，`元` 只出现在界面层 —— 用浮点存钱早晚会差一分钱。
2. **权益判定在服务端**（`GET /api/me/entitlement`），前台只负责显示、不自己算"他是不是会员"。

## 后台改用户角色 / 停用账号 · 2026-10-07

### 一件先想清楚的事：停用是怎么"生效"的

`User` 上加的是 `disabledAt DateTime?`，不是 `disabled Boolean`：
"什么时候停的"顺带就记下了，而判定永远只有一种说法（`disabledAt !== null`），
不会出现"标志位说停用、时间说没停"这种两处对不上的状态。

生效走**两个口**：

| 口 | 拦什么 |
| --- | --- |
| `/auth/login` | 停用之后还想登进来 → 403 `ACCOUNT_DISABLED` |
| `requireAuth` | 已经登着的那些请求 → 403 `ACCOUNT_DISABLED` |

另外，停用的那一下会把他**全部会话吊销**。所以已经开着的浏览器不是"下次请求被拦"，
而是当场失效 —— 实测：停用前拿到的 cookie 再请求 `/me`，回的是 401 `SESSION_REVOKED`。

**登录那处的顺序是刻意的**：先验密码，再判停用。反过来就等于白送人一个
"这个账号存不存在 / 是不是被停用"的探测器。措辞也必须跟"账号或密码不对"分开，
否则本人会一直以为自己记错了密码。

### 界面

用户页从"只能看"变成能改角色、能停用：角色是行内下拉，**选中即生效**（服务端回什么就显示什么）；
停用走一次确认（`ElMessageBox`），因为它的代价是"人当场被踢下线、上不了课"。

失败时**重新拉一次列表**，绝不把界面留在"看着改了、其实没改"的状态上。

### 一个自己删掉的设计：那条护栏是走不到的

原本还写了一条"最后一个管理员不许降级或停用"。写完复核时发现它**永远走不到**：
能改用户的人自己必须是管理员（`user.write` 只在 admin 角色上），而他不可能是被改的那个
（"不能改自己"已经先拦住了）—— 于是"除他之外还有几个管理员"永远 ≥ 1。

真正保证"后台永远进得去"的就是"不能改自己"这一条。第二条是死代码，删掉，
并在原地写下为什么 —— 留着会让下一个人以为它在挡什么事。

### 实测

- 接口断言 **29 条全过**（一次性脚本，跑完已删）：没 cookie → 401、学生 → 403、
  空 body / 非法角色 / id 不是数字 → 400、不存在 → 404、改自己 → 409 `SELF`（降级与停用都试了）、
  升成管理员后**同一个会话立刻能进后台**、降回学生后**同一个会话立刻 403**（权限每次现查，不用重新登录）、
  停用后旧 cookie 立刻失效（401 `SESSION_REVOKED`）、停用后登录 → 403 `ACCOUNT_DISABLED`、
  停用 + 密码错 → 401 `BAD_CREDENTIALS`（只字不提"已停用"）、恢复后能登回来、
  重复"恢复"仍是 200（没变就不写）
- 界面（真浏览器）：改角色双向都通；停用 → 状态列变成"已停用 + 时间"、按钮变「启用」；启用后回「正常」
- **学生端后果**（这才是这个模块的意义）：停用一个学生之后，他那边刷新页面会**如实退回**
  「演示数据 · 登录后看自己的」，不再是「服务器数据 · 就是你自己的」。
  这里**没有改任何学生端代码** —— `auth-client.js` 的 `ready()` 本来就把 401/403/连不上走同一条路，
  一律当"没登录"。停用能生效，靠的就是它从不凭旧镜像当已登录。
- `ruby tools/checks/run_all.rb`：1452 条断言 / 0 失败 / 无红灯；`api:typecheck` 与后台 `build` 均 0 错

### 一条老经验又应验一次

断言里的用户 id 全部**按用户名现查**，一个都不写死：SQLite 的 AUTOINCREMENT 不会因为
`deleteMany` 就回到 1 —— 实测导过几轮之后 `admin` 已经是 94 号了。写死就会测出一个假结果。

## M6 后半：下单与权益生效（支付通道留接口）· 2026-10-07

用户 2026-10-07 定的：**先做下单 + 权益生效，付款走开发用假通道**；真通道先接**微信 Native 扫码**。
理由很实在 —— 商户资质在申请中（企业主体 · 微信支付商户号 · 支付宝开放平台应用 · 域名备案），
这几样代码变不出来。

### 回调那一段的顺序，本身就是它的防线

一笔钱进来要过六道，**顺序一步都不能换**：

| 步 | 挡什么 |
| --- | --- |
| ① 验签 | 伪造的回调连数据库都不该碰到 |
| ② 查单 | 单号不存在就直接回掉 |
| ③ 对金额 | **"把回调里的金额改成 1 分"的唯一防线** |
| ④ 幂等（渠道流水号唯一） | 回调一定会重试；不幂等就会给同一笔钱开两次权益 |
| ⑤ 过期 / 状态 | 超时作废的单不许再开通 |
| ⑥ 落 payment → 开通权益 | |

### 金额与名字在**下单那一刻**快照下来

`Order` 存 `planName` / `days` / `amountCents` 快照，**不给 Plan 加外键**：
后台改价、改名、甚至下架，都不该影响已经下过的单 —— 否则会出现"用户看着 268、付款时变成 288"。
（与 `Mistake.nodeName` 那条同一个道理：历史记录要读得出来，哪怕原物已经没了。）

实测：把一年会员从 288 改成 199 之后，**已下的那一单仍是 28800**，之后新下的单才是 19900。

### 续费是"接着算"的

开通权益时先看手上那份到期没：没到期就从那一天往后加。
从今天重算等于把剩下的日子白送掉。
实测：连买两次一年会员 → 剩余天数 **730**（不是 365）。

### 假通道：不是"直接开通"，而是**伪造一次回调**

`POST /api/pay/dev/pay` 不调开通函数，它造一个**签好名的回调体**，再走 `handleCallback` ——
和真通道**完全同一条链**。直接调开通函数的话，验签、对金额、幂等这几个真正会出事的地方
一步都没被走过，那样测出来的"通了"是假的。

它有两条硬边界：

- **生产环境里它根本不存在** —— 不是"注册了但拒绝"，而是压根不注册：
  回调打过来 404，那个接口本身也是 404
- **前台必须把它标成"测试支付"**，订单列表里那一行也标「测试」——
  一个长得跟真收银台一样的假收银台，迟早骗到有人真去付钱

### 验签为什么一定要原始报文

`app.ts` 给 `/api/pay/callback` 单独挂了 `express.raw`，而且放在 `express.json` **之前**。
签名是对着原始字节算的；解析成对象再拼回去，键的顺序一变就永远验不过 ——
而这种错只在真通道上才会暴露出来。

### 实测

- 接口断言 **37 条全过**（一次性脚本，跑完已删），挑关键的：
  - 没登录不能下单 401；免费版不能下单；不存在的套餐 / 通道 / 不给 channel → 400
  - **验签不对 → 400**；压根没带签名 → 400；不认识的通道 → 404；单号不存在 → 404
  - **签名正确、但金额改成 1 分 → 400 `AMOUNT_MISMATCH`**，事后核对权益**分毫未动**
  - 别人的单查不到（404，和"没这张单"回同一句话 —— 不给单号探测器用）；不能替别人付款
  - 付完 → 权益生效（一年会员 / 365 天）；**重复点一次 → 200 `duplicated`，天数不翻倍**

## M7 部署 · 2026-10-07

### 先把话说在前面：这一节的部署产物，一条都没在这台机器上跑过

本机 `docker` / `nginx` / `certbot` / `mysql` **一个都没有**（只有 openssl）。
所以那些 Dockerfile、compose、nginx 配置是**照着能跑写出来的**，不是跑通过的。
这句话必须写在最显眼的地方 —— 一份没验过的部署脚本，最坏的结局是让人以为它验过了。

能验的都验了（下面「验到的部分」），验不了的逐条列在「没验到的部分」，并给了在服务器上的自检命令。

### 拓扑：一个域名，三条路

```
浏览器 ──▶ web(nginx)
             ├── /         → 学生端静态（直接挂 WKMATH 那份，**零构建**）
             ├── /admin/   → 后台构建产物
             └── /api/     → api:3000
                               └── db(mysql:8)
```

为什么非要**同域**：登录态是 httpOnly Cookie。跨域就得 SameSite=None + CORS 白名单，
而第三方 Cookie 正在被各家浏览器逐步掐掉 —— 同域把这个问题从根上去掉。

### 验到的部分

| 验的什么 | 怎么验的 | 结果 |
| --- | --- | --- |
| 生产构建产物能跑 | `db:gen`（生成 MySQL 版 Client）→ `tsc` 构建 → `node dist/main.js`，`DATABASE_URL` 指一个不存在的 MySQL | 起来了；探活回 `db:"down"`；走库的接口干净地 500、**进程不崩** |
| 后台构建的基路径 | 给 admin 的 vite 加 `base: '/admin/'` 后重新构建，看 `dist/index.html` | 资源变成 `/admin/assets/…`。**加之前是 `/assets/…`** —— 生产上会去要学生端的资源，后台白屏，而且只报一个看不出原因的 404 |
| 请求单号 | curl 带 / 不带 `X-Request-Id` | 不带就生成 UUID；带了就原样回；连发三次三个不同的号 |
| 访问日志 | 打几个接口再看 API 的 stdout | 每行带 `rid=`；`/api/health` **不记**（探活每几秒一次，会把日志刷满） |
| 单号能不能串起来 | 用 `-H` 模拟 Nginx 传下来的号 | 日志里就是 `rid=from-nginx-abc123`，入口到接口是同一个号 |
| 出错时用户能报号 | POST 一个 1.5MB 的 body | 响应里带 `requestId`；日志里那条 warn 也是同一个号 |
| 备份脚本 | `sh -n` | 语法通过 |
| env 示例能不能被 source | `sh -c '. deploy/.env.production.example'` | 通过 —— **顺带修了一个真错**：`JWT_SECRET=换成 64 位随机串` 带空格，不加引号会被 shell 拆成"赋值 + 一条命令" |
| compose 的 YAML 与路径 | 本机 node 里的 yaml 解析 + 逐个路径判断 | 三个服务、两个卷；挂载源都在（`../WKMATH` 指的就是学生端那份静态文件） |
| 机密不会进仓库 | 造了 `deploy/.env.production`、假私钥、假临时文件，再 `git status` / `git check-ignore` | 四条规则全部生效 |

### 顺手堵的一个坑：`.gitignore` 原来挡不住生产密钥

`.gitignore` 里有 `.env`、`.env.local`、`.env.*.local`，**唯独没有 `.env.production`** ——
而部署方案里生产真值正好叫这个名字。照原样走下去，某天一个 `git add .`
就会把数据库密码和 JWT 密钥一起提交上去。
现在补了 `.env.production`，并把 `deploy/certs/*`（私钥）、`deploy/acme/*`（临时文件）、
`deploy/optional/*.conf` 也挡了，而且**真的造了假文件试过**。

### 修的一个小 bug：4xx 被记成了 500

`body` 超过 1mb 时 body-parser 抛的是 `status=413`，但兜底错误处理一直回 500。
500 是要叫人半夜爬起来查的，4xx 不该有那个待遇 —— 而且**日志在这件事上不该撒谎**。
现在按 `err.status` 走：4xx 记 warn 并按原状态码回，其余仍是 500。
实测 1.5MB 的 body：以前 `500 INTERNAL`，现在 `413 BAD_REQUEST`。

## 模块 A：会员权益真的拦起来 · 2026-10-07

### 这一块原来是个空壳

后台在「套餐与服务项目」页勾的那 9 项服务，**前台一处都没读过**（`perks` 接口回了，但没人用），
9 个 code 也从来没出现在前端。也就是说：那份矩阵只是一张给人看的表，勾掉什么都不会发生。

计划里 M6 那条验收「免费版点题库里'会员专属题' → 被拦」，就是这一条 —— 现在补上了。

### 判定只有一处，前后台用的是同一份

新增 `apps/api/src/middleware/perk.ts`：

- `requirePerk(code)` —— 服务端拦得住的那类（题库、题解、额度）直接挂在路由上
- `canUse / perkOf / quotaOf` —— **同一份判定**，前台也用它，不是各算各的
- 判定依据只此一处：`plans.routes.ts` 的 `loadPerks()`

**有一类功能服务端拦不住**：3D 图谱的数据来自公开的知识树接口，服务端给不出
"这一份数据只给会员"的切法。这种只能在前台按权益决定渲不渲染。
所以代码里明确分成两条路，而不是含糊地都丢给前台。

### 数字归数字、文案归文案

错题本容量那格写的是「50 道」。**没有**去把这个字符串里的 50 抠出来当数字 ——
那等于"改文案就是改行为"：运营把"50 道"写成"五十道"，判定就悄悄失效，
而且没人会想到是文案改坏的。

所以 `PlanService` 加了 `quota Int?`（null = 不限）：`quota` 是服务端执行的那个数，
`value` 是给人看的那句话。后台矩阵里也**只有「错题本容量」这一项才出现"上限"输入框** ——
不给任何"填了也没用"的输入框，那是最糟的控件。

### 挂在哪几处

| 服务项目 | 落在哪 | 谁拦 |
| --- | --- | --- |
| `question_bank` | 三个 `/practice/*` 接口 | 服务端 |
| `member_solution` | 提交结果里的 `explanation`（不给就**根本不发出去**，不是前端藏） | 服务端 |
| `mistake_capacity` | 归档时按剩余额度截断，并把丢了几道数出来回给前台 | 服务端 |
| `priority_support` | 论坛列表排序（会员提问靠前）—— **只调顺序、不藏别人** | 服务端 |
| `tutorial_3d` | 3D 图谱页渲染前先问一次权益 | 前台（数据是公开的，服务端拦不住） |

`study_report` / `offline_pack` / `cloud_sync` 三项先留着 —— 它们得先有对应功能才谈得上拦，
分别落在后面的模块里。**留着不等于忘了，是排在后面。**

### 实测

接口断言 **30 条全过**（一次性脚本，跑完已删），关键的几条：

- 免费版 `perks.mistake_capacity.quota === 50`；没有 `member_solution` 这一项
- **后台把「题库与做题」从免费版取消 → 学生立刻 403 `PERK_REQUIRED`**，
  而且响应里带 `perk` 字段告诉前台**缺的是哪一项**；恢复之后又能用
- **后台把错题本上限改成 2 → 归档 `archived: 0 / dropped: 2`**，错题条数一条没多
- 开通会员后：`member_solution` 出现、错题本 `quota === null`（不限）、提交练习 `hasSolution: true`
- **「答疑优先」：会员的帖子排在前面，而且一条都没少**

前端（真浏览器）：

- 免费版打开 `timeline-3d.html` → 画布不渲染，换成「三维交互图谱 · 会员专享」；
  **开通会员后刷新 → 画布 1628×1144 正常渲染**（门能开，不只是能挡）
- 免费版错题本页 → 「错题本已用 158 / 50 道，满了 —— 再做错的题不会再归档」
- 免费版做完一套题 → 每题给出"你答的 / 正确答案"，题解那一段是「会员专享」小锁；
  底部写着「错的 3 道里有 3 道没能进错题本」

### 一个差点写错的地方

体检脚本对 `timeline-3d.js` 做的是**字面匹配**（必须 `WK_API.boot(__wkTimeline3d)`）。
我一开始在启动处套了一层 `__wkStart3d`，两条检查立刻转红。
处理办法**不是放宽检查**，而是把入口本身改成那一层（原来的渲染函数改名 `__wkRender3d`）——
检查的两条意图（必须经 boot 拿到树、必须留同步兜底）继续成立，脚本一个字都不用动。

### 两个要如实说的现状

1. **62 道题里只有 4 道能判分，其中 1 道有题解。** 所以「会员专属题解」这一项现在
   基本看不到内容 —— 这是**内容缺口**，不是代码问题。等后台能录题解之后才填得满（落在模块 B/C）。
2. **演示学生的错题是 158 道，而免费版上限是 50** —— 已经超了。
   那是导入进来的历史数据（15 场考试那批），不受后来配的容量约束。
   前端如实写着"已用 158 / 50，满了"；这件事本身就是个很好的付费点演示。

新增 `GET /admin/orders` + 后台「订单」页。两个要点：

## 模块 H1：考试切片（后端）· 2026-10-07

学生把自己考完的卷子拍下来传上来 —— 这是**学情唯一真实的入口**（做题记录是系统自己造的，
只有卷子是外面真实发生的事）。所以按**独立新实体**做，不去蹭原来那 15 场导入的考试：
两者形状不一样，硬并会把两边都弄脏。

四张表：

| 表 | 一行是什么 |
| --- | --- |
| `exam_slice` | 一次考试（日期 / 科目 / 卷型 / 得分 / 满分 / 情况） |
| `exam_slice_image` | 一张卷子照片（相对路径 + 标签「正面 / 第 2 页」+ 字节数） |
| `exam_slice_box` | 框出来的一道错题（页码 / 题号 / **百分比坐标** / 挂的知识点 / 错因） |
| `exam_slice_node` | 这张切片覆盖的章节（双向真外键 + Cascade） |

两个设计决定：

1. **得分、满分都允许为空。** 有时候学生只想让你看错在哪，不想报分数。
   报告里**没填分数的不进平均 —— 不拿 0 顶替**（断言里那条
   `count 2 / withScore 1 / avgRate 0.82` 就是在钉这件事）。
2. 坐标用**百分比**，不用像素。换图、压缩、裁切都不用重算。

上传一条通道、三道关：

1. **看字节不看 Content-Type**（JPEG `FF D8 FF` / PNG 八字节魔数 / WebP `RIFF`+`WEBP`）
2. **文件名服务端生成**（`YYYY/MM/<18 位 hex>.<ext>`），客户端给的名字一律不采
3. 8MB 封顶

回给前端的 `url` 是 `/uploads/...` —— **挂在接口那台机器的根上**，生产由 Nginx 反代。
（这一条后来在模块 H2 咬了我一口，见下。）

### 实测（40 条断言全过）

- 谎报 `image/jpeg` 的纯文本文件 → 被魔数拦下
- 自己编一个图片路径去建档 → 拒绝（`absOf` 只认服务端生成的那种形状）
- 没填分数的那张不进平均：`count 2 / withScore 1 / avgRate 0.82`
- 删切片时**只删"没有任何切片再引用"的图**：另一张切片还在用的图留着

## 模块 H2：学生端「考试切片」页 · 2026-10-07

`exam-slices.html` + `assets/js/exam-slices-live.js`。左栏接学习中心侧栏，
正文三块：考情报告 / 我的切片 / 上传表单（默认收起）。另给 11 个页面补了侧栏入口。

1. **缩略图和卡片全裂了。** 我按 `API.base + url` 拼图地址，而 `API.base` 是 `…/api`，

   生产同域时摘完是空串，等价于原来的相对路径。

| 步骤 | 结果 |
| --- | --- |
| 空状态 | 「还没有切片…」+「共 0 张」 |

3. **章节搜索按"章名"匹配，不带教材前缀。** 输入「六年级上册 · 分数」搜不到，
   输入「分数除法」才行。占位符写的是「搜章节名」，所以不算错，但值得知道。

## 模块 H4：切片落进 3D 时间轴 · 2026-10-07

**只给会员**——但那不是这里判的，是页面本来就有的门槛）。

### 为什么要在这一层自己再走一遍知识树

`timeline-axis.js` 摊平出来的 `ALL[i]` **只留了名字、没把节点 id 带下来**
（它只服务"2D 与 3D 同一根轴"这一件事），而切片给的是后台的节点 id。
所以这里按同一套摊平规则又走了一遍 `MATH_TREE`（走出来的格数 769
正好等于 `AX.items.length`），把"知识点 id → 它在轴上占哪几格"记成 `NODE_SPAN`；
**章节要把它底下的格子整段算进来**（所以"分数的初步认识"占 140–144）。

### 两个把它做得像样一点的决定

1. **一段一块板。** 一次考试标了两章、而这两章在轴上离得远时（三年级与六年级），
   拿 min…max 画一整块会把中间那一大段**根本不属这次考试**的格子也罩进去 ——
   那是假的覆盖范围。所以按**连续段**分开画（S5 就是 140–144 与 323–327 两块）。
   `range` 仍留着给相机取景用（取景要一个整体跨度）。
2. **没标章节的那种，不编一个假跨度。** 只在它那天立一枚一格宽的窄标记，
   上面如实写"未标章节"（库里那两张正好把"标了"和"没标"两条路都覆盖到）。

### 一个必须改的坑：它不能跟时间条走

上面那 15 场是"只画已经考过的"（`day <= 时间条`）。照这条规则，**学生今天传的卷子看不见**：

- 这个时间轴的"今天"是演示数据冻结的 **2026-06-30**（`timeline-data.js` 的 `TODAY_AT`，
  服务端 `/me/learning` 回的 `today` 也是它）
- 而学生今天传的卷子日期是 **2026-10-07**

也就是说他刚传完、回到轴上什么也没有，看上去就是"功能没生效"。
所以这一层**不跟时间条走**，一直画；位置仍由它自己的日期定
（`zOf` 会把越过窗口的日期夹到轴尾，不会乱跑）。真正上线时学生的卷子都在"今天"之前，
这条规则和"只画考过的"结果一致 —— 是演示时间轴的冻结日期把这个坑暴露出来了。

### 命名

界面上这层叫「**我传的卷子**」，**不叫"切片"**。原因很实在：这个项目原来管那 15 场演示
考试也叫"考试切片"（右侧那颗开关、`state.exam` 那一套都叫切片）。同名就是灾难。

**`state.exam` / `examById` / `pickExam` / `COVERED` / `pinnedInfo` 一个都没动** ——
上传的卷子另走 `state.upload`，点它 = 钉住 + 聚焦 + 面板出详情，再点同一块 = 松开。
原有 15 场考试的行为零变化。

### 实测

### 三处如实说

1. **"点画布上的板子"这一步没能在浏览器里亲验。** 自动化那一层点不到画布上的命中区 ——
   我拿**已有的那 15 场考试的板子**做了对照（用 `xx()` 算出 E15 板子中心的屏幕坐标再点），
   同样没反应。也就是说这是**工具点不动 canvas 指针事件**，不是我这一层特有的毛病，
   也不是回归。代码路径（`hit()` 收 `upQuad` → `select()` 转 `pickUpload`）我逐行看过，
   右侧面板那条路是真的点通了。**但"鼠标点板子"这一条，这里只能说没验到。**
2. **"没登录就不画"那条分支同样没在浏览器里验成。** 试的时候发现：这一页本身就要
   `tutorial_3d` 权益，未登录根本进不来（页面直接出"会员专享 · 先登录"）。

## 模块 W1：后台「用户管理」· 2026-10-07

用户："先做用户管理模块。"在此之前后台用户页只有"看列表 + 改角色 + 停用"。这一轮把增删改查补齐。

### 接口

| 接口 | 干什么 |
| --- | --- |
| `GET /admin/users` | 加了 `q`（账号/昵称）、`role`、`status`、`page`/`pageSize` |
| `GET /admin/roles` | 角色字典（带各自人数） |
| `POST /admin/users` | 新建账号（**可指定角色** —— 后台建管理员走的就是这里） |
| `PATCH /admin/users/:id` | 原来只改角色/停用，现在也能改昵称/年级 |
| `POST /admin/users/:id/password` | 重置密码 |
| `DELETE /admin/users/:id` | 删账号 |

### 四条定死的规矩

1. **角色不写死成 enum。** 原来是 `z.enum(['admin','student'])`。角色是库里的一张表，
   写死就等于"以后加个角色得改代码，忘了改这里接口会**静默拒掉**"。改成任意 code，
   存不存在由库判定（`NO_ROLE`）。后台那个下拉也从 `/admin/roles` 取。
2. **分页有上限。** `pageSize` 夹在 1~100 —— 不夹的话 `pageSize=100000` 就是把整张用户表拉给浏览器。
3. **"状态筛选"要翻译。** 库里存的是 `disabledAt`，**没有** `status` 字段；
   `status=normal/disabled` 在服务端翻成 `disabledAt: null` / `{ not: null }`，不能拿去直接查一个不存在的字段。
4. **删账号两道护栏**：① 不能删自己；② **名下有已付款订单的不让删** ——
   删用户会 cascade 掉他的订单（`Order.user` 是 Cascade），而订单是账，回 `HAS_PAID_ORDER`，
   让人改用"停用"。**要停一个人，停用才是这件事的正解。**

### 一处语义修正：那条"不能改自己"原来是一刀切

它防的其实是"把自己锁在门外"（改角色 / 停用）。现在 `PATCH` 也能改昵称/年级了，
这两样不涉及"还能不能进来"，所以只在传了 `role`/`disabled` 时才拦 —— 自己改自己的昵称没问题。
前端那一行也跟着放开：自己那行的「改资料 / 重置密码」可点，「停用 / 删除」是灰的
（灰只是省一次白跑，真正管事的是服务端）。

### 实测

- **curl 断言全过**：分页（total=4 / page=1 / size=2 只回 2 条）、搜 `q=zhou` 命中 1、
  `role=admin` 命中 1、`status=disabled` 命中 0；新建 → 账号重复 400 `DUP_USERNAME`、
  弱密码 400、不存在的角色 400 `NO_ROLE`；改昵称/年级 200；
  **重置密码后新密码能登、旧密码 401**；删自己 409 `SELF`、删有已付款订单的 `student` 409 `HAS_PAID_ORDER`、
  删刚建的 200、再删 404；学生访问 403
- **真浏览器**：新建 → 列表 4→5 → 搜索命中 1 条 → 改资料（行内立刻变成"改名后 / 四年级（下）"）→
  重置密码（toast「已重置，他已下线」）→ 删除（确认框写明"不可恢复"，删完回 4 人）；
  自己那一行「停用/删除」确实是灰的
- `api:typecheck` 0 错；`ruby tools/checks/run_all.rb` **1452 条断言 / 0 失败 / 无红灯**

## 模块 S1：学生管理 · 学段 / 班级 / 老师 · 2026-10-07

用户："增加学生管理模块；比如小学 中学 高中 奥赛分开管理；各自的班级和管理老师。"
设计稿另有一份：`docs/superpowers/specs/2026-10-07-学生管理-design.md`（四期 S1~S4）。这一节记 S1。

### 一个必须先解决的事：分组靠 stage，不靠 grade

树上的 `book`/`track` 早就带 `stage`（primary 12 册 · junior 6 册 · senior 5 册 · olympiad 4 轨道），
**资料侧是齐的**；但 `User` 上只有一个自由文本 `grade`（`七年级（下）` / `高一 · 必修一`）——
拿它分组迟早出错："七年级（下）"和"初一"是同一个学段，字符串匹配认不出来。

所以 `User` 加 `stage`（与 `Node.stage` **同一套取值**），并**从 grade 回填一次**：
一~六年级→primary、七~九年级→junior、高一/必修*→senior、竞赛→olympiad，
**推不出来的留空**，在后台单列「未分学段」等人来指。`grade` 保留显示，但不再承担分组职责。

### 班级：一个学生一个班

新建 `Class`（name / stage / grade / teacherId / note / order / active），`User.classId` 一个字段。

- **不建中间表**：真实里学生就在一个教学班；允许跨班的话，花名册/平均分/进度每个数
  都要先问"算哪个班的"，那点灵活性换不来这份复杂度。
- `teacherId` **指向 User**，不另建"老师表" —— 老师就是能登录的教师账号。
- `User.class` 是 **onDelete: SetNull**：**删班不该把学生一起删掉**。
- **调学生进班时，学生的 stage 跟着班的 stage 走**（改学段同理）。分栏是按班分的，
  一个人在小班却标着初中，"按学段统计"当场就是错的。这条同步是刻意的。

### 老师：能登录，但只看自己带的班

新角色 `teacher`（`content.read` + `class.read` + `student.read`）。两条护栏：

1. **数据范围在服务端** —— `classScopeOf(user)` 返回允许的 classId 列表（admin 为 `null` = 不受限），
   `/admin/classes` 按它过滤，`/admin/classes/:id` 越界回 **404 而不是 403**。
   （403 等于告诉对方"这个 id 存在，只是不给你看"，那本身就是个班级探测器。）
2. **`class.write` 只给 admin** —— 老师要是能建班，就能把自己塞进任何班，"只看自己班"立刻成空话。
   所以"能不能改"走权限点、"能看多宽"走数据范围，是两件事。

### 接口

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `GET /admin/stages` | class.read | 四学段 + 各自班级数/学生数 + 未分学段人数 |
| `GET /admin/classes?stage=&q=` | class.read | 列表（老师只回自己带的） |
| `POST/PATCH/DELETE /admin/classes[/:id]` | class.write | 建/改/删；只收 teacher/admin 当班主任 |
| `GET /admin/classes/:id` | class.read | 详情 + 名单 |
| `POST /admin/classes/:id/students` | class.write | 批量调人进班（只收 student 角色） |
| `DELETE /admin/classes/:id/students/:userId` | class.write | 移出（只动真在这个班里的那一个） |

顺带把 `stage` / `className` 加进了 `GET /admin/users` 的行里（原来后台看不到学段）。

### 实测

- **curl**：建班（带班主任）200；拿学生当班主任 → 400 `BAD_TEACHER`；调人进班 → 学生 stage 跟着变；
  班级详情回名单；**老师只看到自己那 1 个班**（小学那栏 0）；**老师访问不带的班 → 404**；
  **老师建班 → 403**；用户列表带出 stage/className
- **真浏览器**：后台「班级」页四栏计数正确（小学 1 班/1 人 · 初中 1 班/1 人）；
  换成王老师登录后 **菜单只剩「概览/知识结构/班级」**，班级页**只列他自己带的班**（小学那栏显示 0 班），
  没有「建班/改/删」按钮，名单抽屉里**没有选择器也没有「移出」**，并写明"名单只读"

## 模块 S2：学生管理 · 统计接口 + 演示练习数据 · 2026-10-07

接着 S1。这一期只做**后端与数据**，界面留给 S3。

### 三条接口

| 接口 | 权限 | 给什么 |
| --- | --- | --- |
| `GET /admin/stats/overview?stage=&classId=` | class.read | 一组人的汇总：人数 / 已学格数 / 平均掌握度 / 考试场次 / 平均得分率 / 错题数 / 习题量 |
| `GET /admin/classes/:id/roster` | class.read | 花名册：**每人一行**核心指标 + 班级汇总 |
| `GET /admin/students/:id/growth?granularity=week\|month&from=&to=` | student.read | 成长曲线 / 学习曲线 / 成绩曲线 / 习题量 / 薄弱章，一次给齐 |

算法全在 `class-stats.service.ts` 里，路由只管"谁有资格看什么"。
老师范围内的人由 `visibleUserIds()` 出，越界一律 **404**（与 S1 同一条规矩）。

### 五块数据怎么算的

**成长曲线** —— 把事件按时间扫一遍，维护"每一格当前的掌握度"，
每个桶结束时算一次**所有已触及格子的平均掌握度**（累计口径）。
不用"这个桶里事件的平均"：那是"这周新学的东西学得怎么样"，不是"这个人的水平到哪了"。

**学习曲线** —— `done`＝到那一刻为止有 `first` 事件的格数；`plan`＝`plannedAt` 已到的格数。
      两条线一张图，"跟不跟得上计划"一眼看出来。

**成绩曲线** —— 每场考试的`得分率`；**满分是 0 的场次不进平均**（那是脏数据，不是 0 分）。

**习题量** —— `PracticeSession.total/correct` 求和。

**薄弱章** —— 错题本 + 切片里框出的错题，都归到**章**上按合计排序。
      归到章而不是知识点：一个人可能有几十个薄弱知识点，摆在报告里没法看，
      而老师要的是"这一章得再讲一遍"。节点表整张读进内存往上走祖先，比逐个查快得多。

### 一条贯穿全文件的规矩：「没有数据」与「数据是 0」

一次都没练过 → `accuracy: null`（前端显示"暂无练习数据"），**不是 0%**；
一场考试都没有 → `avgRate: null`，**不是 0**。实测：周雨桐 `考试 0 / 均分率 null`。
这和切片报告"不拿 0 顶替"是同一条。

### 演示练习数据（**这是造的，要知道**）

新增 `seed/practice-sessions.json` + `apps/api/src/seed/practice-sessions.ts`（`npm run db:seed:practice`）。
给三位演示学生各造 **20 次练习会话**（共 60 次 / 187 道答案），铺在近 90 天里，确定性伪随机生成（可复现）。

- **为什么造**：全站只有 4 道可判分题、0 次练习会话，习题量恒为 0 ——
  0 对 0 永远相等，连接口算得对不对都验不了。
- **只从 p1~p4 抽题**：58 道白板题（kind=board）没有答案、判不了分，
  给它们编一个 `correct` 就是在编一件系统自己说做不到的事。
- **幂等**：导入前先清掉这几位演示学生已有的会话（范围只到文件里列的账号，别的一行不碰）。

### 一个先写错了的默认值

`growth` 一开始默认取"近 180 天"，结果成长曲线是一条**平线**（avg 一直是 67）。

## 模块 E1：后台可查看可编辑学生数据 · 地基与留痕 · 2026-10-07

用户 2026-10-07："明确一下 学生端和教师端的所有的报告和数据要在管理后台里都可以查看和编辑。"
设计稿另有一份：`docs/superpowers/specs/2026-10-07-学生数据后台可查看可编辑-design.md`（分 E1~E4）。这一节记 E1。

### 这条要求推翻了什么

`UserDetail.vue` 里当初明写"这一页**只读**，改数据走各自那一处"，理由是"再开一个入口，两边迟早对不上"。
现在反过来 —— 但**当初担心的不是"多一个入口"，是"多一个没人记得的入口"**。
所以 E1 做的不是编辑功能，是**留痕**：编辑功能要等 E2/E3，而留痕必须先立住。

### 三张表 / 一个权限点

- 新模型 `DataChange`：`batchId`（同一次保存共用）+ 谁改的 + 改的是谁的 + 实体/实体 id + 给人看的 label +
  字段 + 旧值 → 新值 + 原因 + 时间。
- 新权限点 **`student.write`**，给 **admin 与 teacher**。
  teacher 拿到它不等于能乱改：数据范围仍由 `classScopeOf` / `visibleUserIds` 卡到"自己班"，越界 404。
  这与"class.write 只给 admin"不矛盾 —— **建班是管理动作，改学生学业数据是教学动作**。

两处 `onDelete` 是刻意选的：

| 字段 | 取值 | 为什么 |
| --- | --- | --- |
| `actor`（谁改的） | **Restrict** | 删了执行人，"谁改的"就成空白，而留痕的价值恰恰在那个人身上 —— 所以执行过改动的管理员账号**删不掉** |
| `target`（改的是谁） | Cascade | 学生被删时他的数据一起没了，留痕跟着走是一致的，不会留下指向空学生的孤儿记录 |

### `applyChange()`：把"改动"和"留痕"按一个事务提交

`apps/api/src/modules/classes/change-log.service.ts` 只有一条硬规矩：

> **任何时候都不许绕过 applyChange() 直接 prisma.update / delete 学生数据。**

因为留痕和改动在**同一个事务**里 —— 留痕写不进去，改动也一起回滚。
这样"忘了记一笔"在物理上就不可能发生，而不是靠纪律。

两个配套的小规矩：
- `diffOf()` **只留真的变了的字段**：照单全写会留下"掌握度 85 → 85"这种噪音，
  看变更记录的人得先学会忽略一半的行。
- 没有任何字段变化时 `applyChange` **直接抛错**，不静默放行 ——
  静默返回会让"我明明改了"和"其实没改"看起来一样。

### 实测（一次性脚本，跑完即删）

**基本行为**：没有改动 → 抛错 ✓；改一次 → 库里 85→86 ✓ 且留痕恰好 1 条（`mastery 85 → 86`，原因也在）✓；
改回来 → 库里回 85 ✓、历史 2 条按时间倒序 ✓。**测试留痕已清，那条记录的值也还原了。**

**回滚保证（这条最关键）**：给 `targetId` 一个不存在的人，让留痕那条**必然插不进去**（外键拦住），
而 `write` 本身是合法的 —— 如果它提交了，"同事务"就是一句空话。结果：
整体失败 ✓、**库里的值仍是 85（回滚生效）✓**、留痕表 0 条 ✓。

`ruby tools/checks/run_all.rb` **1452 条断言 / 0 失败 / 无红灯**；`api:typecheck` 0 错。

查看明细的 8 个接口：`/admin/students/:id/` 下的 learning · events · mistakes · exams ·
practice · slices · notes · favorites · changes。现在后台对这些基本只有"计数"。


## 模块 E2 / E3：后台查看明细 + 修正型编辑 · 2026-10-07

接着 E1 的留痕地基。

### E2：8 个"看明细"的接口

在这之前，后台对一个学生只有**计数**（错题 158、事件 1863…）和一张考试表；明细全在库里，就是没口子。

`apps/api/src/modules/classes/student-data.routes.ts`：
`/admin/students/:id/` 下的 **learning · events · mistakes · exams · practice · slices · notes · favorites · changes**。

两处细节：
- 每条明细都带**可读路径**（`六年级上册 / 圆 / 解决问题`）。路径靠整张节点表读进内存算一次 ——
  一页 100 条逐条往上查库才是真的慢。**头一个"数学知识网络"是根节点名、每一行都一样，去掉了**，
  不然表格里那一列白占宽度。
- `learning` 支持 `only=learned|marked`，`events` 支持 `kind=`，`mistakes` 支持 `status=`/`source=`。

老师范围复用 `visibleUserIds()`（E2 顺手把它从 classes.routes 里 export 出来 ——
**范围判定只该有一处**，多一个入口就多一种口径）。越界与"没这个人"回**同一句 404**。

### E3：修正型编辑（每一条都走 applyChange）

`apps/api/src/modules/classes/student-write.routes.ts`：
学习记录、错题、卷面题、考试、切片、笔记 —— 能改；学习记录/错题/笔记/切片/练习会话 —— 能删。

三道闸，每个接口都走：① `student.write` ② 这条记录属于谁 + 那个学生在不在"我能管的人"里 ③ `diffOf` 只留真变了的字段。

**写这个文件时抓到自己的一个错**：删除最初写成了"先记一笔留痕、再去删"——
这两件事不在一个事务里，中间断电就会出现"留痕说删了、其实还在"。
改成把**删除动作本身交给 applyChange 的 write**，才真的同事务。这正是 E1 那条硬规矩的意义。

顺带改的：`applyChange` 现在把 `batchId` 回给调用方（前端拿它在变更记录里归组）。

两条刻意的边界：
- **练习会话不可改**（PATCH 回 404"没有这个接口"）—— 那是"当时做了什么"的历史，改它就是伪造历史；
  只能整次删，删了可以重练。
- 改考试日期时，`at`（时间戳排序键）**跟着 date 一起改** —— 两处不一致的话，
  时间轴上的位置会和列表里的日期对不上。

### 实测

- **E2**：8 个接口全部出真数据（学习记录 769 · 事件 1863 · 错题 158 · 考试 15 · 练习 20 · 切片 2 · 笔记 6 · 收藏 12 · 变更 0），
  路径可读；老师看自己班学生 **200**、看不属于自己的学生 **404**、看不存在的学生 **404（同一句）**、学生访问 **403**
- **E3**：改掌握度 → `{ok, changed:["mastery"], batchId}` ✓；再写同一个值 → **400 `NO_CHANGE`** ✓；
  老师改**不属于自己班**的学生 → **404** ✓、改**自己班**的 → 200 且留痕里执行人记的是**王老师** ✓；
  删一次练习 → 200 且留痕有 `delete` 那条 ✓；**PATCH 练习会话 → 404（不可改）** ✓
- 变更记录里四条逐条可读：`管理员 | practice_session#112 | delete | 练习 #112（2 题） → null | E3 验证删除`
- **测试痕迹已清、被改的数据已还原**（掌握度回 51、错题状态回 fixed、练习会话重跑 seed 回 60 次）
- `api:typecheck` 0 错；`ruby tools/checks/run_all.rb` **1452 条断言 / 0 失败 / 无红灯**

## 题库扩容 · 2026-10-07

用户 2026-10-07："好的，按这个表从题库扩容开始继续执行"。

### 先说清楚"扩容"到底能扩什么

动手前先把全站素材数了一遍：

| 来源 | 数量 | 能不能判分 |
| --- | --- | --- |
| `practice.html` 那四道（`p1`…`p4`，choice / blank） | **4** | 能（有正确答案） |
| 白板题库（`whiteboard-problems.js`，`kind=board`） | **58** | **不能**（只有题面，没有答案） |
| 真题库 `ExamQuestion` | 3（其中 2 道带答案） | 部分 |

**结论：这个项目里根本不存在"一大批真题 + 答案"。** 所以没有现成素材可以搬进题库 ——
所谓扩容只有一条诚实的路：**把 58 道白板题放进练习**。它们的题面是真题面（`−7 + 3`、
`3(x − 1) + 2(x + 4)`、`求抛物线 y = x² − 2x − 3 的顶点` 这种），学生能在纸上真做完。

**不自己编题面、也不编答案。** 编答案更糟：那等于让系统假装自己判得了一道它其实判不了的题。

### 于是把"做了几道"和"判对几道"拆开

这是这一期唯一的模型改动 —— `PracticeSession` 多一列：

```
total   Int    // 这次真做了几道（含白板题）
correct Int?   // 判对了几道
judged  Int?   // ★ 新增：其中**判得了分**的有几道
```

**正确率的分母从此是 `judged`，不是 `total`。** 原来那句 `correct / total` 在放进白板题之后
会变成"把判不了的题全判成错的"—— 那是让学生背一件系统自己说做不到的事。

`PracticeAnswer.correct` 本来就是 `Boolean?`，所以白板题的答案是 `null`，不用改表。

### 后端（`modules/practice/practice.routes.ts`）

- **取题**：池子从 `kind in (choice, blank)` 放开成全部。抽法是**可判分的先全给**
  （判分与正确率是这一支的主业，而全库只有 4 道），**剩下的位子用白板题补足**。
  白板题**洗牌**取 —— 不然每次都固定拿最前面那 16 道，后 42 道等于没进题库。
- **提交**：`judged = 判得了分 && 有答案`；白板题 `correct: null`，**不判错**。
- **跳过的白板题整条撤掉**（`deleteMany`），`total` 跟着缩 ——
  不这么做的话，点开就跳过也能把"习题量"刷上去。
- **错题本只收 `correct === false` 的**（`null` 既不算错也不归档）。
- 响应加 `judged`；`score` 改成 `number | null`（一道都判不了分时是 `null`，不是 0）。
- 顺带把 `/practice/questions` 也放开（它原来只列可判分的题，与"题库"这个名字不符）。

**下游三处口径一起改**（同一件事不能有两套算法）：

- `class-stats.service.ts`：`practice.accuracy = correct / judged`；`PracticeStat` 加 `judged`
- `student-data.routes.ts`：后台「练习」明细的 `score` 也按 `judged` 算，并透出 `judged`
- `seed/practice-sessions.ts`：演示数据只从 `p1`…`p4` 抽，所以写 `judged = total`

### 学生端（`assets/js/practice-live.js`）

### 问题长什么样


### 新文件：`modules/uploads/sweep.service.ts`

只干一件事：**盘上没有任何切片引用的图，扫出来删掉。** 四条不能破的规矩写在文件头上：

1. **只认我们自己生成的形状**（`YYYY/MM/<18 位十六进制>.jpg|png|webp`）。
   删文件比"拒收一个入参路径"危险得多 —— 认不出来的一律不碰。
   这条比 `storage.service` 的 `absOf` **更严**：那里判的是"接不接受这个入参"，
   这里判的是"能不能从盘上删掉"，两者该严的程度不一样。
2. **给足宽限期**（默认 24 小时）。**库里没有引用 ≠ 没人要**：学生正开着表单、
   图传上去了还没点提交，这一刻它就是个"孤儿" —— 这时候删掉等于把人刚传的弄丢。
3. **先查库、再读目录**。顺序反过来的话，两次之间新提交的切片会被当成孤儿删掉
   （它的行还没进库）。引用集一次读全，不做逐文件查询。
4. **删不掉不算失败**：库里没变、盘上留一个文件，比整个任务崩掉好，下一轮还会扫到它。

### 怎么跑

| 场景 | 命令 |
| --- | --- |
| 定期（默认） | API 进程里自带一个定时器：每 360 分钟一次，启动后 1 分钟跑第一次 |
| 关掉 | `UPLOAD_SWEEP_MINUTES=0` |
| 手动看 | `npm run uploads:sweep`（**默认只看不删**） |
| 手动删 | `npm run uploads:sweep -- --apply` |

两个旋钮进了 `config.ts`（`UPLOAD_SWEEP_MINUTES` / `UPLOAD_SWEEP_MIN_AGE_HOURS`），
`.env.example` 与 `deploy/.env.production.example` 都补了说明。

**放在 web 进程里而不是 cron**：部署只有一个容器（见 `deploy/`），
而这件事只是扫一个目录 + 一次库查询，够不上另开一个进程的量级；
定时器 `unref()`，不替进程"续命"。手动那条路默认 dry-run ——
第一次跑、或者换机器之后，应该先看清它打算删什么，再决定动不动手。

## 补 prisma migrate 迁移体系 · 2026-10-07

### 为什么必须补

到这一轮为止，**改表只有一条路：`prisma db push`**（作用在从主 schema 生成的 SQLite 那份上）。
`db push` 对"空库、随便推"没问题，但对**有数据的线上库**是危险的：
它按"schema 现在长什么样"去对齐，没有历史、没有回放、也不知道每一步改了什么。
`package.json` 里那条 `db:migrate` 一直挂着，但 `prisma/migrations/` **根本不存在**。

### 这台机器上做不到的事，先说清楚

`prisma migrate dev` 要**一台连得上 MySQL 的机器**（它还要建一个影子库把已有迁移重放一遍）。
这台开发机上：**没有 mysql、没有 docker、没有 podman** —— 一条都跑不了。

所以基线换了个生成办法：`prisma migrate diff --from-empty --to-schema-datamodel`。
**它不连数据库**，比的是"空库"和"schema 文件"两个静态物。生成的仍然是逐字的 MySQL DDL。

```bash
npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script
```

### 交付了什么

| 东西 | 说明 |
| --- | --- |
| `prisma/migrations/20261007230502_init/migration.sql` | **基线**：39 张表 / 46 个外键 / 752 行 MySQL DDL，从空库建全 |
| `prisma/migrations/migration_lock.toml` | `provider = "mysql"` |
| `prisma/migrations/README.md` | **两条路怎么分工**、改表四步、本机没有 MySQL 这条约束、"已有库怎么接上迁移" |
| `tools/check-migrations.mjs` | 迁移体检：**表级对账**，不连数据库 |
| `db:migrate:deploy` / `db:migrate:status` / `db:migrate:check` | 接口层 + 根目录各一套（根目录没有 `db:migrate`：它要 `--name`，参数会被外层 npm 吃掉） |
| `apps/api/Dockerfile` 的 CMD | 改成 `npx prisma migrate deploy && exec node dist/main.js` |

**两条路的分工**（写进了那份 README，这是这一轮最要紧的一条）：

| | 本地开发 | 生产 |
| --- | --- | --- |
| 库 | SQLite | MySQL 8 |
| 改表 | `db:dev` → `db push`（**不走迁移**） | `migrate deploy`（读 `migrations/`） |

所以 `db:dev` 跑得通**不代表迁移是对的** —— 两边由 `db:migrate:check` 对账。

### 体检脚本查什么（以及它查不了什么）

不连库，只比 **`schema.prisma` 里的表 ↔ `migrations/` 里建/删过的表**：

- 锁文件在不在、provider 是不是 mysql
- 迁移目录名是不是 `\d{14}_小写名`（**顺序靠它**）
- schema 里每个 model 的表名都在迁移里建过 ← **"改了 schema 忘了写迁移"就是这一步抓的**
- 迁移里没有 schema 认不出来的多余表

**查不了的**：列 / 索引 / 外键 / 默认值的**逐字**差异 —— 那一步要 `--from-migrations`，
而它需要影子库。脚本自己在末尾把这句话打出来，**不让人误以为全绿就是全都对**。

### 实测

```
✓ migration_lock.toml：provider = mysql
✓ 迁移目录 1 个，命名与顺序可用
   20261007230502_init
✓ schema 的 39 张表都在迁移里建过
✓ 迁移里没有 schema 认不出来的多余表

== 迁移体检：通过 ==
```

**体检本身也得被检查一遍**（一个从不报错的体检等于没有）——
故意造两处漂移：schema 里加一个 `model FakeDrift`、迁移里加一张 `ghost_table`：


## 断网时学生端读缓存 · 手工验收 · 2026-10-07

### 怎么把"断网"造出来（可复现）

不用拔网线、也不用停服务：**把 API 那个进程冻住**（`kill -STOP <pid>`），
它的监听套接字还在，但不会回话 —— 请求一直挂着，8 秒后撞上 `api.js` 自己的
`AbortController` 超时。这正是"网挂着不动"那种最坏情况，而且**完全可逆**（`kill -CONT`）。

```
$ kill -STOP 24511        # 冻住听 3000 的那个 node
$ curl -m 2 http://localhost:3000/api/health ; echo $?
28                        # 28 = 超时（挂住），正是要的
```

**一条读数上的坑，先说清**：`WK_TREE_META.from === 'cache'` **不能单独当"走了缓存"的凭据** ——
在线时带了 `?version=` 而服务端回 **304**，`from` 也是 `'cache'`（那是另一条设计好的路）。
真正的凭据是 **`api.js` 那条 warn**（`退缓存时留一条日志`，见文件头注释）+ curl 打不通。

### 验通的四条

| 页面 | 结果 |
| --- | --- |
| `reader.html` | 树从缓存来（`09121738599f`，84785 字节，与在线一字不差）；正文照旧（`6 册 · 29 章 / 1.2 有理数 / 知识点 2 数轴 …`）、`MATH_TREE.children = 27`；**没有兜底页** |
| `graph.html` | 树从缓存来、**图谱画出 71 个节点**（`#mm-world > *`）、没有兜底页 |
| `timeline.html` | 树从缓存来、`WK_AXIS` 起来了、2 块画布、没有兜底页 |
| 空缓存 + 断网 | 换一个**没缓存的源**（`127.0.0.1:5173`）→ 出兜底页：`连不上服务器，这台设备上也没有缓存` + `…/api/tree：signal is aborted without reason` + **重试按钮**。**不是白屏**。 |

控制台里两条 warn 都按设计出现了：

```
[warn] [WK_API] 接口没拉通，用本地缓存（09121738599f）： AbortError: signal is aborted without reason
[warn] [WK_API] 学习数据没取到，界面用本机演示规则： AbortError: signal is aborted without reason
```

**恢复也验了**：`kill -CONT` 之后点兜底页那颗「重试」→ 页面正常回来
（`from: 'network'`、正文在、`林一鸣` 也回来了）。

### 没通过的一条：三维那一页，断网时不渲染，而且给的理由是错的

`timeline-3d.html` 断网时：树**确实**从缓存来了、没有兜底页，
**但 3D 起不来**（`window.WK_TIMELINE_3D` 没有、画布 0 块）。
同一台浏览器、同一个页面，**在线**时 `WK_TIMELINE_3D` 在、画布 1 块 —— 所以不是环境不支持。

顺着代码找到了原因，在 `timeline-3d.js` 末尾：

```js
function __wkTimeline3d() {
  var ENT = window.WK_ENT;
  if (!ENT) { __wkRender3d(); return; }
  ENT.ready().then(function () {
    if (ENT.has('tutorial_3d')) { __wkRender3d(); return; }
    … ENT.paintGate('tutorial_3d', host, '当前方案里没有这一项 —— 开通之后这一页直接变成 3D。');
  });
}
```

而 `entitlement.js` 的 `load()` **失败时把 `ent` 判成 `null`**（`state.ent = null`），
`has()` 于是恒为 false。**它没有缓存**（`api.js` 有，它没有）。

结果就是：**一个明明有权益的会员，断网打开这一页，看到的是"当前方案里没有这一项"** ——
把"问不到"说成了"没有"。同理，`practice.html` 上「题解」那一块
（`member_solution`）断网时也会被锁上。

### 没通过的第二条：断网时身份丢了，连带自己那份学习数据缓存也被丢掉

- `/me` 拉不到 → `AUTH.ready()` **把"连不上"和"401"当同一件事**（这是它文件头写明的取舍：
  "连不上时更不能凭旧镜像就当成已登录"）→ 侧栏从 `林一鸣` 变成 `登录`。
- 跟着 `learning()` 里那句 `if (cached && (cached.who || '') !== who) { cached = null; }`
  就生效了：缓存里的 `who` 是 `student`，这次问出来的是 `''` → **判成"换了人"，整份缓存作废** →
  `WK_LEARN_DATA = null` → 视图退回**本机按老规则生成的那一份**（`timeline-data.js` 里的兜底）。
- 表现：**页面不空，但数字不是你的那份**。这条当初防的是"共享设备上别把上一个人的数据显示出来"，
  代价是**一次网络抖动就把自己的缓存也判掉**。

（侧栏那个镜像 `wkmath.user` 还在，所以名字其实还写得出来 —— 但那是显示缓存，
当初明确不许拿它当身份判据，这里没动它。）

### 一条体验上的账：离线首屏慢得明显

离线时每条请求都要等满超时，而 `boot()` 串了几条：树(8s) → `/me`(12s) → 学习数据(8s)，
最坏 ~28 秒。所以 `graph.html` 在 **19 秒时画布还是空的、34 秒才画出来** ——
第一轮我按 19 秒读数，差点把"慢"记成"坏了"。**以后验这类要等够 40 秒以上。**

### 结论

- **"不许白屏"这条守住了**：四张读树的页面断网都能出内容（三维那页出的不是 3D，见上），
  缓存也没有的时候出的是兜底页而不是空白。
- **两条要修**（都是"降级姿势不对"，不是崩溃）：
  ① `entitlement.js` 没有缓存 → 断网时把"问不到"当成"没有"，反向锁住已付费的东西；
  ② `learning()` 那条链把"连不上"当成"换了人"，把自己的缓存也判掉了。
- 这两条**当天就修了**，见下一节。

### 修完之后（同日）

| 改哪 | 怎么改 |
| --- | --- |
| `auth-client.js` | 把**"服务端说没登录"（401）**和**"根本没答上"（连不上 / 超时）**分开：只有 401 才 `clearShell()`（那是真的退登，擦镜像 + 擦学习缓存）；连不上时**什么都不擦**。顺带把 `reachable()` 挂出去，让上层分得出这两种情况。 |

## 推送：两天推不上去的那个错，今天解决了 · 2026-10-07

### 症状

从 2026-10-05 起 `git push` 一直失败，日志里只留了一句"推不上去"。今天把原文抓全了：

```
error: RPC failed; HTTP 400 curl 22 The requested URL returned error: 400
send-pack: unexpected disconnect while reading sideband packet
fatal: the remote end hung up unexpectedly
Everything up-to-date                     ← 这句是误导，其实一个提交都没上去
```

### 排查（逐条排掉）

| 怀疑 | 结论 |
| --- | --- |
| 推的东西太大 | **不是**。19 笔里最大的对象 2.7MB（`seed/learning-students.json`），没有 >10MB 的 |
| 中间有代理 | **不是**。`http.proxy` 空、系统代理空白（只有一个 `ICUBE_PROXY_HOST` 环境变量，与 git 无关） |
| 认证失效 | **不是**。`git ls-remote` 正常；而且认证错会回 401/403，不会回 400 |
| 远端仓库有问题 | **不是**。远端 `main` 停在 `4ba3438`，是正常的祖先 |

### 修法（两条一起上）

```bash
git repack -ad                                    # 本机 1599 个松散对象 → 打成 3.35MB 一个包
git -c http.postBuffer=524288000 -c http.version=HTTP/1.1 push origin main
```

结果：

```
To https://github.com/shanjipengdatachina-lab/WUKONG-MATH-SYSTEM.git
   4ba3438..8054820  main -> main
```

`git push origin v1.7` 也成了（远端标签现在到 `v1.7` → `b505008`）。

**哪一半起作用没拆开验**：只加 `http.version=HTTP/1.1`（不 repack）**仍然 400**，
所以 repack 那一半至少是必需的；但推上去之后不再重试去分离变量了 ——
**下次再遇到这个错，两条一起用。**

（`-c` 是这一次命令的临时覆盖，没动用户级 git 配置。）

### 后端仓库还推不了（如实记）

`WUKONG-MATH-SERVER` **没有配远端** —— `git remote -v` 是空的。
这不是漏了，是 10-05 就定下的（见本文档「M0 · Task 0.2」：*"远端等你们在 GitHub 建好再配"*）。

这台机器上也没有能建 GitHub 仓库的工具：**没有 `gh` CLI**，
可用的连接器只有 **Gitee**（`mcp_plugin_Gitee_gitee_create_repo`）—— 跟学生端不在同一个地方。

所以后端要推，只差一步：**在 GitHub 上建好仓库**（`shanjipengdatachina-lab/WUKONG-MATH-SERVER`），
然后把下面三条跑一遍即可（本机 12 笔提交已经备好，工作区干净）：

```bash
cd ~/Desktop/WUKONG-MATH-SERVER
git remote add origin git@github.com:shanjipengdatachina-lab/WUKONG-MATH-SERVER.git
git push -u origin master
```

（用 HTTPS 的话把第一条换成 `https://github.com/…`；真推的时候同样带上上面那套 repack + postBuffer 的参数。）
