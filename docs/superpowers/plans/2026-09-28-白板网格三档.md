## 关键实现点

### 1. 梯子与状态

```js
var GRID_SIZES = [
  { value: 20, label: '小' },
  { value: 40, label: '中' },
  { value: 80, label: '大' }
];
var DEFAULT_GRID_SIZE = 40;
```

放在 `ERASERS` 之后（同一类东西排在一起）。`state.gridSize = DEFAULT_GRID_SIZE`。

### 2. drawGrid：只换基数

```js
var step = state.gridSize || DEFAULT_GRID_SIZE;
while (step * v.scale < 14) step *= 2;
while (step * v.scale > 96) step /= 2;
```

**两条修正不动。** 换基数就能让三档在一百%下是 20 / 40 / 80 像素。

### 3. setGridSize

```js
function setGridSize(value) {
  var v = parseFloat(value);
  var hit = null;
  GRID_SIZES.forEach(function (g) { if (Math.abs(g.value - v) < 0.01) hit = g; });
  if (!hit) return false;               // 不在梯子里就不认
  state.gridSize = hit.value;
  if (!state.grid) state.grid = true;   // 决定 #4：顺手打开
  redraw();
  persist();
  syncUI();
  toast('网格 · ' + hit.label + '（' + hit.value + '）');
  return true;
}
```

注意 `toast` 只在"顺手打开"时才有意义；关着的时候说一句，开着的时候也刷新一下当前档。
（简单起见一律 toast，信息量一致，不做两套。）

### 4. buildPickers：三档按钮

预览方块用两条 repeating 渐变画格子；疏密方向必须是"数值越小格子越密"：

```js
var gridBox = byId('wb-grids');
if (gridBox) {
  gridBox.innerHTML = GRID_SIZES.map(function (g) {
    return '<button type="button" class="wb-grid" data-wb-grid="' + g.value + '"' +
      ' data-wb-tip="网格 · ' + esc(g.label) + '" aria-label="网格疏密' + esc(g.label) + '"' +
      ' aria-pressed="false"><span class="wb-grid__chip"></span>' + esc(g.label) + '</button>';
  }).join('');
}
```

### 5. 委托点击

与 `#wb-themes` 同一写法，绑在 `#wb-grids` 容器上，命中 `[data-wb-grid]` 才处理。

### 6. syncUI

```js
var gridBox2 = byId('wb-grids');
if (gridBox2 && gridBox2.querySelectorAll) {
  Array.prototype.forEach.call(gridBox2.querySelectorAll('[data-wb-grid]'), function (b) {
    press(b, Math.abs(parseFloat(b.getAttribute('data-wb-grid')) - state.gridSize) < 0.01);
  });
}
```

工具条网格按钮的气泡也要跟上当前档：

```js
var gridBtn = byId('wb-grid');
if (gridBtn && gridBtn.setAttribute) {
  gridBtn.setAttribute('data-wb-tip', '网格 · ' + shortOfGridSize() + ' G');
}
```

### 7. 落盘与恢复

- `persist()` 里 `gridSize: state.gridSize`
- `restore()` 里：

```js
if (typeof d.gridSize === 'number' && GRID_SIZES.some(function (g) { return Math.abs(g.value - d.gridSize) < 0.01; })) {
  state.gridSize = d.gridSize;    // 不在梯子里就保持默认 40
}
```

## 执行记录

### 2026-09-28 · 完成

`GRID_SIZES` 梯子（20/40/80）+ `state.gridSize`（默认 40）+ `drawGrid()` 只换基数 + 设置浮层里多一行
「网格」三按钮（带疏密预览方块）+ 落盘与容错 + 工具条网格按钮的气泡跟上当前档。
断言 730 → **748** 条，全量 0 失败。

**两处执行时才发现的、计划里没写对的东西：**

1. **量出来的间距是世界单位，不是屏幕像素**。桩记录的是 `moveTo / lineTo` 的原始参数，
   而真实画布上世界坐标要经过 `setTransform` 的 scale 才是屏幕像素。第一版断言直接把
   相邻两条线的坐标差当成像素，结果在 100% 下侥幸全过（scale = 1，两者恰好相等），
   一跑整条缩放范围就炸出 `20@0.15x=160`。改成乘一次 scale 才对。
   —— 这也说明"量画出来的东西"这条规矩本身要立得住：量错了坐标，断言就成了摆设。
2. **"坏值回落 40"这条写的不是实际契约**。`restore()` 的语义是"只覆盖认识的字段"，
   不认识的值一律**不采纳**（主题就是这样）。所以准确的说法是：启动时 `state.gridSize`
   本来就是默认 40，坏值不采纳就等于保持 40；而契约应该写成"恢复之后疏密必然落在梯子里"。
   计划里那句"回落 40"改成了这个说法，断言也照着真实契约写（外加一条 `setGridSize(55) === false`）。

**证明过它能红（两次）：**

- 把 `drawGrid()` 里的基数改回写死的 `40`：正好 3 条 FAIL，数字有意义 ——
  `小档 20px（实际 40）`、`大档 80px（实际 40）`、`疏密方向对`。中档那条仍然通过（40 = 40），
  这恰好说明"中档就是原来那一档"是真的。
- 把"顺手打开网格"那句关掉：正好 1 条 FAIL `网格关着时选一档 → 顺手把网格打开（实际 false）`。

**真机验证（读画布像素 + 量面板几何）：**

| 档 | 一百%缩放下实测的格子间距（读画布像素） |
| --- | --- |
| 小 20 | **20.00 px** |
| 中 40 | **40.00 px** |
| 大 80 | **80.00 px** |

同一时刻浮层里三个按钮的文字与选中态是 `20:小 / 40:中 / 80:大(选中)`，工具条网格按钮的气泡
跟到了「网格 · 大 G」。

面板几何：窗口 654px 高时，面板高 **281px**、顶端距视口顶 **307px**、下方留 66px（`bottom:74px`）。
也就是说这块面板需要约 **355px** 的可视高度；654px 下余量充足。为了在极矮的窗口里不把顶上
一截切掉，补了一条兜底：`.wb-pop{max-height:calc(100vh - 100px);overflow-y:auto}` ——
654px 下这条不生效（281 < 554），只在放不下时自己滚。

**结论：** `wb-check` +18 条断言，全量 **748 条 / 失败 0 条**；`verify_whiteboard.rb` 另加了
四条守线（三档齐、数值与 js 梯子一致、预览方块疏密方向不能写反、样式不许进共享区、面板要有兜底滚动）。
其中"疏密方向"那条也证明过能红：把 20 那一档的 `background-size` 从 4px 改成 9px，
体检立刻报 `✗ 网格预览方块的疏密写反了（应 20 最密 → 80 最疏，实际 9.0 / 6.0 / 9.0px）`。
