### 真机抓出来的两个真问题（都不是断言能发现的）

**一、`data-theme` 被运行环境抢走了。**

现象：设置页选「暗色」，`localStorage` 是 dark、内存状态是 dark、白板画布也是黑板（`rgb(15,23,42)`），
**只有 `<html>` 上的 `data-theme` 是 light** —— 于是整页还是亮的。

定位过程（记下来，下次少走弯路）：
1. 三个脚本候选（shell / ide-shell / pages）全 grep 过：没有任何一处写 `data-theme`/`dataset.theme`；
2. 换 `whiteboard.html`（它的标签上**本来就没有** `data-theme`）—— 属性照样是 light，说明不是"标记里那个值把我们的覆盖回去了"；
3. 决定性一步：打开一个**裸文件页**（`assets/js/display.js` 这种没有任何我们代码的页面）——
   它的 `<html>` 上同样挂着 `data-theme="light"`。**结论：写它的是环境，不是我们的代码。**

修法：我们的读写搬进**自己的名字空间** `data-wk-theme` / `data-wk-fs`，并加一条守线
「display.js 又用回通用的 data-theme 了」。`data-theme` 是全站通用的属性名（很多库与扩展都认），
谁先声明谁倒霉，不如不碰。页面标签上那个老 `data-theme="light"` 全站没有任何代码读它，保持原样。

**二、悬浮工具条写死 `rgba(255,255,255,.86)`，深色下是画布上一大块白板。**

白板与图谱底部那条工具条原来是半透明白。亮色下没问题，深色下就是一块发光的白板（截图里一眼可见）。
收进令牌 `--math-dock`（亮 / 中 / 暗各一份）。
顺手把"白底白字"这条守线从只认 `#fff` **扩到也认 `rgba(255,255,255,…)`** —— 原来的写法正是从这条缝里漏过去的。

### 反证过（三条，都点名到了具体位置）

- 暗色少写一个令牌 → `暗色缺 1 个颜色令牌：--math-ink-3（深色下会留着亮色，可能白底白字）`；
- 把亮色的灰字改回原来的 `#9ba1a9` → `亮色：--math-ink-3(#9ba1a9) 压在背景(#ffffff)上只有 2.60:1，低于 4.5:1`（正是跟用户讲的那个数）；
- 把某个预览色块改成白色 → `settings.html 里还有写死的 #fff：.disp-dot--mid`（守线是窄的，不是"凡是白都放过"）。

### 已知边界（没做的）

- **中色**只做了令牌对齐与对比度计算，没在真机逐页看观感（暗色是逐页看过的）；
- 深色下各页的 **hover / focus / 选中态**没有逐页走查，只走了主干；
- 不改 `zoom`、不改根字号（`rem` 间距不动）—— 这是刻意的，见 §3.2；
- 不做跟随系统配色（见 §2「刻意不做」）。
