## 关键实现点

### 1. 「往下排」的登记表

```js
function belowBlocks() {
  return [{ el: byId('wb-ink-text'), open: state.ink.open }];
}
```

`layoutOverlays()` 拆成 `layoutActs()` + `layoutBelow()`；`layoutBelow()` 从题面底边往下依次排，
每块占完位置把游标往下推。后面的「台阶框」「答案块」加一行就行。

### 2. 两个可替换函数

```js
recognize(problemId, strokes) -> { ok, steps: [{ text }] }
review(problemId, index, text) -> { ok, tone, comment }
```

真服务版：前者把手写图送去 OCR，后者把识别出的文字送去点评（`text` 参数就是那时候要用的）。

### 3. 输入不重画

步骤列表用 `innerHTML` 一次铺完，`input` 事件**委托**在容器上；输入只写数据并落盘，
绝不调 `inkRender()` —— 一重画 DOM 被重建，光标就断了。

## 验收方式

```bash
ruby tools/checks/build_wb_harness.rb && osascript -l JavaScript tools/checks/_build/wb-check.js
ruby tools/checks/verify_whiteboard.rb
ruby tools/checks/run_all.rb
```

真机：打开 `whiteboard.html`，选一道预置题（如 7a-01），在题面外写几笔，点「转文字」。

第三个按钮 + 题目下方的面板 + 只认框外的范围判定 + 按题目 id 存取 + 两个可替换函数。
断言 868 → **916** 条，0 失败。

**断言抓出来的一个真 bug：** 编辑某一步的文字，会被存到**上一题名下**。
根因是 `state.ink.problemId` 只在 `inkSyncProblem()` 里更新，而"关掉再打开"这条路径不走它，
于是切到 7a-03 改字，写进了 7a-02。修法：打开（`inkLoad`）与重新识别（`runTranscribe`）时
都以"此刻的题"为准。**这条只有断言能发现** —— 界面上看起来一切正常，只是换个题打开发现改动不见了。

**两处旧守线的订正（都是"守线写错了"而不是代码错了）：**

1. `border-radius:999px` 的计数原来数**整个文件**、要求恰好 6。我新加的「演示」标与语气标
   本来就是圆的小标签（在页面自己的样式块里），一加就报"圆形用法数量异常（8）"。
   改成**只数共享区**（`wb-styles`）—— 要守的是"工具条 / 浮层这些共用控件别变回胶囊"，
   回归风险只存在于共享区。改完共享区仍然是 6，守线强度没变。
2. 预置数据的语气标必须只有"成立 / 可以更严谨"：加了一条守线，`PRESET` 里出现 `'warn'` 就报错 ——
   「没有真模型就不判学生对错」这条规矩得有人看着，否则以后很容易顺手加两句"这一步错了"。

**证明过它能红（两次，各自隔离）：**

- 把"框外零笔迹就不装"那道门关掉：**4 条 FAIL**，其中第一条正是要害 ——
  `**不给内容** —— 不许凭空变出一段用户没写过的字（期望 0，实际 3）`，
  即面板会凭空显示 3 步用户没写过的"思路"；配套的演示标 / 说明 / 动作按钮也跟着错。
- 把"只认框外"的过滤去掉（全收）：**4 条 FAIL** ——
  `整条都在题面框里 → 不算（期望 0，实际 1）`、`正好一半在框里的不算（期望 0，实际 1）`、
  `混在一起也能挑对（期望 2，实际 3）`、`题面里的那条不算，题面外的才算（期望 1，实际 2）`。

断言自身也改对过一处：第一版把"框里那笔"的坐标写死了，实际题面框只有 160×77
（宽度随题目长短变），写死的点早跑到框外去了 —— 改成按 `problemLayout()` 现算。

**真机验证（读页面几何 + 截图）：**

| 项 | 实测 |
| --- | --- |
| 题面框 | `{x:16, y:16, w:160, h:77}`（真实布局算出来的） |
| 范围判定 | 往板上放两条笔迹（一条框内、一条框外）→ 只有 **1** 条算作"你写的思路" |
| 点按钮 | `#wb-act-transcribe` 点一下 → 面板展开、`state.ink.open = true` |
| 落位 | 面板 360×419，左上角 `(88, 121)`；题面底边在屏幕上 y=109，**+12 就是 121** —— 正好贴在题目下方 |
| 内容 | 3 步，文字与语气标分别是 `ok / ok / careful`；第一步的 HTML 带 `contenteditable="true"` 与 `data-step="0"` |
| 说明 | 「演示」标可见；说明为「识别与每步点评由本机演示数据生成，尚未接入在线模型。」 |
| 视觉 | 截图确认：题面右边三个按钮（分析 / 答案 / 转文字，当前那个高亮）、面板在题目正下方、三步文字与点评都可读、「可以更严谨」是琥珀色 |

**一处必须说清的限制：** 真机上的那两条笔迹是**直接放进 `state.strokes`** 的，不是用合成指针事件画出来的 ——
浏览器自动化通道里 `setPointerCapture` 对非真实指针会抛，笔迹起不来。
所以这一步跳过了"指针 → 笔迹"，而那一环另有 367 条断言，本轮之前也在真机上手验过。
不把这个说清楚，等于把"验过"说大了一号。

**结论：** 全量 **916 条 / 失败 0 条**；`wb-check` 367 条；`verify_whiteboard.rb` 新增 17 条守线。
