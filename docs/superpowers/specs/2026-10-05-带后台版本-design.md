## 1. 为什么做

用户原话（2026-10-05，逐条）：

> 「原来设定的那些是原来设定的那些事，是静态的。**现在要都改成和服务器对接**。」
> 「**章节 图谱 时间轴**的数据都是从后台才录入的，需要后台录入。」
> 「登录之后，这个**论坛同步**。」
> 「**真题**可以一直看，**方法**也是公共的，不需要登录看……但是要用**题库**那时候，我就需要登录了。」
> 「**支付也一起搞**，可以连接微信和支付宝账号支付。我们的系统收费可以**在后台设置套餐和服务项目，然后在前台显示出来**。默认出**免费版本**，收费版本一个**半年期、一年期、三年期**。」
> 「一切按照你的规划做；但是我们要做成**全部后台数据贯通**的。」

### 1.1 这一版推翻的三条旧口径

写在规则与原理里的，要一起改，否则以后每次都吵：

| 旧口径 | 出处 | 改成 |
| --- | --- | --- |
| 零构建、零 npm | §3.1、§1 技术底座 | **学生端仍然是零构建**（这条保住）；**管理后台**允许 Vue 构建链 |
| **双击 HTML 就能打开** | §3.1、§1 技术底座 | **作废** —— 接了接口，学生端必须由 HTTP 提供（原因见 §1.3，不是构建造成的） |
| 本地优先的数据模型（论坛 / 会话 / 画布 / 进度全在 localStorage） | §3.6 | 服务器是**唯一真相源**；localStorage 降级成"只读缓存 + 设备偏好" |
| 不引入构建链（红线 §6.1，"违反即打回"） | §6.1 | 收窄为「**学生端不引构建链**」；管理后台另立一条 |

### 1.2 保留的一条

**章节 / 图谱 / 时间轴共用同一份知识结构。** 现在是 `math-tree.js`（`window.MATH_TREE`，由 `tools/build-math-tree.rb` 从 4 份教材 md 生成），改成 `GET /api/tree`。这是现在代码里最干净的一处，**不许在接后台时弄丢**（`reader.html:103` 那句注释就是它）。

### 1.3 「零构建」与「联网」是两回事（用户 2026-10-05 专门问过）

这两件事**互不相干**，必须分开记，否则一接后台就会误以为"要上构建链了"：

| | 说的是什么 | 接后台后的结论 |
| --- | --- | --- |
| **构建** | 源码能不能直接给浏览器看 —— 要不要 `npm install` + 打包才能跑 | **学生端不需要**：文件还是 `reader.html` + `assets/js/*.js`，改一行刷新就生效 |
| **联网** | 运行时数据从哪来 —— 静态文件，还是接口 | **必须联网**：`fetch('/api/tree')` |

**"零构建 + 必须联网"完全成立** —— 就是现在的静态站换了个数据源。数据怎么读的，对比只有这两行：

```js
// 现在（读静态 JS 文件）
var TREE = window.MATH_TREE;        // reader-live.js:18
var DATA = window.MATH_TREE;        // mindmap.js:20（图谱读的同一份）
var axis = window.WK_AXIS.build();  // timeline.js:188（时间轴用它摊平）

// 接后台后（读接口）—— 文件本身不变、工具链不变、还是没有 npm
var TREE = await fetch('/api/tree').then(function (r) { return r.json(); });
```

**但有一个后果必须认下来**：`file://` 下浏览器会拦掉 `fetch`（跨源），所以**"双击 HTML 打开"这条用法到此结束**，学生端必须由 Nginx（或本地 `ruby serve.rb`）提供服务。这不是构建造成的，是联网造成的 —— 两个门槛分开记。

**为什么学生端不趁机上 Vue**：好处是 45 页里重复的侧栏 / 页脚 / 页头能变成组件、能用 TS，改一处全站生效；代价是 **45 页整体重写成 SPA + 路由，工作量与做一遍管理后台同量级**，而且现在这 1452 条前端守线、15 项静态体检全是围绕"能直接读源码做断言"建的，重写完得重做一遍。**这一版不动**（见 §6）。

## 2. 决策

| # | 决策 | 为什么 |
| --- | --- | --- |
| 1 | 拆成**三部分**：管理后台（Vue3 构建）/ API 服务 / 学生端（现静态站改造），三者独立部署 | 管理后台要构建链，学生端不要；混在一起就得二选一 |
| 1a | 学生端**保持零构建**，只把数据源从静态文件换成接口；**不趁机上 Vue、不重写 SPA** | 构建与联网是两件事（§1.3）。"改一行刷新就生效"这条要保住；上 Vue 等于 45 页重写 + 1452 条守线重做 |
| 1b | 学生端**必须由 HTTP 提供服务**（Nginx / 本地 `ruby serve.rb`），"双击 HTML 打开"这条用法作废 | `file://` 下 `fetch` 被浏览器拦掉，接口一个都调不到；这是联网的代价，不是构建的 |
| 2 | **服务器是唯一真相源**；学生端保留一层**只读缓存**（localStorage 存上次的树与正文） | 用户要"全部后台贯通"。纯裸连会在教室网抖动时白屏；只读缓存救急，不承担写 |
| 3 | 知识结构走**一次 `GET /api/tree`**，三处共用 + 带版本号可缓存 | 见 §1.2 |
| 4 | 正文粒度到**节**（Section） | 一章一篇太粗（一章几万字发不动）；一个知识点一篇头太多（现在是 520 节 / 280 知识点） |
| 5 | 公开 / 登录的分界**按用户原话**，见 §3.2 | 真题、方法公共；**题库要登录** |
| 6 | 时间轴**未登录也能看**（看公共/空的），登录后叠自己的学习数据 | 用户没说时间轴要登录；而且这条与现在代码的设计一致（未登录看"演示学生"） |
| 7 | 收费：**免费 + 半年 / 一年 / 三年**三档；**套餐与服务项目在后台配**，前台按配置渲染 | 用户原话 |
| 8 | 支付接**微信支付 + 支付宝**，PC 端优先 **Native 扫码（微信）+ 电脑网站支付（支付宝）** | 用户原话；见 §3.8 的前置条件 |
| 9 | 权限：**后台 RBAC（管理员）** 与 **学生 JWT** 两套，别混 | 管理员是"能改数据的人"，学生是"只能改自己的" |
| 10 | 学生端登录态走 **httpOnly Cookie + SameSite**，不用 localStorage 存 token | localStorage 有 XSS 面；部署同域反代最省事 |
| 11 | **Redis 第一版不上** | 真有场景的只有会话 / 验证码 / 热点缓存，现在没有痛点；少一个要装要运维的东西。等出现批卷队列 / 排行榜再加 |
| 12 | 文件存储：**开发期用「本地目录」驱动**，生产切 OSS / COS | 原定开发期 MinIO，**探测后推翻**：官方已下架 macOS 构建（`dl.min.io` 返回 410），装不了。改成本地目录反而更省事（少一个容器）：API 里抽象一层 storage 接口，dev 写本地文件夹、生产换 OSS，只改配置 |
| 13 | **白板云同步这一版不做** | 用户只说了论坛同步；白板搬上去是独立一块（画布数据结构要重设计），留给 1.8 |

## 3. 技术方案

### 3.1 三个部分与数据流

```
┌─────────────────┐        ┌──────────────────┐        ┌─────────────────┐
│  管理后台        │  REST  │    API 服务       │  SQL   │   MySQL 8       │
│  Vue3+Vite+TS   │ ─────► │  Node + TS        │ ─────► │   Prisma        │
│  Element Plus   │  JWT   │ Node + Express+TS │        │                 │
└─────────────────┘        └────────┬─────────┘        └─────────────────┘
                                    │ REST               ┌─────────────────┐
┌─────────────────┐                 │                    │ 本地目录 / OSS   │
│  学生端          │ ────────────────┘                    │ 扫描件 / 头像    │
│  静态页 + 改造   │  Cookie 会话                         └─────────────────┘
└─────────────────┘
```

- **管理后台**：老师/运营用。录结构、录正文、录题、配套餐、看订单。
- **API 服务**：一套接口，两种身份（管理员 / 学生）。RESTful + Swagger。
- **学生端**：现有 45 页逐页改造，`fetch` 换掉 `window.MATH_TREE` / `timeline-data.js`。**仍然是零构建**（没有 npm、没有打包器、没有框架运行时，改动仍是"存盘刷新"），但**必须由 HTTP 提供服务** —— 它变成一个"零构建 + 联网"的静态站（§1.3）。**数轴与 3D 数轴的数据分两块**：轴上的格子与刻度来自公共的 `/api/tree`，彩条与日期（掌握度 / 学习记录 / 考试切片）来自私有的 `/api/me/learning`。两块都是后台读，只是后者要登录。

### 3.2 公开 / 登录分界（按用户原话画）

| 内容 | 未登录 | 登录后 | 来源 |
| --- | --- | --- | --- |
| 章节正文 | ✅ 公共那份 | ✅ 同左 + 自己的笔记/进度标 | 后台录入 |
| 知识图谱 | ✅ | ✅ | `/api/tree` |
| 时间轴 | ✅ 看公共 / 空的 | ✅ 叠**自己的**学习数据 | `/api/tree` + `/api/me/learning` |
| 真题卷 | ✅ 能看能翻 | ✅ 记作答 | 后台录入 |
| 方法速学 | ✅ 公共 | ✅ 可收藏 / 记笔记 | 后台录入 |
| 公式速查 / 易错速析 | ✅ 公共 | ✅ | 后台录入 |
| **题库（练题）** | ❌ **触发登录闸** | ✅ 作答、判分、进错题本 | 后台录入 |
| 论坛 | 只读 | 发帖 / 回复，**归账号** | `/api/forum/*` |
| 学习中心 9 页 | ❌ 跳登录 | ✅ | `/api/me/*` |
| 管理后台 | ❌ | 仅管理员（RBAC） | 独立应用 |

> **"两副面孔"要在设计上认下来**：同一根时间轴 / 同一个知识点，未登录看的是公共视图，登录后是自己的。这不是特例，是常态，接口要显式区分（`/api/tree` 公共 vs `/api/me/*` 私有）。

### 3.3 收费与套餐模型

用户口径：**免费版默认**；收费三档（半年 / 一年 / 三年）；**套餐与服务项目在后台配，前台按配置显示**。

所以钱这块不是写死在页面上的三张卡，而是**数据驱动**：

```
Plan（套餐）        ：免费版 / 会员版 ……  可后台增删
  ├─ term: 免费 | HALF_YEAR | ONE_YEAR | THREE_YEAR
  ├─ price / 原价 / 排序 / 是否上架
  └─ ServiceItem[]（服务项目，多对多）

ServiceItem（服务项目）：能做什么 —— 逐条列，前台按"有/没有"打勾
  例：免费版 { 章节正文 ✅ 图谱 ✅ 时间轴 ✅ 真题 ✅ 方法 ✅ 题库 ❌ 错题本 ❌ 学习报告 ❌ }
      会员版 { 全 ✅ + 扫描件精批 + 学习报告 + 错题本 …… }

Entitlement（权益判定）：一个用户当前"能用哪些 ServiceItem"
  ← 由「有效的 Subscription」推导，服务端算，前端只读
```

**关键一条**：**能不能用某个功能，判定必须在服务端**（前端只负责"灰掉 + 提示"）。前端藏个按钮不算权限。

免费版的"哪些能用"也要入库（就是一条 `Plan`），别在代码里写死 —— 否则以后想改免费版给什么，就得改代码发版。

### 3.4 数据模型（Prisma schema 草案）

**A. 知识结构（后台录入 · 公共读）**

```
Stage      学段       primary | junior | senior | olympiad
Book       册 / 板块   → Stage         （竞赛那四支没有册，用 track 当这一级）
Chapter    章         → Book          no / name / field（课标领域）/ order
Section    节         → Chapter       no / name / order
Point      知识点      → Section       name / order / difficulty
PointCard  知识点卡片   → Point         kind（概念/公式/例题/变式/错题/复习）/ weight
```

> `PointCard.weight` 就是 3D 轴"一格按权重切成几块"的依据（§2.11 第 73 条），别丢。

**B. 内容（后台录入 · 公共读）**

```
Content    正文        → Section（或 Point）   body（HTML）/ version / publishedAt
Exam       真题卷       → 名称 / 日期 / 学年 / 类型 / 满分
ExamQuestion 卷面题序   → Exam, Question       no / fullScore / order
Question   题          → Section/Point         stem / options / answer / analysis / difficulty
QuestionPoint 兼考关系  → Question, Point      （对应现在的 also 字段）
ExamScan   扫描件       → Exam                 ossKey / page / 正反面
ScanBox    每题框       → ExamScan, ExamQuestion  x / y / w / h（**百分比**，见 exam-scan.js）
Formula    公式速查     → Section/Point
Pitfall    易错速析     → Section/Point
Method     方法          → 分类 + 正文
```

**C. 用户与运营（登录后 / 后台）**

```
User          账号       phone / email / passwordHash / nickname / grade / status
Role / Permission / RolePermission        后台 RBAC
Subscription  订阅       → User, Plan       startAt / endAt / status
Order         订单       → User, Plan       amount / status / channel
Payment       支付单     → Order            channel（WECHAT/ALIPAY）/ 三方单号 / 回调原文
Refund        退款       → Payment
LearningRecord 学习记录   → User, Point       type（首学/复习/纠错/考试）/ at / mastery
ExamAttempt   考试记录   → User, Exam        每题得分
Mistake       错题本     → User, Question    原因 / 订正状态
Favorite      收藏       → User, (Point|Question|Method)
Note          笔记       → User, (Point|Section)
PointMark     标记       → User, Point        （现在的 wkmath.timeline.marks.v1）
CauseAck      错因认可    → User, ExamQuestion（现在的 wkmath.exam.scan.v1）
Notification  消息       → User
Board / Post / Reply   论坛三张表
```

`LearningRecord` 的字段**照 `timeline-data.js` 现在的输出形状设计** —— 那个文件的头注释写着"接后端时只替换 `build()`，视图层一个字不用动"，别另发明形状。

### 3.8 支付接入与前置条件（**这是最长的前置，先启动**）

| 渠道 | 场景 | 要什么 |
| --- | --- | --- |
| 微信支付 | PC 网页 → **Native 扫码**；手机在微信内 → JSAPI；小程序 → 小程序支付 | 企业主体 · 微信支付商户号 · 已认证的 appid · API v3 密钥 + 商户证书 · **回调域名（已备案 + HTTPS）** |
| 支付宝 | PC 网页 → **电脑网站支付**；手机网页 → **手机网站支付** | 企业支付宝账号 · 开放平台应用 · 应用私钥 / 支付宝公钥 · 签约对应产品 · 回调域名 |

**硬前置（不是技术活，是流程活，通常要几天到两周）**：企业营业执照、对公账户、域名备案。
**技术要点**：回调必须**验签**（微信 v3 平台证书 / 支付宝公钥）；订单号幂等；`Payment` 表存回调原文备查；开通后按 `Plan.term` 算 `Subscription.endAt`，到期用**定时任务**扫（不用 Redis）。

> 实现时：本机环境里有支付宝官方接入的 skill（`alipay-payment-integration`，覆盖产品选型 / 签名验签 / 服务端 SDK），到那一步我会用它对齐；微信支付没有对应 skill，按官方 v3 文档做。

### 3.9 部署

`Docker Compose`：`api` + `admin`（Nginx 出静态）+ `mysql`。**开发期不上 MinIO**（macOS 构建已下架），文件走本地目录；生产再加 OSS。生产用 **Nginx 同域反代**（`/api` → API，`/` → 学生端或后台），好处：Cookie 不用处理跨域，CORS 白名单也不用开。

学生端在 Nginx 上就是**一堆静态文件直接吐**（没有 node 进程、没有 SSR、没有构建产物）—— "零构建"这条保住了。**但"双击 HTML"这条路没有了**：接口要求 HTTP 源（§1.3），所以 Nginx 从"可选"变成"必需"；本地开发仍是 `ruby serve.rb`。

### 3.10 自检体系怎么延伸

现在是"1452 条断言 + 15 项静态体检"，全在前端。接后台后要分三层：

1. **前端那套不动**（章节/图谱/时间轴的结构与口径照旧守）。
2. **接口契约**：Swagger 导出 → 生成一份"字段与类型"的静态核对（前端读的字段必须存在于 schema）。
3. **数据模型**：用 Prisma schema 反推断言（例如"每个 `Point` 必须属于一个 `Section`"、"`ScanBox` 坐标必须在 0–100"）。

### 7.1 选了 Express 之后，要自己立的三条规矩

Express 不带结构，所以下面三样**必须在项目里定死**（细则写进实施计划），否则半年后就是一团中间件：

1. **Swagger 不许手写** —— 接口文档从 **zod schema 生成**（`zod-to-openapi`）：一份 schema 同时管「运行期校验」和「文档」。手写 doc 迟早和实现脱节，那"接口文档"这条选型就白选了。
2. **入参一律走 zod，出参一律走 mapper** —— 不许在路由体里直接拿 `req.body.xxx` 当业务参数；也不许把 Prisma 的原始对象直接吐给前端。
3. **权限一律走中间件** —— `requireAuth` / `requireRole('ADMIN')`；不许在路由体里手写 `if (user.role !== 'ADMIN')`。一个域一个目录（`router / service / schema / mapper` 四件套），业务只写在 service 里。
