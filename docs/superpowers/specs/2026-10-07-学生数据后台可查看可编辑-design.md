# 学生数据 · 后台可查看可编辑 · 设计稿（2026-10-07）

用户原话：

> 明确一下 学生端和教师端的所有的报告和数据要在管理后台里都可以查看和编辑

---

## 1. 这条要求推翻了什么（要先说清）

| 原有约定 | 出处 | 现在 |
| --- | --- | --- |
| "这一页**只读**。改数据仍然走各自那一处（角色/停用在本文件上面，切片在学生自己那儿）。" | `admin.routes.ts` 用户详情 overview 的注释 | **反过来**：后台要能看明细、能改 |
| "在这儿顺手加一个'改分数'，就等于开了第二个入口 —— 两边迟早对不上。" | 同上 | 改成"**有留痕的第二个入口**"：不是不能开，是开了必须记下谁改的 |

这不是"忘了当初为什么"，而是需求变了：老师要能改错录的分数、订正标错的错题，
而学生手上那台设备改不了。**当初那条担心的不是"多一个入口"，是"多一个没人记得的入口"** ——
所以这一版的核心不是编辑功能，是**留痕**。

## 2. 现状缺口（2026-10-07 逐条核过）

| 学生端的数据 | 后台**能看** | 后台**能改** |
| --- | --- | --- |
| 学习记录（掌握度/状态/日期/五因子/卡片） | 只有汇总计数 | ✗ |
| 学习事件（轨迹） | 只有计数 | ✗ |
| 考试 + 卷面逐题 | 列表（得分率/错题数） | ✗ |
| 错题本 | 只有计数 | ✗ |
| 收藏 / 笔记 / 标记点 | 只有计数 | ✗ |
| 练习记录（会话 + 逐题） | 只有汇总 | ✗ |
| 上传的切片（图 + 框出的错题） | 列表 + 报告 | ✗ |
| 学习报告那五块 | ✓（同一组数） | ✗（算出来的） |
| 班级 / 花名册 / 班主任 | ✓ | ✓（已有） |

**结论：明细基本看不到，编辑几乎为零。**

## 3. 三条已定的决策

1. **修正型编辑** —— 能改已存在的数据、能删；**不提供"凭空造一条学习记录/考试"的入口**。
   理由：一旦有了造数入口，"这个学生到底学没学过"在库里就再也分不清，
   而这一整站的数（成长曲线、报告、花名册）全都建立在"这些记录是学出来的"上面。
2. **老师可改自己班学生的数据**，越界一律 **404**（与 `classScopeOf` / `visibleUserIds` 同一条规矩）；
   管理员全权。
3. **留痕**：每次改动记下"谁、什么时候、改了哪个学生的哪条、哪个字段、旧值 → 新值、为什么"。

## 4. 数据模型

### 4.1 变更留痕

```prisma
/// 后台改动学生数据留下的痕迹。
/// **每一次改动都必须写一条** —— 这是"第二个入口"能被接受的前提：
/// 学生说"我明明是 85 分"的时候，要查得出是谁、什么时候、从多少改成了多少、为什么。
model DataChange {
  id      Int  @id @default(autoincrement())
  /// 同一次保存产生的一批改动共用一个 batchId，回放时能看成一次操作
  batchId String @db.VarChar(32)

  actorId  Int
  actor    User @relation("ChangeActor", fields: [actorId], references: [id], onDelete: Restrict)
  /// 改的是**谁的数据**（不是谁改的）—— 查一个学生的变更历史走这个
  targetId Int
  target   User @relation("ChangeTarget", fields: [targetId], references: [id], onDelete: Cascade)

  /// learning_record | learning_event | mistake | exam | exam_paper | exam_slice | note | favorite
  entity   String @db.VarChar(32)
  entityId String @db.VarChar(32)
  /// 改的是哪一层（做批注用得上）
  label    String @db.VarChar(191)
  /// 改动的字段名；删除是整个实体的改动，field 记 delete
  field    String @db.VarChar(48)
  oldValue String? @db.Text
  newValue String? @db.Text
  /// 为什么改（改的人填一句）——允许留空，但界面上要催一下
  reason   String? @db.VarChar(191)

  createdAt DateTime @default(now())

  @@index([targetId, createdAt])
  @@index([actorId, createdAt])
  @@index([batchId])
  @@map("data_change")
}
```

为什么 `actor` 是 `Restrict`、`target` 是 `Cascade`：

- **actor 不能删**：删了执行人，这条留痕就废了（"谁改的"变成空白），
  而留痕的价值恰恰在那个人身上。所以有留痕的管理员账号**删不掉** —— 这是刻意的。
- **target 跟着学生走**：学生被删了，他的数据也一起没了（`User` 下各表都是 Cascade），
  留痕跟着走是一致的，不会留下一批指向空学生的孤儿记录。

### 4.2 权限点

| 权限点 | 给谁 | 管什么 |
| --- | --- | --- |
| `student.write` | admin · **teacher** | 改学生的学业数据（学习记录/错题/考试/切片/笔记） |

teacher 拿 `student.write`，但**数据范围仍由 classScopeOf 卡住**（只看/只改自己班）。
这与"`class.write` 只给 admin"不矛盾：建班是管理动作，改学生的学业数据是教学动作。

## 5. 接口

### 5.1 查看明细（补上现在看不到的那些）

统一 `GET /admin/students/:id/...`，全部 `student.read` + 老师范围过滤：

| 接口 | 给什么 |
| --- | --- |
| `/admin/students/:id/learning` | 学习记录明细（知识点名 + 章节路径、掌握度、状态、日期、五因子、卡片、标记） |
| `/admin/students/:id/events` | 学习事件轨迹（时间、类型、掌握度、关联考试） |
| `/admin/students/:id/mistakes` | 错题明细（来源、知识点、错因、状态） |
| `/admin/students/:id/exams` | 考试 + **卷面逐题**（题号、知识点、得分/满分、错因） |
| `/admin/students/:id/practice` | 练习会话 + 逐题（答了什么、对不对） |
| `/admin/students/:id/slices` | 切片明细（含图与框出的错题） |
| `/admin/students/:id/notes` `/favorites` | 笔记与收藏 |
| `/admin/students/:id/changes` | **变更留痕**（谁在什么时候改了什么） |

分页一律 `page`/`pageSize`（上限 100，和用户列表同一条规矩）。

### 5.2 编辑（全部 `student.write` + 老师范围 + **写留痕**）

| 接口 | 能改什么 |
| --- | --- |
| `PATCH /admin/learning-records/:id` | 掌握度、状态、学习/复习/计划日期、五因子 |
| `PATCH /admin/mistakes/:id` | 订正状态（open/fixed）、错因 |
| `PATCH /admin/exam-papers/:id` | 本题得分、错因 |
| `PATCH /admin/exams/:id` | 考试名、日期、范围 |
| `PATCH /admin/exam-slices/:id` | 名称、日期、分数/满分、备注 |
| `PATCH /admin/notes/:id` | 标题、正文 |
| `DELETE /admin/<实体>/:id` | 学习记录 / 错题 / 笔记 / 切片（都写一条 `field: delete` 的留痕） |

**改学习记录会牵动成长曲线和报告** —— 这是必然的，也是要留痕的原因。
接口返回里带上"这条改动影响了什么"（例如改了 mastered 数），让改的人当场看见后果。

### 5.3 明确不提供的

- **不提供造数入口**（决策 1）
- **练习记录（PracticeSession/Answer）不可编辑**：那是"当时做了什么"的历史。
  改它就是伪造历史。允许**删除整次会话**（学生重练），删也留痕。
- **不提供改学生账号密码之外的身份数据**（角色/停用已另有入口，不重复开）。

## 6. 界面

「学生详情」页从**只读一页**改成 **tab 式**：

```
基本资料 | 学习记录 | 时间轴 | 错题 | 考试 | 练习 | 上传的卷子 | 笔记与收藏 | 变更记录
```

- 每个 tab **能看明细**（现在只有计数）
- 可改的字段行内可编辑，保存时**弹一次原因**（可留空，但默认聚焦在那里）
- 「变更记录」tab：按时间倒序列出"谁改了什么"，同一次保存用一个批次号归组
- 顶部加一条提醒：**这一页的改动学生端立刻可见**

## 7. 分期

| 期 | 内容 | 验收 |
| --- | --- | --- |
| **E1** | `DataChange` 模型 + `student.write` 权限点 + 留痕写入的公共函数 + 老师范围复用 | 表建起来；权限点上到 admin/teacher；留痕函数有单测级的验证 |
| **E2** | 查看明细的 8 个接口 | curl 逐条验：数据与学生对得上；老师越界 404 |
| **E3** | 编辑接口（含删除），每一条都写留痕 | curl 验：改完值变了、留痕多了一条（旧值/新值/原因都在）；**改别人的班 404** |
| **E4** | 学生详情页 tab 化 + 行内编辑 + 变更记录页 | 真浏览器：改一个掌握度 → 学生端成长曲线当场变 → 变更记录里查得到 |

## 8. 风险与硬规矩

1. **留痕不能漏**：编辑函数一律从一个公共入口走（`applyChange()`），
   它负责"写库 + 写留痕"两件事一起做。**任何绕过它直接 `prisma.update` 的写法都是 bug。**
2. **改完要看得到后果**：改了掌握度/分数，学生的报告、成长曲线、花名册全部会变。
   接口的返回里带上受影响的关键数字，界面在保存后刷新那一块。
3. **删除比编辑危险**：删学习记录会连带删 `LearningEvent`（Cascade）。
   删除接口要先回一句"会连带删掉 N 条事件"，让人知道自己在删什么。
4. **老师的范围不能靠前端**：`student.write` 给了 teacher，范围一律由服务端
   `visibleUserIds()` 卡；越界 404 而不是 403。
