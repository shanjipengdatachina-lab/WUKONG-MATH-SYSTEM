# 白板呈现层：把手 / 反馈位置 / 导出图片 / 板面主题

> 状态：**设计已确认**（2026-09-28 对话确认），待你过一遍文档本身
> 范围：白板页 `whiteboard.html` 一个子项目
> 不在本次范围：图谱掌握层标记（A）、图谱结构搬到白板（B）、真 AI 服务、手机端 —— 各自单独出方案
> 相关：`docs/1.0-版本日志.md` §2 功能清单、§4 规范（尤其 §4.6 浮层事件隔离、§4.8 画布变换）、§7 验收口径
> 上游：`docs/superpowers/specs/2026-09-28-白板题目底纹与AI分步分析-design.md`（题面底纹与「分析 / 答案」）

## 1. 要解决的问题

1. **题面的把手多了一条。** 悬停时浮现的是"一条蓝色通高竖条 + 两道短横"两部分。竖条是多余的 —— 只留那两道类似等号的短横就够了。
2. **操作反馈挡住工具条。** 清空 / 撤销之后底部弹出的提示气泡正压在工具条上，看不清工具按钮。上一轮我修的是 `[data-wb-tip]` 自绘**工具提示**，而这个气泡是**全站统一的 toast 组件**，根本没碰到。
3. **演算没法带走。** 板上的题和自己的推导，只能留在这一块板里。需要一键导成一张图片，能发给老师、能存进错题本。
4. **板子只有白的。** 长时间盯着白底看累眼睛；板书场景（投影、教室）反而需要深色板。板面色一换，题面文字和笔色都得跟着换，否则字直接消失。

## 2. 设计决定

| # | 决定 | 为什么 |
| --- | --- | --- |
| 1 | 题面把手只留**两道短横**，删掉左侧那条通高蓝竖条 | 两道短横已经说清了"这里能抓"。竖条横向不占地方，但视觉上多一条竖线，题面看着像被框住了一半 |
| 2 | 操作反馈（toast）在白板页**抬到工具条上方**（≥ 工具条顶边 + 8px） | 白板的工具条在底部居中，而 toast 的定位是全站统一的 `bottom:28px` —— 两者天然重叠。只改白板页，不动全站：别的页面底部没有工具条，抬高了反而怪 |
| 3 | 导出用**离屏重画**，不是裁当前屏幕 | 裁屏幕只能拿到"当前看得见的那一块"：缩到 40% 看全局就糊，演算超出可视区就缺。要做到"他算到哪就截到哪"，必须按内容包围盒把笔迹重新渲染一遍 |
| 4 | 导出**先给预览**，不直接下载 | 直接下载会掉进"下载"文件夹，学生经常找不到。预览里给「保存」和「关闭」两个按钮，图就在眼前 |
| 5 | 导出比例给三档：**16:9（默认）/ 4:3 / 按内容** | 16:9 横着看方便，是日常分享的默认；要贴进作业本用 4:3；只想留个记录就用按内容（不补边） |
| 6 | 四周留白**8%（最小 24 世界单位）**，不足比例的边用**板面色**补 | 题面贴着图片边不好看；补白边会突然冒出一块白，用板面色补才像"这块板本来就那么大" |
| 7 | 导出**默认只带题目与演算**；工具条与题库面板**永远不带**；台阶框与答案块做成**两个可勾选的开关**（默认关，记住选择） | 工具条和面板是 DOM，本来就不在画布里，天然排除。台阶框和答案块也是 DOM，但它们属于"这道题的内容"，该由用户决定带不带 —— 存证自己的演算时，图上带着答案反而是坏事，所以默认关。"悬停底"和"把手"是画在画布上的，导出时必须显式关掉，否则正悬停着截图就一起进去了 |
| 8 | 板面做三套：**白板 / 中板 / 黑板**；每套是一整套配色（板面色、网格、题面四色、六支笔、荧光透明度） | 换板面色不是刷个背景：深色板上深色字会直接消失。少给一样就会坏 |
| 9 | 换板时画笔颜色**按序号平移**（第 2 支 → 新板子的第 2 支），**已经画在板上的笔迹也一起平移** | 序号平移是唯一不会让人意外的映射（否则"我选的红色怎么变绿了"）。已经画好的笔迹也要平移，是因为不平移的话切到黑板时原来的深色墨迹会**直接看不见**——那不叫"换了块板"，那叫"把我的推导弄没了"。代价是切换时整幅图会换一次色，但位置、形状一律不动 |
| 10 | 黑板用**深蓝黑 `#0f172a`**，不用纯黑 ~~（已作废：用户要纯黑，改成 `#000000`，见下面「三套配色」表后的修订注）~~ | 原理由：纯黑配白字对比过强、久看累；深蓝黑是"护眼"那句的落点。**用户看过真机之后否掉了这条** |
| 11 | 板面色由**画布自己填**，不再靠 CSS 白底 | 画布现在是 `clearRect` 透明的，白底来自 `.wb-canvas-wrap` 的 CSS。导出时透明区就变成透明 PNG 了，必须有个真实的板面色 |
| 12 | 导出**长边 1600px**，不做更高 | 16:9 就是 1600×900。够发群里、够贴进错题本，文件也不至于几 MB。要更清楚是以后的事 |
| 13 | 勾上分析 / 答案时，导出图变成**左右两栏**：左边板面、右边一栏竖排分析与答案 | 屏幕上的台阶框是可以随手拖的"工作台"，摆位是你思考的过程；交出去的图该是整齐的。所以右栏是**用同一份数据重新排版**（编号台阶 + 引导语 + 你自己写的那一栏；答案 + 注释），不是把屏幕像素抠下来 |
| 14 | 勾选**与屏幕上的开合状态无关** | 可以在干净的板上导图（不点开「分析」也能导出分析），也可以板上开着两个框却不带进图。勾的是"这张图里要不要"，不是"屏幕上开没开" |

## 3. 界面细节

### 3.1 题面把手

- 悬停时只画**两道短横**（13 × 2.2 世界单位，竖排在左侧无字条的中线上下），不再画那条 2.5px 通高竖条。
- 压在把手上仍变 `grab` 光标；正文照常落笔（Plan 1 已交付的规矩不变）。
- **连带后果：** 悬停时的填充次数从 4 降到 3。有一条断言正盯着这个数字（`wb-harness-tail.js` 的「悬停时浮现底 + 竖条 + 把手的两道短横」），要一起改成 3 并改掉措辞。
- **另一处连带：** 那条竖条原本兼任"这是一道题"的静态锚点（上游设计 §3.1）。删掉后题面静止时只剩极浅的底 + 一行标签色。可接受 —— 悬停底还在。

### 3.2 操作反馈的位置

- 只在**白板页**覆盖：`.wb-shell` 作用域内把 `.toast-stack` 的 `bottom` 抬到工具条上方。
- 数值不写死魔法数：工具条 `bottom:18px`、高约 46px（34 按钮 + 5×2 内边距 + 1×2 边框），所以抬到 `calc(18px + 46px + 12px + env(safe-area-inset-bottom))` = **76px 起**。
- 体检脚本按 CSS 里的实际数字算出"toast 底边 − 工具条顶边"的间隙，**小于 8px 就报错** —— 和上一轮修工具提示用的是同一套算法，不给"看着差不多"留空间。

### 3.3 导出图片

**入口：** 工具条上「清空」右侧加一个相机按钮 `#wb-shot`（与撤销 / 重做 / 清空同属"动作组"）。**不绑快捷键** —— `⌘S` 是浏览器自己的"保存网页"，抢过来是坏事。

> 注意两个被钉住的数字：工具条槽位到 **14**（体检上限正好也是 14，卡住，以后再加按钮必须先合并同类）；自绘提示总数 **14 → 15**（相机按钮要气泡，且工具条上所有按钮都有，不能破例）。体检脚本里这两个上限要同步改，并写明"这次是故意加的"。
>
> **事后修订**：槽位后来到过 **15** —— 「适应内容」从「画笔设置」浮层挪到了工具条上、紧挨着「放大」右边
> （用户要求："适应内容按钮挪出来，放在放大按钮的右边；换个图标表示适配内容"）。体检里那条上限同步放宽到 15，
> 注释写明"这次是故意加的"，并补了 6 条守线（位置 / 类名 / 图标 / 快捷键提示 / 旧位置清干净 / 死样式删掉）。
> 自绘提示总数仍是 **18**（按钮只是换了个地方）。上限仍然卡得紧：以后再加按钮，先想能不能并进已有的组。

**流程：**

1. 取**真实内容**包围盒。**这里有个坑：** 现有的 `contentBounds()` 里写死了一个 `720 × 120` 的默认区域（当初为了让"适应窗口"永远有个合理范围），所以它永远不会"空"，不能拿来判断"板上有没有东西"。新写一个只算真实墨迹的 `inkBounds()`：题面（若显示）+ 全部笔迹点，**没有任何内容时返回 null**。返回 null 就提示「板上还没有内容」，不做图。
2. 算尺寸（**纯函数** `exportPlan(bounds, ratio, include)`，可断言）：

```
pad      = max(24, 0.08 × max(内容宽, 内容高))        // 世界单位
boardW   = 内容宽 + 2·pad
boardH   = 内容高 + 2·pad

// 一、整张图的输出尺寸
若 ratio = 16:9  → 长边 1600，即 1600 × 900
若 ratio = 4:3   → 1600 × 1200
若 ratio = 按内容 → 让板面区正好等于（boardW : boardH），长边 1600

// 二、右栏占多宽（只在 include 非空时有）
panelW   = clamp(整图宽 × 0.38, 380, 620)            // 输出像素
gap      = 整图宽的 2%
板面区    = { x: 0, y: 0, w: 整图宽 − panelW − gap, h: 整图高 }
右栏区    = { x: 整图宽 − panelW, y: 0, w: panelW, h: 整图高 }
（不带右栏时，板面区 = 整张图）

// 三、把内容放进板面区：等比缩放 + 居中，多出来的边用板面色补
k        = min(板面区.w / boardW, 板面区.h / boardH)
内容左上角 = 板面区中心 − (boardW·k/2, boardH·k/2)
世界原点在输出图上的位置 = 内容左上角 − (pad·k, pad·k) + (裁切框相对内容左上角的偏移)·k
```

> 关键：**比例说的始终是"整张图"**。带上右栏时，板面区只剩左边约 62%，所以板面在图上会变小 —— 这是带上右栏的必然代价，预览里一眼就能看到，觉得小了就切「按内容」或 4:3。

3. 离屏重画：新建 `document.createElement('canvas')`，尺寸 = 输出尺寸，**先整张用板面色铺满**（这样补边色自然就是板面色），再画板面区（设变换后按顺序画网格（若开着）、题面、笔迹），最后画右栏。
4. 预览：在画布上方浮出 `#wb-shot-pop`。里面是 `<img>` + 两个勾选（`带分析` / `带答案`）+ 三个比例切换（`16:9` / `4:3` / `按内容`）+ 「保存」/「关闭」。任何切换都**立即重算重画**并更新预览图。
5. 「保存」→ 用 `<a download="文件名">` 触发下载，然后收起预览。

**右栏的内容与排版**（只在勾上时画；`exportPanelLines()` 是纯函数，可断言）：

```
分析
  1  先只看题目在问什么：要求的到底是哪一个量？     ← stepGuides()[i]，用 wrapText 折行
     我要求的是 −7 + 3 的和                        ← stepText(i)，学生写的那一栏（空就不画这一行）
  2  ……
答案                                              ← 只在勾了「带答案」时出现
  −7 + 3 = −4                                     ← 干净答案（answer.lines[].text）
  异号相加：先比绝对值。|−7| > |3|，所以取负号。    ← 注释（answer.lines[].note）
```

- 右栏配色**跟板面主题走**：黑板时也是深底浅字，不会突然冒出一块白纸。
- 答案的注释**跟随当前「显示注释 / 干净答案」开关**。
- 台阶里学生写的那一栏**一起带上** —— 那是"在台阶上自己推"的痕迹，正是这份作业的价值。
- 勾选状态**与屏幕上的开合无关**（决定 #14）。

**文件名：** `悟空数学-<题面来源>-<YYYYMMDD>.png`；没有来源时用 `悟空数学-白板-<YYYYMMDD>.png`。来源里的 `·`、空格、斜杠要清成 `-`。这是纯函数 `exportFilename(data, date)`，可断言。

**已知限制（要说在前面）：**

- **台阶框和答案块不会出现在导出图里。** 它们是 DOM 浮层，画布导出天然拿不到。这恰好就是你要的"只带题目和他演算的那一块"。如果以后想让某个台阶框也进图，那是另一件事（要把 DOM 光栅化后合成），本次不做。
- 长边封顶 1600px。演算铺满好几屏时，缩到 1600 会偏小。
- 深色板上荧光笔仍偏淡（只调了透明度，没换混色方式）。

### 3.4 板面主题

**入口：** 设置浮层（`#wb-pop`）里加一行「板面」，三个小色块按钮（`#wb-themes`）。位置在「颜色」上方 —— 板面是更外面一层的东西，先选板、再选笔，读起来顺。

**三套配色（一个主题就是一整包，少一样都不行）：**

| 字段 | 白板 | 中板 | 黑板 |
| --- | --- | --- | --- |
| `board` 板面色 | `#ffffff` | `#eceff3` | `#000000` |
| `grid` 网格 | `rgba(15,23,42,.06)` | `rgba(15,23,42,.07)` | `rgba(255,255,255,.10)` |
| `ink` 题面正文 | `#101215` | `#12161c` | `#ffffff` |
| `inkSoft` 题面补充 | `rgba(16,18,21,.56)` | `rgba(18,22,28,.58)` | `rgba(255,255,255,.62)` |
| `tag` 题面标签 | `rgba(16,18,21,.42)` | `rgba(18,22,28,.44)` | `rgba(255,255,255,.46)` |
| `tagHot` 标签悬停 | `rgba(37,99,235,.78)` | `rgba(37,99,235,.78)` | `rgba(255,255,255,.88)` |
| `tint` 题面浅底 | `rgba(37,99,235,.05)` | `rgba(37,99,235,.045)` | `rgba(255,255,255,.06)` |
| `highlightAlpha` | 0.30 | 0.30 | 0.38 |
| `colors` 六支笔 | 墨黑 `#1f2937` / 朱红 `#dc2626` / 靛蓝 `#2563eb` / 青绿 `#059669` / 橘橙 `#ea580c` / 紫罗兰 `#7c3aed` | 同白板（中板底色仍浅，深色笔照样看得清） | 雪白 `#ffffff` / 珊瑚 `#f87171` / 天蓝 `#60a5fa` / 翡翠 `#34d399` / 琥珀 `#fbbf24` / 淡紫 `#c084fc` |

> **事后修订（同日）**：用户看过真机之后要"纯粹的黑白"（原话："暗色系怎么感觉是蓝色；搞成黑色，
> 黑白是纯粹的颜色"），上表黑板那一列已是**改后**的值：板面纯黑、粉笔纯白，网格 / 悬停底 / 题面三档浓淡
> 一律无彩的白。原先选深蓝黑（`#0f172a` 一族）的理由是"纯黑配白字对比过强、久看累" ——
> **这条判断被用户否掉了，别再照着它改回去**。
> 应用层面的暗色（`tokens.css` 的 `html[data-wk-theme="dark"]`）同步纯化：
> 中性面一律 R=G=B，底 `#000000`、字 `#ffffff`；只留主色（品牌蓝）与状态色两处有颜色。
> 守线：`verify_display.rb` 第 8 节 + `wb-check` 第 11 节（都是"踩坏了会红"的）。

**换板的行为：**

1. 板面色、网格色立刻生效（`redraw()` 里改为**填板面色**而不是 `clearRect`）。
2. 题面四色立刻生效。
3. 笔色按序号平移，**两条路径都要**：
   - 当前在用的那支笔：它原来在旧板配色里是第几支，就换成新板的第几支。
   - **板上已有的每一笔**：同理按序号平移（旧色不在旧板配色里就不动）。
   代价说清楚：切换时整幅图会换一次颜色。但位置、形状、粗细一律不动，而且不这么做的话，切到黑板就等于把原来的推导弄没了。
4. 颜色面板（`#wb-colors`）按新的一套重建，当前色仍高亮。
5. 写进存储，刷新后还在。

## 4. 数据与存储

沿用项目既有规矩：`wkmath.*` 命名 + 版本后缀。**不新增键**，都并进白板主键 `wkmath.whiteboard.v1`：

| 字段 | 内容 |
| --- | --- |
| `theme` | `'white'` / `'mid'` / `'dark'`，默认 `'white'` |
| `shotRatio` | 上次用的导出比例 `'16:9'` / `'4:3'` / `'free'`，默认 `'16:9'` |
| `shotInclude` | 导出带不带分析 / 答案：`{ analysis: false, answer: false }`，默认都不带 |

**不写入的：** 导出的图片二进制（它只存在于预览里，用户点「保存」才落到磁盘）、裁切框、输出尺寸。

**恢复要容错：** `theme` 不在三套里就回落 `'white'`；`shotRatio` 不在三档里就回落 `'16:9'`；`shotInclude` 不是对象、或字段不是布尔，就回落 `false`。旧数据没有这些字段就是默认值。

## 5. 模拟与真实的分界

这四项**全部是真的功能**，没有预置假数据：

- 把手的两道短横：真画。
- toast 位置：真 CSS。
- 导出：真渲染、真生成 PNG、真下载。
- 板面主题：真配色、真持久化。

唯一"验不到"的是**导出的像素内容**：断言桩里没有 2D 上下文（`document.createElement('canvas')` 返回的是 DOM 桩，没有 `getContext`），所以自动化只能守住**几何**（`exportPlan`）与**文件名**（`exportFilename`），以及"没有 2D 上下文时优雅返回 null 而不是抛错"。**真正的图对不对，我在真机页面上导一张出来看**，并把结果记进计划文档 —— 和上一轮量"绘制瞬间用的变换"同一个做法。

## 6. 不做什么

| 不做 | 原因 |
| --- | --- |
| 把屏幕上的台阶框 / 答案块**像素级照抄**进导出图 | 它们是 DOM 浮层、还能在里面写字，画布拿不到。改成用同一份数据**重新排版**（决定 #13）—— 而且整齐的排版比照抄屏幕更适合交出去 |
| 导出图里保留台阶框在屏幕上的**自由摆位** | 那是"工作台"的状态，不是文档该有的样子。右栏统一竖排 |
| 导出 GIF / 录屏 | 另一个功能，本次不提 |
| 自定义板面色 / 自定义主题 | 三套够用；开放色值就要开放对比度校验，YAGNI |
| 导出加页码 / 水印 / 边框 | 不知道谁要，先不做 |
| 导出绑快捷键 | `⌘S` 是浏览器的"保存网页"，抢过来是坏事 |
| 导出分辨率可调 | 参数越多越没人调；先固定长边 1600px |
| 全站抬 toast | 别的页面底部没有工具条，抬高了反而怪 |

## 7. 验收

- 题面悬停时**不再有通高竖条**；只剩"浅底 + 两道短横"，填充次数恰为 **3**（断言改掉旧的 4）。
- 白板页 toast 底边与工具条顶边的**间隙 ≥ 8px**（体检脚本从 CSS 算出，不是目测）。
- `exportPlan` 的几何：16:9 档输出恰好 1600×900；4:3 档 1600×1200；内容在板面区内**居中**（四边留白之差 < 1px）；留白不小于 8%；"按内容"档不补边且板面区比例等于内容比例。
- `inkBounds()`：板上没内容时返回 **null**；有笔迹 / 有题面时返回真实范围。**特别守住不能退化成 `contentBounds()`** —— 后者写死了 720×120 的默认区，永远不空（断言：空板上 `inkBounds()` 为 null，而 `contentBounds()` 不为空）。
- 勾上分析 / 答案后：输出宽高**变大**（多了右栏）；板面区右边界 < 右栏区左边界（两栏不重叠）。
- `exportPanelLines()`：勾「带分析」时含全部台阶引导语；台阶里学生写的内容**跟着出现**（写过才出现）；勾「带答案」时含答案文本；**关掉注释时不含注释文本**。
- **勾选与屏幕开合解耦**：`state.analysis.open === false`（没点开分析）时勾上「带分析」，右栏照样有内容。
- `exportFilename`：带来源与日期，且把来源里的 `·` `/` 空格清成 `-`；没有来源时回落成 `白板`。
- 环境里没有 2D 上下文时，`exportImage()` **返回 null 而不是抛错**（优雅降级）。
- 三套主题**字段齐全**（板面色 / 网格 / 题面四色 / 六支笔 / 荧光透明度），少一个字段就报错。
- 换板后：当前笔色与**板上已有的每一笔**都按**序号**平移到新板的同一支；旧色不在旧板配色里的保持不变。
- 换板**只动颜色**：笔迹的点坐标、粗细、图形类型一律不变（断言：换板前后笔迹的点数与坐标逐一相等）。
- 换板后**板面色真的被画进了画布**（不是靠 CSS 白底）—— 这条是导出能带背景色的前提。
- 主题与导出比例**写进存储并能容错恢复**：非法值回落默认，不抛错。
- 工具条槽位 ≤ 14、自绘提示总数 = 15（体检里的两个上限同步更新并写明原因）。
- **全套自检保持全绿**（当前基线：19 个断言包 / 676 条断言）。
- **真机验证：** 导出一张 16:9 的 PNG，检查（a）不带工具条与任何面板，（b）题面与笔迹完整，（c）四边有留白，（d）补边色是板面色而非白边，（e）切到黑板后再导一张，背景是深色、题面字是浅色、笔迹看得清，（f）**勾上「带分析」+「带答案」再导一张**：右栏出现、编号台阶齐全、学生在台阶里写的那句话在里面、答案与注释按当前开关显示、两栏不重叠、右栏配色跟着板面走。
