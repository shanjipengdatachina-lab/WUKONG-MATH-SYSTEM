# 白板：手写转文字 + 分步点评 · 设计

日期：2026-09-28
状态：已与用户确认（用户回复「定了 你搞吧」；三个判断点里两个选了推荐项，另一项改为用户原意）
相关文件：`whiteboard.html`、`assets/js/whiteboard.js`、`assets/js/whiteboard-ink-text.js`（新）、
`tools/checks/wb-harness-*.js`、`tools/checks/verify_whiteboard.rb`

## 1. 背景与用户原话

> 「用户在白板里写的题目的解题思路；题目右边可以再设置一个按钮，点击后 AI 自动识别写的，
> 转换为电子文字；挂在题目下面；并 AI 自动标记出……」
> 追问后用户补齐：「意思是用户手写的东西，后期加上 AI 可以识别，然后识别的手写的题目可以自动加在
> 题目下方；然后 AI 也会针对用户每个解题步骤进行分析和评价」

**先说清一件硬事实**：这站没有 AI，也没有后台 —— 整个 JS 层零网络请求，页面双击就能离线打开。
手写识别（OCR）必须有模型。白板本身已经处理过同类问题（`whiteboard-analysis.js` 的文件头写着
「本版不接真 AI」），所以这里照同一套做法：**界面全部真做，结果先用预置，读取收成可替换的函数**。

用户三个判断点的回答：

1. **AI 这版怎么落地**：界面全做，结果先用预置（界面上如实标明这是演示）
2. **识别哪些笔迹**：只认题面框以外的
3. **标记什么**：切成步骤 + **每步分别分析与评价**（用户补齐的那句）

## 2. 决定

| # | 决定 | 理由 |
| --- | --- | --- |
| 1 | 题面右边第三个按钮「**转文字**」（`#wb-act-transcribe`） | 用户明确要求；与「分析 / 答案」同一套落位与激活态 |
| 2 | 结果面板挂在**题目下方**，与后面的「台阶框 / 答案块」共用一张"往下排"的登记表 | 三块都往下挂，各算各的必然会互相压；先立规矩，后面两块直接挂进来 |
| 3 | 只认**题面框以外**的笔迹（采样点过半在框外才算） | 题面上的笔迹多半是"圈已知条件"，混进去会把识别结果带脏。工具种类不参与判断 |
| 4 | **题面外一笔都没有就不装** | 不许凭空变出一段用户没写过的字 —— 那比不做更糟 |
| 5 | 有内容时挂「**演示**」标 + 一句明话 | 预置数据不是真识别，必须说清 |
| 6 | 每步 = **可编辑的文字** + 语气标 + 一条点评 | 识别一定会出错，改不了就是坏产品；只转文字不点评就少了一半 |
| 7 | 语气标只有三种：成立 / 可以更严谨 / 这一步有问题 | 与图谱的 tone 语言一致 |
| 8 | **预置数据里不出现「这一步有问题」** | 没有真模型就不判学生对错。语气标支持它，数据里不用 |
| 9 | 内容与界面分两个文件：`whiteboard-ink-text.js`（数据 + 两个可替换函数）/ `whiteboard.js`（界面） | 接真服务时只换 `recognize()` 与 `review()` |
| 10 | 按**题目 id** 存本机，与笔迹分开存 | 换题不串台；「清空画布」只清笔迹，不动已转出的文字 |
| 11 | 输入过程中**不重画面板** | 重画会重建 DOM、光标就断了（正打字时最烦人的那种 bug） |
| 12 | 面板上两个动作：「重新识别」（覆盖）与「移除」（删这一题的记录） | 用户要能重来、能删掉 |
| 13 | 样式写在 `#wb-page-styles`（共享区之外） | `wb-styles` 会被抄到图谱当死规则 |

## 3. 数据形状

```js
// 界面内部（state.ink.steps）与本地存储都是这个形状
[ { text: '第几步写了什么', tone: 'ok' | 'careful' | 'warn', comment: '这一步的点评' } ]
```

存储键：`wkmath.whiteboard.inktext` = `{ '7a-01': { steps: [...] }, ... }`（按题目 id 分开）。

## 4. 界面

```
#wb-acts（题面右上角）          分析 / 答案 / 转文字
#wb-ink-text（题目下方，默认 hidden）
├─ 标题「手写转文字」 + 「演示」标 + 收起
├─ 一句说明（#wb-ink-note）
├─ 步骤列表（#wb-ink-steps）  第 k 步 / contenteditable 文字 / 语气标 + 点评
└─ 重新识别 / 移除
```

## 5. 验收

| 层面 | 守什么 |
| --- | --- |
| 范围判定 | 全在框内 / 全在框外 / 正好一半 / 过半在框外 四种情况判得对；框无效时一律不收 |
| 没写东西 | 框外零笔迹 → 不给内容、只给一句实话、不挂演示标、不显示动作按钮 |
| 有内容 | 每一步都有文字 + 语气标 + 点评；语气标取值在三种里；演示标与说明都在；文字格可编辑 |
| 落位 | 面板在题目下方（按世界坐标算，不写死坐标）；题面右移面板跟着走；题面收起一起收起 |
| 编辑 | 走真实路径改字（input 事件）→ 立刻落盘 → 重绘后还在 |
| 不串台 | 按题目 id 分开存；换题显示那一题的；收起状态下换题面板不自己弹出 |
| 重来与移除 | 重新识别覆盖；移除删记录但不动画布 |
| 容错 | 存的不是 JSON / 语气标认不出 / 空步骤 → 一律当"没转过"，不崩 |
| 清空画布 | 只清笔迹，已转出的文字保留 |
| 体检 | 九个挂点齐、面板默认收起、演示标与说明在、样式不在共享区、数据模块被引用且文件头写明"不接真 AI"、预置数据里不得出现 warn |

## 6. 刻意不做的

- 不接真 AI、不做真 OCR；不给模型调用留 URL 或密钥位。
- 不判学生对错（没有真模型时的"批改"必然是假的）。
- 不在体系里做"识别整板"（只认题面外的笔迹，用户的选择）。
- 不做识别置信度 / 原文对照（没有真识别，谈不上置信度）。
