## 1. 要解决的问题

1. **题面现在是一张卡片**：有边框、宽度固定，题目短也占满一整条，四周空白被框吃掉了。板面是演算的地方，这些空白本该还给学生。
2. **题目和"对题目做的动作"是散的**：想分析、想看答案，得离开题面去找按钮。
3. **手机上拍的题进不来**：学生做作业时遇到的题在纸上、在手机相册里，进不到白板上。

## 2. 设计决定

| # | 决定 | 为什么 |
| --- | --- | --- |
| 1 | 题面由「卡片」改为**「底纹」**：无边框、浅色衬底、直接印在板上、可拖动 | 卡片有边界和固定宽度，边界要吃掉四周空白。底纹没有边界 —— 板面全还给演算。既然是印上去的、透明的，它就能被拖 |
| 1b | 拖动靠**左侧那一条无字把手**（悬停才现身的两道短横），**题面正文上照常落笔** | 执行时被老断言挡下来的一个真问题：一开始做成"按住题面任意处即拖动"，结果画布的左上角 >1.5 倍缩放后正落在题面里，正文上**再也画不了线**。而"在题目上圈已知条件、划关键词"是学生最常用的动作 —— 为了一个拖动手势把它禁掉，代价太大。把手只压在无字的左侧条上：想挪就抓它，想圈画就直接画 |
| 2 | 题面旁跟**两个很轻的按钮**：`分析` / `答案` | 两个动作心思完全不同：分析给台阶不给答案（保护"我想自己推完"的动机），答案给结果（用来对着改）。合成一个按钮就废了 |
| 3 | 「分析」产出 **1～5 个步骤框**，一步一框 | 框本身就是那一级台阶 |
| 4 | 步骤框**可拖动、可在框里写字** | 这个功能的重心不是"看 AI 讲题"，而是**在台阶上自己推**：在框里推，推不动再看下一框 |
| 5 | 步骤框**浮在板上、跟着板走** | 它不是一份"阅读材料"，是板面上的工作区，要能和题面、和自己的演算并排放 |
| 6 | 「分析」**不给答案**，答案只在「答案」按钮里 | 同上：给了答案，前面几级台阶就没人走了 |
| 7 | 「答案」标在题目下方，重点处带注释；一个小开关切 **`显示注释` / `干净答案`** | 第一遍要干净结论，复盘时才要"为什么这么想、这里易错在哪" |
| 8 | 上传图片按钮放**工具条正中间** | 左边是"怎么画"（画笔 / 图形），右边是"看什么"（题面 / 题库 / 设置），上传是"往板上进料"，夹在中间正好分界 |
| 9 | **只存文字，不存图片** | 照片在本地识别成题面文字后，图片本身不留 —— 否则存储压力会失控 |
| 10 | 题库标签行新增 **`我的题`** | 上传过的题要有归处。与「全部 / 七上 / …」并排，三个字，不突兀 |
| 11 | **`我的题` 是来源，册与知识点是归属** | AI 判定这道题属于哪个知识点后，它同时也能在「八上」这些标签下被筛到。两条进入路径不打架 —— 「我的题」不会变成一个进得去出不来的孤岛 |
| 12 | 手机拍照上传、跨设备中转**不在本版** | 需要服务端 + 小程序/APP，是一道架构分水岭，先不碰 |

## 3. 界面细节

### 3.1 题面

- 位置：板面，按**世界坐标**绘制（跟现在一致，跟随缩放与平移）
- 视觉：浅色衬底（`--math-primary-tint` 一类），**无边框**，正文用次级文字色，不抢演算的注意力
- 交互：抓住题面**左侧那条无字把手**（约 24 世界单位宽、通高；悬停时显出两道短横、光标变 可抓）可拖动；题面**正文上照常落笔**（圈已知条件 / 划关键词）；拖动时**不带动板面**（与 §4.6 浮层事件隔离同一条规矩）
- 按钮：`分析` `答案` 紧跟在题面旁，样式很轻；不点它们时，板面就是一块干净的白板

### 3.2 分析与答案

- 点 `分析` → 步骤框依次浮出（1…5），每框一行引导语，**只有"该往哪儿看"，没有答案**
- 点 `答案` → 答案块标在题目下方（左侧一条主色竖线标识），重点处给注释
- 注释开关：`显示注释` / `干净答案` 两态，默认展示注释

### 3.3 上传与「我的题」

- 工具条正中间一个 `上传图片` 按钮，点开系统文件选择框
- 选完 → 照片落到板面上（**本次会话内**可见、可拖动），随即触发识别
- 识别完成 → 识别出的**题面文字**印成底纹，与照片在本次会话里并存（可以对照"拍歪了没有"）
- 上传过的题进入题库的 `我的题` 标签下

## 4. 数据与存储

### 4.1 新增的键

沿用项目既有规矩：`wkmath.*` 命名 + 版本后缀。

| 键 | 内容 |
| --- | --- |
| `wkmath.whiteboard.uploads.v1` | 上传过的题：识别出的题面文字 + 元信息（上传时间、AI 判定的知识点） |

（白板现有的主存储键是 `wkmath.whiteboard.v1`，所以上传这个键跟着同一个前缀走。）

**不写入的**：图片二进制、图片缩略图。

### 4.2 「只存文字」连带的行为（要提前知道）

- 照片只在**当前这次会话**里显示在板上
- 刷新页面后，照片消失，**题面文字仍在**（因为它已存进上面的键）
- 这是"省存储"的必然代价，不是 bug

## 5. 模拟与真实的分界

本版**不接真 AI**。以下是真的：上传、落板、识别中的状态、题面底纹、步骤框的浮出与拖动、答案与注释的切换、写入 `我的题`。

以下**是预置的假数据**：识别出的题面文字、分步引导语、标准答案、注释文字。

接入真服务时，**只换"识别 + 分析"这一个调用点**，界面层完全不动 —— 所以这份设计不会因为换模型而返工。

## 7. 验收

- 题面**不再有边框**，且宽度**随内容自适应**（不是固定宽度）
- 拖题面时板面**纹丝不动**（新增断言，与 §4.6 同源）
- `分析` 出的框里**不含答案**（断言：分析块文本里不出现答案字段）
- `答案` 的注释开关两态可切，且默认是"显示注释"
- `我的题` 标签存在，且与其它册标签**可叠加筛选**（选了「我的题」再选「八上」要有结果）
- **不写图片二进制进 localStorage**：断言上传一道题后的存储增量 **< 20 KB**（题面文字的量级）。参照系 —— 一张手机照片转 base64 通常 > 200 KB，差一个数量级
- 全套自检保持全绿（当前 629 条断言基线）
