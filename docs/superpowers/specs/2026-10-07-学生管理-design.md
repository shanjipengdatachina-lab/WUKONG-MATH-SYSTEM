# 学生管理 · 设计稿（2026-10-07）

用户原话：

> 增加学生管理模块；需要完善一些；比如小学 中学 高中 奥赛分开管理；各自的班级和管理老师；
> 每个人的各自学习情况；考试情况；成长曲线，学习曲线，习题量等等；模块的统计和管理要完善，
> 详细到我们目前的系统的学习资料都匹配。

---

## 1. 现状（2026-10-07 逐条核过的，不是猜的）

| 要的东西 | 现在有什么 | 缺口 |
| --- | --- | --- |
| 小学 / 初中 / 高中 / 奥赛分开 | 知识树上 `book`/`track` 带 `stage`：**primary 12 册 · junior 6 册 · senior 5 册 · olympiad 4 条轨道**，资料侧是齐的 | 学生侧没有学段 |
| 按学段管学生 | `User` 上只有一个**自由文本** `grade`（`七年级（下）` / `五年级（上）` / `高一 · 必修一`） | 没有 `stage`，文本没法可靠分组 |
| 班级 / 管理老师 | **全仓零痕迹**（搜 `班级`/`班主任`/`teacher`/`homeroom` 无命中） | 从零建 |
| 学习情况 | `LearningRecord` 每人 **769 格**（mastery 0~100 / 六档 status / `learnedAt`）；`LearningEvent` **4153 条**（带 `at` 时间戳 + `mastery`） | 有数据，但只有 `/admin/users/:id/overview` 那几个静态计数 |
| 考试情况 | `Exam` 15 场 + `ExamPaper` **812 道卷面题**（逐题 `score/full/causes`） | 只在学生详情里列一张表 |
| 成长曲线（掌握度随时间） | 原始数据**有**（`LearningEvent.at + mastery`） | **没有任何聚合接口** |
| 学习曲线（累计完成 vs 计划） | `timeline-3d.js` 前端按 14 天分桶现算，**默认还关着** | 服务端没有；后台看不到 |
| 习题量 | `PracticeSession(total/correct/submittedAt)` + `PracticeAnswer(given/correct)` 表结构完备 | **seed 里 0 次练习会话**，全站只有 **4 道**可判分题 → 指标恒为 0 |

另外两处「有数据没接上」：学生端 `report.html`（学习报告）**整页是写死的假数字**，
没接任何接口；`LearningRecord.factors`（五因素 acc/solo/gap/speed/err）schema 注释写着
「给雷达图整块读出来用」，但**从来没有画出来过**。

## 2. 目标与非目标

**做**：学段归属 · 班级与班主任 · 老师登录后只看自己班 · 学习/考试/曲线/习题量的统计接口 ·

**不做**（这一轮明确不碰）：题库扩容（那是从资料里出题，另一个活）· 家长的账号 ·
排课/作业/通知 · 学生端新增页面（只改 `report.html` 与既有两个详情页）。

## 3. 数据模型

### 3.1 学段落到 User 上

`User` 加两个字段：

```prisma
/// primary | junior | senior | olympiad —— 与 Node.stage 同一套取值，别发明第二套
stage String? @db.VarChar(16)
/// 班级。一个学生一个班（见 §3.2）
classId Int?
class   Class? @relation(fields: [classId], references: [id], onDelete: SetNull)
```

`onDelete: SetNull` 而不是 Cascade：**删班不该把学生一起删掉**。班没了，人是还在的。

`grade` **保留**（`七年级（下）` 这种更细的信息仍然要显示），但**不再承担分组的职责** ——
分组一律看 `stage`。回填时从 `grade` 文本推一次：

| grade 开头 | stage |
| --- | --- |
| 一~六年级 | `primary` |
| 七~九年级 | `junior` |
| 高一 / 高二 / 高三 / 必修* / 选择性必修* | `senior` |
| 竞赛 / 奥赛 / 轨道名 | `olympiad` |

推不出来的**留空**，不瞎猜 —— 留空的人在后台「未分学段」那一栏里，等人来指。

### 3.2 班级

```prisma
/// 一个教学班。**按学段分栏管理**（小学/初中/高中/奥赛），所以 stage 是它的一等字段。
model Class {
  id      Int     @id @default(autoincrement())
  name    String  @db.VarChar(64)          // 例如「五年级（上）· 周三班」
  /// primary | junior | senior | olympiad
  stage   String  @db.VarChar(16)
  /// 年级，例如 五年级（上）/ 七年级（下）；奥赛班可以只写阶段
  grade   String? @db.VarChar(64)

  /// 班主任。老师是 User（role=teacher），所以这里指 User 而不是另建一张表
  teacherId Int?
  teacher   User? @relation("ClassTeacher", fields: [teacherId], references: [id], onDelete: SetNull)

  /// 备注（上课时间、教材版本这类）
  note   String? @db.VarChar(5000)
  order  Int     @default(0)
  active Boolean @default(true)

  students User[] @relation("ClassStudents")
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([stage, order])
  @@map("class")
}
```

**一个学生一个班**：`User.classId` 一个字段，不建中间表。理由：真实里学生就在一个教学班，
而"同时进数学班和奥赛班"一旦允许，花名册/平均分/进度每个数都要先问"算哪个班的" ——
那点灵活性换不来这份复杂度。

**班主任是指向 `User` 的引用，不是老师表**。老师要么是能登录的教师账号（见 §4），
要么是还没开通账号的人 —— 后者这一轮不支持，需要先建账号。

### 3.3 演示练习数据（补习题量）

新增 `seed/practice-sessions.json`：给三位演示学生各造 **20 次练习会话**（分布在近 90 天，
题在现有 4 道可判分题 + 58 道白板题里抽，正确的题造 `correct=true`）。
导入器写进 `PracticeSession` + `PracticeAnswer`。

为什么造：习题量/正确率这两个指标，**表结构是完备的，只是从来没有数据**。
不造的话整块指标恒为 0，界面上只能看到一片空 —— 那样连"接口算得对不对"都验不了。
**造的数据必须在种子文件里写明是演示数据**，并且导入脚本要在日志里说明这一批是造的。

## 4. 角色与权限

新增角色 **`teacher`**（教师）与三个权限点：

| 权限点 | 给谁 | 管什么 |
| --- | --- | --- |
| `class.read` | admin · teacher | 看班级、看**自己班**的学生与统计 |
| `class.write` | admin | 建/改/删班级、调学生进班、设班主任 |
| `student.read` | admin · teacher | 看学生详情与成长曲线（**teacher 只能看自己班的**） |

**teacher 的边界必须在服务端**：不是"前端藏了别的班"，而是接口按 `User.classId === 老师带班` 过滤。
判定放在一处辅助函数里（`teacherScopeOf(user)` → 允许的 classId 列表），所有 teacher 可访问的
接口都过它。admin 不受限（`class.write` 只在 admin 上）。

为什么不让 `class.write` 给 teacher：老师能建班就能把自己塞进任何班，那"只看自己班"就成了一句空话。

## 5. 接口

### 5.1 学段与班级（管理端）

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/admin/stages` | `class.read` | 四个学段 + 各自的班级数/学生数（后台分栏用） |
| GET | `/admin/classes?stage=&q=` | `class.read` | 班级列表（teacher 只回自己带的） |
| POST | `/admin/classes` | `class.write` | 建班 |
| PATCH | `/admin/classes/:id` | `class.write` | 改名/学段/年级/班主任/备注/排序 |
| DELETE | `/admin/classes/:id` | `class.write` | 删班（学生 `classId` 置空，**不删人**） |
| GET | `/admin/classes/:id` | `class.read` | 班级详情：花名册（每人核心指标）+ 班级汇总 |
| POST | `/admin/classes/:id/students` | `class.write` | 批量调学生进班 `{userIds: []}` |
| DELETE | `/admin/classes/:id/students/:userId` | `class.write` | 把某人移出班 |
| GET | `/admin/classes/:id/roster.csv` | `class.read` | 花名册导出 |

### 5.2 统计（模块核心）

**统一原则：曲线一律由服务端算好，返回分好桶的数组，前端不自己聚合。**
（和 `/admin/finance/summary` 同一套路数与同一个理由：dev 跑 SQLite、prod 跑 MySQL，
`strftime` 与 `DATE_FORMAT` 不是一回事，写 raw SQL 就得维护两套；先在 JS 里聚合。）

| 方法 | 路径 | 权限 | 返回 |
| --- | --- | --- | --- |
| GET | `/admin/stats/overview?stage=&classId=` | `class.read` | 人数 / 已学格数 / 平均掌握度 / 考试场次 / 平均得分率 / 错题数 / 习题量 |
| GET | `/admin/students/:id/growth?granularity=week\|month&from=&to=` | `student.read` | 见下 |

`/admin/students/:id/growth` 一次给五块（拆成五个接口的话，页面会出五个各自转圈的方块）：

```jsonc
{
  "student": { "id": 143, "nickname": "林一鸣", "stage": "junior", "classId": 3, "className": "…" },
  // ① 成长曲线：掌握度随时间的推进（来自 LearningEvent.at + mastery，按周/月取当期末值）
  "growth":  { "buckets": [{ "key": "2020-W36", "masteryAvg": 42, "events": 3 }] },
  // ② 学习曲线：累计已学格数 vs 计划（照 timeline-3d 那套口径，挪到服务端）
  "progress":{ "buckets": [{ "key": "2020-09-14", "done": 12, "plan": 18 }], "total": 769 },
  // ③ 成绩曲线：每场考试的得分率
  "scores":  [{ "code": "E1", "name": "…", "date": "2020-09-30", "score": 82, "full": 100, "rate": 0.82 }],
  // ④ 习题量：练习次数 / 题数 / 正确率（没有就说没有，不拿 0 顶替）
  "practice":{ "sessions": 20, "questions": 100, "correct": 78, "accuracy": 0.78, "lastAt": "…" },
  // ⑤ 薄弱点：错题 + 切片框出的知识点，按章汇总（直接对上知识树）
  "weak": { "byChapter": [{ "nodeId": 12, "name": "有理数", "mistakes": 3, "boxes": 2 }] }
}
```

**"没有数据"与"数据是 0"必须分开**：`practice` 一次都没练过时回 `sessions: 0, accuracy: null`，
前端显示「暂无练习数据」，不是「正确率 0%」。这和切片报告「不拿 0 顶替」是同一条规矩。

### 5.3 老师登录后的可见范围

`teacher` 走的是同一批接口，但服务端按 `teacherScopeOf()` 过滤：
`/admin/classes` 只回自己带的班；`/admin/classes/:id` 与 `/admin/students/:id/growth`
在 id 不在自己范围内时回 **404**（不是 403 —— 403 等于告诉对方"这个 id 存在，只是不给你看"，
那就是一个班级/学生的探测器）。

## 6. 界面

**后台新增**
- **「班级」页**：按学段分四栏（小学/初中/高中/奥赛），每栏里是班级卡片（人数、平均掌握度、
  最近一次考试得分率）；卡片上直接改班主任、调学生；顶部可切换「只看我带的班」（老师视角）
- **「班级详情」页**：花名册表格（可排序：掌握度 / 已学格数 / 考试平均分 / 错题数 / 习题量）
  + 班级汇总条 + 每行点进学生详情；支持导出花名册
- **「学生详情」页升级**：现有七块之外，加三张曲线（成长 / 学习 / 成绩）+ 习题量 + 薄弱点

**学生端**
- `report.html`（学习报告）：现在是写死的假数字，改成读 `/me/profile` + 新的
  `GET /me/growth`（学生看自己的，同一套算法）。**这条必须做** —— 一页假数字比空着更糟，
  会有人拿它对账。

曲线图仍然**不引图表库**：后台用纯 CSS/SVG 画（和财务页那个柱状图一致），
学生端沿用 `timeline-3d.js` 已经有的 canvas 画法。

## 7. 分期与验收

| 期 | 内容 | 验收点 |
| --- | --- | --- |
| **S1** | `stage`/`Class`/`classId` 建模 + 回填 + teacher 角色与权限点 + 班级 CRUD + `/admin/stages` | 后台能按四个学段分栏建班、班主任能设；学生详情能显示学段与班级；老师登录只看得到自己班（404 边界验到） |
| **S2** | 统计接口：`/admin/stats/overview`、`/admin/classes/:id`、`/admin/students/:id/growth` + 演示练习数据 | curl 逐条验：桶数与实际数据对得上；"无数据"与"0"分得开；teacher 越界 404 |
| **S3** | 后台「班级」页 + 「班级详情」页 + 「学生详情」加曲线 | 真浏览器：建班 → 调人 → 看花名册 → 点进学生看三条曲线；老师视角只看到自己班 |
| **S4** | 学生端 `report.html` 接真接口 + `GET /me/growth` | 真浏览器：报告页数字与后台学生详情**同源同值**（同一套算法，不是两套） |

**S4 那条"同源同值"是硬要求**：`sliceReport()` 的教训 —— 两套算法迟早给出两个
"平均得分率"，老师照着哪个数说话都可能是错的。所以 `/me/growth` 与
`/admin/students/:id/growth` 共用同一个 service 函数，只是一个把 userId 从 cookie 取、
另一个从路径取。

## 8. 已知缺口（如实记，不装作有）

1. **习题量这一轮是演示数据**。题库只有 4 道可判分题，学生的真实练习量无从产生。
   演示数据能验证"接口算得对"，但**不能当成真数据看**。
2. **奥赛学段没有"年级"的概念**（树里是 4 条轨道，不是年级）。奥赛班的 `grade` 允许留空，
   统计里按"轨道覆盖的章节"来对齐学习资料，不硬凑一个年级。
3. **老师的范围只有"自己带的班"这一个维度**。没有教研组/年级组/多班老师那套。
4. **成长曲线按"期末值"取桶**：一周内有多次掌握度变化时，取这一周最后一次的值，
   不做插值。日粒度太碎（事件是突发式的），周/月才是能看的。
