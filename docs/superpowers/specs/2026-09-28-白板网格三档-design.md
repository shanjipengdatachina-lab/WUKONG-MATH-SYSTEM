# 白板网格三档（小 / 中 / 大）· 设计

日期：2026-09-28
状态：已与用户确认（用户回复「定了 你搞吧」）
相关文件：`assets/js/whiteboard.js`、`whiteboard.html`、`tools/checks/wb-harness-tail.js`、`tools/checks/verify_whiteboard.rb`

---

## 1. 背景

白板现在只有**一档**网格：格子基数写死 40 个世界单位，画的时候还会随缩放自动翻倍 / 减半
（`drawGrid()` 里那两条 `while`），让屏幕上的格子始终落在 14～96 像素之间 —— 所以放大缩小
格子既不会糊成一片，也不会疏得看不出参照。

用户要求：网格可以选**大 / 中 / 小**三档，入口放在设置浮层里。

## 2. 决定

| # | 决定 | 理由 |
| --- | --- | --- |
| 1 | 三档 = 小 20 / 中 40 / 大 80（世界单位），**中档即今天这一档** | 默认观感一点不变；小二倍、大两倍，100% 下一眼看得出差别 |
| 2 | 默认中档（40） | 同上，等于不改变现有体验 |
| 3 | 在设置浮层里加一行「网格」，位置在「板面」之后 | 板面与网格都是"板长什么样"，排在一起 |
| 4 | 点某一档时**顺手把网格打开** | 网格关着时选一档却什么都没变，会被当成"没生效"。与既有习惯一致：正在用橡皮时点颜色会自动切回画笔 |
| 5 | 工具条那个网格按钮仍是纯开关，但提示气泡跟上当前档：「网格 · 中 G」 | 不点开设置也知道现在是哪档 |
| 6 | `drawGrid()` 里那两条疏密修正**一字不改**，只把基数从写死的 40 换成 `state.gridSize` | 三档只换基数，"格子始终看得清"这条保证对三档一视同仁 |
| 7 | 三档在极端缩放下会趋于同一疏密，**如实写进界面**，不做假 | 数学上躲不掉：要保证格子落在有限的可读区间里，任何两档总会在某个缩放撞上。为"永远不同"把格子画到 7px 是更坏的选择 |
| 8 | 样式写在 `#wb-page-styles`（共享区之外），与 `.wb-theme` 放一起 | `wb-styles` 会被 `tools/build_graph_css.rb` 抄进图谱当死规则 |
| 9 | 不新增快捷键 | 疏密是低频设置，不值得占一个键 |
| 10 | 疏密与板面主题互不影响：换板只换格子**颜色**，不动疏密 | 两件事正交 |

## 3. 数据与接口

```js
var GRID_SIZES = [
  { value: 20, label: '小' },
  { value: 40, label: '中' },
  { value: 80, label: '大' }
];
state.gridSize = 40;          // 默认中档
```

- 落盘：与 `grid` 一起进 `STORE_KEY`，字段名 `gridSize`。
- 恢复：值必须是 `GRID_SIZES` 里那三个之一，否则**回落 40**（不崩、不画出奇怪格子）。
- 挂到测试接口：`__WB__.config.GRID_SIZES`、`__WB__.setGridSize`、`__WB__.gridSizes`。
  断言从梯子里读数，不写死 20 / 40 / 80。

## 4. 界面

设置浮层里新增一行：

```html
<div class="wb-pop__row">
  <span class="wb-pop__label">网格</span>
  <div class="wb-grids" id="wb-grids" role="group" aria-label="网格疏密"></div>
</div>
```

按钮由 `buildPickers()` 生成，每个按钮里带一个 14×14 的**疏密预览方块**（用两条 repeating 渐变
画格子，小档最密、大档最疏），按钮类名 `.wb-grid` + `.wb-grid__chip`，属性 `data-wb-grid="20|40|80"`。
样式与 `.wb-theme` 同族，写在 `#wb-page-styles`：

```css
.wb-grids{display:flex;gap:6px}
.wb-grid{ /* 与 .wb-theme 同一套外形 */ }
.wb-grid[data-wb-grid="20"] .wb-grid__chip{background-size:4px 4px}
.wb-grid[data-wb-grid="40"] .wb-grid__chip{background-size:6px 6px}
.wb-grid[data-wb-grid="80"] .wb-grid__chip{background-size:9px 9px}
```

点一档 → `setGridSize(v)`：校验在梯子里 → 写 `state.gridSize` → **打开网格** → `redraw()` → `persist()` → `syncUI()`。
`syncUI()` 里把当前档标上 `aria-pressed` 与 `is-on`（两个都要，前者给读屏、后者给眼睛）。

## 5. 边界与容错

- 存了个不在梯子里的值（如 55）→ 回落 40。
- 没有 `#wb-grids` 元素时（老页面缓存）→ `buildPickers()` 跳过，不报错。
- 网格关着时改疏密 → 网格被打开，并给一次 toast 说明（`网格 · 中`），让"顺手打开"这件事有反馈。
- 板面切到黑板：格子颜色跟着变（走 `theme().grid`），疏密不动。

## 6. 验收

| 层面 | 守什么 |
| --- | --- |
| 梯子 | 就是 20 / 40 / 80；默认中档；点小档 → 20、大档 → 80 |
| 真的画了 | 100% 缩放下，量画布上相邻两条线的**实际间距**是 20 / 40 / 80 像素（量画出来的线，不是量状态里的数） |
| 疏密保证 | 缩放从 0.15 拉到 8，三档实际间距始终落在 14～96 像素内 |
| 开关联动 | 网格关着时点一档 → 网格变开；且"顺手打开"只发生在选疏密时（点颜色 / 笔粗不会把网格带开） |
| 落盘 | `gridSize` 写进本地存储、刷新能恢复；存个垃圾值（55）→ 回落 40 |
| 体检 | `#wb-grids` 三档齐；数值与 js 里梯子一致；三条预览方块的 CSS 都在且方向没写反（20 那档格子最小）；样式不在共享区 |
| 真机 | 三档在一百%下肉眼可辨；设置浮层多一行后在矮窗口（约 700px）下打开，面板顶端不超出可视区 |

## 7. 刻意不做的

- 不做"网格步长随意输入"（低频需求，且会和疏密修正打架）。
- 不给网格疏密绑快捷键。
- 不做疏密随板面主题联动（两件事正交）。
- 不为"三档永远不同"改动那条疏密修正（见 §2 #7）。
