# 阅读与显示设置 · 字号方案 + 亮/中/暗配色

日期：2026-09-28
状态：已与用户确认决策，待实施

---

## 1. 为什么做

用户原话：**「我们的文字有点细，怕孩子会看不清；可以设置一下，有个字号方案；还要在设置里有个亮色、中色、暗色的设置按钮，避免眼睛有问题。」**

拆成三件事：

1. **字号可调** —— 孩子视力差异大，一个固定字号伺候不了所有人。
2. **亮 / 中 / 暗三档配色** —— 长时间看屏幕（尤其晚上）需要比纯白更柔的底，或者干脆深色。
3. **顺手修「太细」** —— 这是**对比度与字重**的问题，不只是大小。

第 3 条的证据（不是感觉）：

| 令牌 | 现值 | 在纯白底上的对比度 | 用在哪儿 |
| --- | --- | --- | --- |
| `--math-foreground` | `#101215` | 约 17:1 | 正文主色 —— 没问题 |
| `--math-ink-2` | `#5b6069` | 约 4.9:1 | 次级正文 —— 及格 |
| `--math-ink-3` | `#9ba1a9` | **约 2.6:1** | 说明文字、目录项、标签 —— **低于 4.5:1 的可读标准** |
| `--math-ink-4` | `#c4c8ce` | **约 1.7:1** | 空态说明、占位符、极次要信息 —— **几乎看不清** |

所以「怕孩子看不清」是**真问题**，主因是这两级灰太浅 + 中文在小字号下字重偏细。

## 2. 决策（用户已确认，逐条可核对）

| # | 决策 | 为什么 |
| --- | --- | --- |
| 1 | 字号做**三档**：标准 100% / 大 112% / 特大 125% | 三档和亮/中/暗对称；125% 是"明显变大但仍不破排版"的上限；再大就该动布局了 |
| 2 | 字号**作用于全站所有文字**（含侧栏、按钮、标签、题面、正文） | 用户选的是这个。只放大正文的话，视力弱的孩子看目录、按钮仍然吃力 |
| 3 | 亮 / 中 / 暗**管整站 + 白板板面** | 不这么做会出现"整站是暗的、一开白板被白板面闪一下" |
| 4 | 设置入口放在**账号设置页新增「阅读与显示」一节** | 用户指定「在设置里」；这里是全站唯一一处"调我自己"的地方 |
| 5 | 顺手把**字重提一档**（正文 400 → 500）+ **把 ink-3 / ink-4 加深** | 用户选的是这个。字重走令牌，一处改全站生效 |
| 6 | 配色用**「一整包」**的做法（每个主题把 `:root` 里的令牌全部重定义一遍） | 白板当初就踩过这个坑：只换底色不换字色，深色板上深色字直接消失。这条由体检脚本逐令牌比对守住 |
| 7 | 字号用**乘数令牌**（`--math-fs`），在**声明处**相乘，不改根字号 | 改根字号会连 `rem` 的间距一起放大 = 布局重排；而改动点只在 `font-size:` 处，边界清楚、可机械核对 |
| 8 | 设置**存在本机**（`localStorage`），首屏前应用 | 零构建、无后端；首屏前应用是必须的，否则会先白闪一下再变暗 |
| 9 | **白板板面开关 = 同一份设置**（在板里切，整站跟着切） | 两个开关写两份状态迟早打架。一个真值最省心：在白板里选"黑板"，设置页也显示"暗色" |

### 刻意不做

- **不引入 CSS 变量之外的主题机制**（如按 `prefers-color-scheme` 自动跟随系统）。用户要的是"我自己选"，自动跟随会与手动选择打架。跟着系统走这件事以后想加，再加一档「跟随系统」即可。
- **不做对比度超出三档的自定义**（比如"我要更黑"）。三档 + 字重/灰阶修正已经覆盖"看不清"，再加旋钮就是把设计权交给用户、把责任推给用户。
- **不改 `zoom` 或根字号**：`zoom` 会与白板的画布坐标（世界坐标 ↔ 屏幕像素）打架。

## 3. 技术方案

### 3.1 令牌层（`assets/css/tokens.css`）

```css
:root {
  --math-fs: 1;                     /* 字号乘数：只有显示设置会改它 */
  --math-weight-body: 500;          /* 正文默认字重（原来是浏览器默认 400） */
  /* ink-3 / ink-4 加深，见 §2 #5 */
}
html[data-fs="lg"] { --math-fs: 1.12; }
html[data-fs="xl"] { --math-fs: 1.25; }

/* 一整包配色：每个主题把 :root 的令牌全量重定义一遍（纪律见 §2 #6） */
html[data-theme="mid"] { … }
html[data-theme="dark"] { … }
```

`html[data-theme="light"]` 保持现状（`:root` 就是亮色），所以**不选任何设置的人看到的还是现在这一套** —— 唯一的差别是 ink-3 / ink-4 加深与字重提档（这两条是用户明确要的"修细"）。

### 3.2 字号乘数怎么落到 724 处

全站 `font-size` 的写法分布：**724 处 px、23 处 rem、38 处 clamp**，另有 3 处 em（相对值，不动）。

规则只有一条：**在"定义处"乘一次**。

| 位置 | 做法 |
| --- | --- |
| 页面样式里的字面量 `font-size:13px` | → `font-size:calc(13px * var(--math-fs))` |
| `font-size:1.125rem` | → `font-size:calc(1.125rem * var(--math-fs))` |
| `font-size:clamp(…, …, …)` | → `font-size:calc(clamp(…, …, …) * var(--math-fs))` |
| `--math-text-*` 令牌的定义处（tokens.css） | 同样乘一次 |
| 引用处 `font-size:var(--math-text-h1)` | **不动** —— 令牌已经乘过，再乘就是双重放大 |

机械可核对的两条（写成体检守线）：变换后全站**不该再出现**裸的 `font-size:12px`，也不该出现 `font-size:calc(var(--math-text-…`。

### 3.3 共享启动器（`assets/js/display.js`）

一个几十行的小文件，职责只有一个：**在首屏绘制前，把本机设置写到 `<html>` 上**。

```
读 wkmath.display.theme / wkmath.display.fs  →  写 html[data-theme] / html[data-fs]
并存成 window.WK_DISPLAY（供设置页与白板调用）
```

挂在 42 个页面的 `<head>` 里最前面（在 `<link>` 之前即可，不必更早）。识别不了的值一律回默认 —— 存坏值不许把页面弄成"白底白字"。

### 3.4 设置页（`settings.html`）

新增一节「阅读与显示」，两行：

- **字号**：标准 / 大 / 特大（三个按钮）
- **配色**：亮色 / 中色 / 暗色（三个按钮，各带一个自己配色的预览色块）

按钮的绑定逻辑写在 `display.js` 里（页面里只放 DOM），这样"设置长什么样"与"设置怎么生效"不分散在两处。

### 3.5 白板与图谱

- 图谱画布已经是 `background:var(--math-background)`，跟着令牌走，不用改。
- 白板板面是 canvas 画的、颜色来自 JS 的 `THEMES`，需要接线：板面主题与全局配色**共用同一个真值**（§2 #9）。
- 白板里那些 DOM 浮层（题面旁按钮、台阶框、转写面板）现在有 `background:#fff` 这类硬编码，深色下会刺眼 —— 一并收进令牌（全站仅约 27 处）。

## 4. 验收

1. **断言**：新增 `dd-check`（display）断言包 —— 默认值、三档切换、坏值回落、属性落点、`std` 不写属性；白板板面与全局同源。
2. **体检**（新增 `verify_display.rb`）：
   - 42 个页面都在 `<head>` 里挂了 `display.js`；
   - 全站没有漏乘的 `font-size`（两条机械守线）；
   - **中色 / 暗色定义齐了 `:root` 里的每一个令牌**（缺一个就是"深色下有个东西还是白的"）；
   - 设置页有这两行控件、有 `aria-pressed`。
3. **反证**：去掉一个令牌 → 体检变红并点名是哪一个；把 `--math-fs` 断开 → 断言报字号没变。
4. **真机**：三档字号 × 三个配色共 9 组，在首页 / 阅读器 / 图谱 / 白板 / 设置五个页面上各走一遍，重点看**有没有文字被裁切**、**深色下有没有白块**。截图留档。
5. `run_all.rb` 全绿（断言 + 语法 + 体检红灯 0）。
